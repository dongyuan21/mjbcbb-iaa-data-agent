## 核心知识

### 1. ROI360 / PGP 主链路

- `dim_market_campaign_s2s_event_map_da`：点位 `s2s_event` 到 campaign/adset 的桥。
- `tj_ad_spend_active_v2`：消耗、展示、点击、AF 安装、媒体安装。
- `tj_ad_sdk_revenue`：SDK/埋点校准回收，MI 默认 `revenue_source=sdk`。
- `tj_ad_revenue_v2`：AppsFlyer 回收，对比 SDK 口径。
- `af_cohort_user_acquisition_v2`：cohort 留存，核心是 `date_diff` 与 `unique_users`。
- 对 PGP/MI 来说，短期仍以 `campaign_name` 传 filter；但稳定建模要保留 `campaign_id/adset_id`。

### 2. 表后缀语义

- `_local`：本地分片表，通常是 Distributed 表的底层存储，不建议业务 agent 默认查询。
- `_view`：MI/ROI360 常用视图，业务查询更贴近页面结果；需要 `SHOW CREATE` 解析依赖。
- `_staging` / `stagging` / `temp_` / `test`：中间或测试资产，默认不能作为正式口径。
- `_v2` / `_v3`：不同版本路径，需要结合 nexus reportType 判断是否仍在生产。

### 3. 日期字段习惯

- 消耗：`active_date`，注释为 UTC8。
- 回收：`active_date`、`revenue_date`、`date_diff`，注释为 UTC0。
- 留存：`dt`、`active_date`、`event_date`、`date_diff`。
- 映射：`last_dt` 表示最新出现日期，不是分区。

### 4. 大表风险

最大本地表集中在预测、回收、留存和消耗域。agent 生成查询必须带日期过滤、LIMIT、执行时间和扫描上限。

## Agent 使用优先级

1. 问 ROI/投放复盘：先召回 `roi360_p0` 表卡和 `../ai_ck/agent_knowledge/数据地图.md`。
2. 问素材效果：再进入 `material_asset` 和 `spend_cost`。
3. 问预测：区分预测表与真实回收表，避免把预测 ROI 当真实 ROI。
4. 问 campaign/adset/ad 元数据：使用 `campaign_ad_account`，但最终指标仍回到 spend/revenue/retention。
5. 问 KOL：使用 `kol` 域，和 UA ROI 主链路分开。
