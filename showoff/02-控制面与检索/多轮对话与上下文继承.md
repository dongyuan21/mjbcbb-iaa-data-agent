# Data Agent 多轮对话与上下文继承

> 面向：业务、DA、数仓、投放和管理同学。
> 当前结论：**有限的历史文本续接可用；结构化多轮状态的组件已实现，但真实主链尚未闭环。**
> 设计权威：[多轮对话与上下文压缩工程设计](../../data_agent_plan/架构/在线/横切面/多轮对话与上下文压缩工程设计.md)。

## 一句话说明

用户追问“换成 iOS”“只看美国”“那归因呢”时，系统会先判断这是不是对上一轮的追问、纠正或换题；在有限条件下，把最近历史文本带入当前问题后重新路由。

这不等于系统已经拥有完整、版本化、可恢复的“长期对话记忆”。当前不能把“页面能连续聊天”或“某个四轮样例通过”表述为结构化多轮已完成。

## 当前主链实际做了什么

```text
当前问题 + 最近历史消息
  → TurnResolver 判断轮次类型
  → follow_up / correction 且置信度足够时，注入有限历史文本
  → 用补全后的问题重新 route
  → 正常执行本轮只读分析
  → 对外只保存轮次的安全摘要
```

当前历史注入最多保留 8 条消息、约 5,000 字符；历史助手回答被明确标为“可能有误”，用户后续纠正优先。切话题时不注入旧历史，避免把 ROI 上下文污染到实验、素材等新问题。

## 轮次类型

| 类型 | 含义 | 当前主链作用 |
|---|---|---|
| `standalone` | 独立新问题 | 不继承历史 |
| `follow_up` | 续问或替换已知条件 | 高置信时可注入有限历史 |
| `correction` | 用户纠正上一轮理解或条件 | 高置信时可注入有限历史，用户纠正优先 |
| `topic_switch` | 明确换题 | 使用原问题独立重路由，不注入旧历史 |
| `clarification_answer` | 回答系统的澄清问题 | 组件存在；durable pending 语义尚待主链闭环 |
| `cancel_or_restart` | 取消或重新开始 | 组件存在；状态清理与真实事务语义尚待主链闭环 |

规则解析器当前在回答前以 `enforce=True` 参与历史注入和重路由。模型解析器是可配置兜底，默认不应被视为已完成的线上强制能力。

## 组件与主链接线

系统已有 `ConversationState`、CAS checkpoint、`TurnResolver`、`conversation_orchestrator`、Context Compiler 和 reducer，也有相应组件测试。但真实回答目前只附加 `turn_resolution` 的安全投影；状态提交入口需要完整的运行时对象 `_turn_resolution_obj`，而普通回答并不生产它。

结果是：原始历史文本续接可以工作，但真实 API、SSE、Worker 不会稳定地把 `state_patch`、状态版本和 checkpoint 原子推进。

| 能力 | 代码 / 单测 | 真实主链 |
|---|---|---|
| 原始历史注入与重路由 | 有 | 已接，适用于有限续问 |
| `ConversationState` + CAS | 有 | 未完整接线 |
| 规则 TurnResolver | 有 | 已影响历史注入与路由 |
| 模型 resolver | 有 | 配置控制，默认不 enforce |
| 状态 orchestrator | 有 | 调用入口存在，但当前等待未生产的完整解析对象 |
| Context Compiler / reducer | 有 | 尚未成为 provider 输入的生产调用者 |

## 对外表述范围

| 可以说 | 不可以说 |
|---|---|
| 系统能处理一部分显式追问、纠正和切题，避免每轮只看孤立句子 | 每轮成功都已写入结构化会话状态 |
| 规则、状态、CAS、压缩组件已有实现与测试 | 已完成可恢复、并发安全、长会话压缩的多轮主链 |
| 多轮 golden/precision 是解析器质量证据 | 解析器准确率或旧样例等同 API/Worker 上线证明 |
| 结构化多轮已有清晰收口方案 | 已完成线上 `v1 → v4` checkpoint 验收 |

## 主链接线要求

1. BeginTurn 固定 `turn_id` 与 `base_state_version`，加载最新 committed state。
2. 用私有 envelope 携带完整 `TurnResolution`，对外 metadata 只保留安全投影。
3. 在 sync、SSE、Worker 的同一成功事务中原子提交 answer、query record、turn ledger 和 checkpoint。
4. 为六类 TurnKind 定义真实迁移语义；失败、取消、lease lost 和 CAS 冲突都不得污染状态。
5. 将 Context Compiler/reducer 接入真实 provider 输入，并在 trace 中证明实际选中的上下文与压缩决策。
6. 用真实 API、SSE、Worker、数据库和无重试的四轮/并发/恢复案例验收，不以旧报告替代。
