为什么要这样分层加载？

  • 变贵：如果把所有知识一次性塞给模型，资料越多 token 越多，单次问答成本随知识库膨胀上涨。
  • 变慢且抓错重点：无关资料越多，AI 越容易被淹没，关键信息反而被稀释。
  • 不可扩展：每加一张表，每次问答都跟着变重，知识库越大越不可用。
  • 解决方案：常驻资料（default_bootstrap）只放导航和治理入口；表卡、语义合同、SOP、已验证 SQL 等重索引在任务命中后逐层拉取；表卡永远命中哪张读哪张，不整包加载。
  • 运行约束：上下文大小、资产数量和命中率是随资产与运行时版本变化的工程度量，应在需要时用当前 runtime 测量或 catalog 核验，不能把本图当作实时状态面板。
