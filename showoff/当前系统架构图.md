# 当前系统架构图

> 这份文档适合作为汇报附录。它不展开字段和脚本细节，只解释系统从“数据源”到“Agent 输出”的主路径。  
> 注意：这里画的是架构关系，不是实时数据状态。实时状态以刷新脚本和最新报告为准。

## 一句话说明

Data Agent 数据基座像一套“投放分析导航系统”：表卡告诉 Agent 去哪里查，语义层告诉 Agent 怎么算，分析资产告诉 Agent 哪些方法已经跑通过，质量门禁告诉 Agent 什么情况下不能下结论。

## 1. 系统全景

```mermaid
flowchart LR
  User["业务问题<br/>ROI、DNU、素材、点位、Campaign"]
  Agent["只读 Data Agent<br/>分析、解释、提示风险"]
  Base["数据基座<br/>表卡、语义、SQL、SOP、case、门禁"]
  MC["MaxCompute / Hive<br/>事实源和明细"]
  CK["ClickHouse / MI<br/>报表层和 OLAP"]
  Report["周报 / DA 报告<br/>沉淀经验和案例"]
  Output["汇报输出<br/>事实、拆解、风险、待确认项"]

  User --> Agent
  Agent --> Base
  Base --> MC
  Base --> CK
  Report --> Base
  Agent --> Output
```

## 2. 数据到结论的分层

```mermaid
flowchart TB
  L1["1. 数据来源<br/>MC、CK、MI、周报、历史 SQL"]
  L2["2. 表卡层<br/>每张表的使用说明书"]
  L3["3. 语义层<br/>统一解释 ROI、LTV、DNU、留存等概念"]
  L4["4. 分析资产层<br/>跑通过的 SQL、SOP、复盘 case"]
  L5["5. 质量门禁<br/>数据新鲜度、分区、PII、回归"]
  L6["6. 只读输出<br/>事实拆解、风险提示、待确认项"]

  L1 --> L2 --> L3 --> L4 --> L5 --> L6
  L5 -. 发现缺口 .-> L2
  L6 -. 复盘沉淀 .-> L4
```

## 4. Agent 处理一个问题的路径

```mermaid
flowchart LR
  Q["问题"] --> R["归类<br/>ROI / DNU / 素材 / 点位"]
  R --> K["找可信资产<br/>语义层、表卡、已验证 SQL、分析流程"]
  K --> S["选数据源<br/>MC 或 CK"]
  S --> G["过门禁<br/>数据是否到齐、分区是否安全、是否含敏感字段"]
  G --> A["输出分析<br/>事实、拆解、风险"]
  A --> D{"是否需要动作？"}
  D -->|"否"| V["沉淀为可复用知识"]
  D -->|"是"| H["交给人类拍板"]
```

## 5. 资产如何变得可信

```mermaid
flowchart TB
  Raw["原始材料<br/>报告、截图、临时 SQL"]
  Review["人工或脚本复核<br/>抽取、标注、脱敏"]
  Candidate["候选资产<br/>候选 SQL / 草稿流程"]
  Validate["验证<br/>小窗口跑数、schema probe、对账"]
  Verified["可信资产<br/>已验证 SQL / 流程 / 案例"]
  Recall["Agent 默认召回"]

  Raw --> Review --> Candidate --> Validate --> Verified --> Recall
```

## 6. 这套架构的边界

| 边界 | 对外表达 |
|---|---|
| 只读优先 | 当前系统先做分析和解释，不自动改预算、停投或放量 |
| 数据成熟度 | 数据未到时先提示延迟，不把空结果当业务变差 |
| 证据分层 | 原始材料、草稿只能作线索，已验证 / 已确认内容才能作默认事实 |
| 跨源处理 | MC 和 CK 分别查询，应用层对齐，不直接跨库 SQL join |
| 人类拍板 | 阈值、动作和策略仍由业务 owner 确认 |
