只读分析工作流

先解释清楚，再交给人决定是否行动
Observe
识别问题
ROI、DNU、素材、点位、campaign、数据质量先归类。
Route
召回资产
优先复用跑通过的 SQL，其次读取语义层、表说明、流程和案例。
Validate
检查口径
检查数据是否到齐、时间窗是否正确、分母和收入源是否一致。
Explain
输出拆解
给事实、贡献和风险，不把草稿或延迟数据当确定结论。
Handoff
交给上层闭环
需要动作时进入人类决策、操作记录和 D+1/D+3/D+7 后验。

质量判断

已经能支撑只读分析，但还不是自动投放系统

已经做对的部分

  • 知识分层清楚：原始材料、草稿、已验证、已确认、待拍板事项有边界。
  • 机器可读程度高：表说明、目录、语义合同和回归报告都能被 Agent 消费。
  • 查询护栏明确：分区过滤、跨源 join 禁止、PII 禁止、数据新鲜度先行。
  • 有验证闭环：语义模型和问答回归让变更后可以检查是否跑偏。

还缺的关键闭环

  • 历史案例还缺人类动作与后验，经验还没有完全变成策略记忆。
  • UA 阈值、样本量、冷启动、停投/放量边界仍待拍板。
  • 部分 DA 口径和素材 / 点位 SQL 仍在候选或小窗口阶段。
  • 广告平台操作记录工具未接入，归因还不能自动连接到预算、bid、状态变更。

上层建设路线

从基层可用，到只读稳定，再到可审计治理闭环
P0

跑稳只读 POC

选择 DNU、ARPU、campaign 观察三类问题，完整走数据新鲜度、SQL、解释、风险输出。

P1

结构化人类经验

把待问清单变成确认口径、阈值、样本量规则和不能动作的边界。

P2

接入只读操作日志

补 Google / Meta 等 change log，只解释预算、bid、状态变化，不自动执行动作。

P3

形成闭环 Agent

沉淀人类决策、实际动作、D+1/D+3/D+7 后验，形成策略记忆和审计链路。
