只读分析工作流

观察 -> 建模 -> 查询 -> 验证 -> 解释；动作仍由人确认
Observe
识别问题
ROI、DNU、素材、点位、campaign、数据质量先归类。
Route
召回资产
优先 verified SQL，其次语义模型、表卡、SOP、case。
Validate
检查口径

Explain
输出拆解
给事实、贡献、风险，不把 draft 或 delayed 数据当确定结论。
Handoff
交给上层闭环
需要动作时进入人类决策、操作记录和 D+1/D+3/D+7 后验。

质量判断

强项与当前短板

已经做对的部分

  • 知识分层清楚：raw、draft、verified、confirmed、needs_decision 有边界。
  • 机器可读程度高：表卡、catalog、manifest、semantic model、eval 都能被 Agent 消费。
  • 查询护栏明确：分区过滤、跨源 join 禁止、PII 禁止、freshness 先行。
  • 有验证闭环：语义模型 5/5、Agent 回归 8/8，已具备只读演练基础。

还缺的关键闭环

  • decision case 缺人类动作与后验，经验还没有真正变成策略记忆。
  • UA 阈值、样本量、冷启动、停投/放量边界仍待拍板。
  • 部分 DA 口径和素材 / 点位 SQL 仍在 draft 或小窗口阶段。
  • 广告平台操作记录工具未接入，归因还不能自动连接到预算、bid、状态变更。

上层建设路线

从基层可用，到只读稳定，再到可审计治理闭环
P0

跑稳只读 POC

选择 DNU、ARPU、campaign 观察三类问题，完整走 freshness、SQL、解释、风险输出。

P1

结构化人类经验

把待问清单变成确认口径、阈值、样本量规则和不能动作的边界。

P2

接入只读操作日志

补 Google / Meta 等 change log，只解释预算、bid、状态变化，不自动执行动作。

P3

形成闭环 Agent

沉淀人类决策、实际动作、D+1/D+3/D+7 后验，形成策略记忆和审计链路。
