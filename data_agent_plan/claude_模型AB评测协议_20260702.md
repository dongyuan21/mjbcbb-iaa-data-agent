## 0. 已完成的前置验证（2026-07-02，本次已做）

- **网关模型可用性（2026-07-02 历史记录）**：当时 Runtime 使用的内网网关已废弃；当时实测 serve：`claude-sonnet-4-5/4-6`、`claude-opus-4-1…4-8`、`claude-haiku-4-5`、`qwen3.7-max`、`deepseek-v4-pro/flash` 等 68 个。当前统一使用公司 Stargate 网关 `stargate.example.com`，模型可用性需按当前网关重新核验。
- **工具调用兼容性**：对内网网关做 live smoke（OpenAI `tools` 触发 `run_bash`），`qwen3.7-max` / `claude-sonnet-4-6` / `deepseek-v4-pro` **三者均返回正确 `tool_calls`（finish_reason=tool_calls，参数正确）**。PI 的 bash-tool agent loop 用 Claude 跑得通。
- **代码启用**：已把 `claude-sonnet-4-6`、`claude-opus-4-8` 加进 `runtime/backend/app/config.py` 的 `ALLOWED_AGENT_MODEL_FAMILIES` + `DEFAULT_AGENT_MODEL_OPTIONS` + `model_catalog()`，并在 `runtime/pi/agent/models.json` 注册；`test_model_selection.py` 已同步、全量后端测试 493/493 通过。**线上默认未改**，仍 `qwen3.7-max`。
- **sonnet-5 启用路径（含 temperature 真相，侦察确认）**：PI 主链路（openai-completions）**从不发送 `temperature`**（pi-coding-agent 不设 `options.temperature`，openai-completions.js 仅在有值时才写）。因此我先前观察到的 `temperature is deprecated for this model` 是**手工 curl 显式传 temperature**触发的，**不是 Runtime 的调用方式**。结论：sonnet-5 授权到内网网关后，只需在 `models.json` 的 `hs-litellm` 下加一个**普通模型条目**（`id: claude-sonnet-5`，不带任何采样字段），**无需**任何 temperature 抑制。**切勿**给它加 `compat.supportsTemperature` 或 per-model `temperature`——对 openai-completions 是 no-op，且加 schema 不认的键会让 `validateModelsConfig` 失败、导致整份 models.json 自定义模型被丢弃。

## 3. 如何切模型（三种入口，评测用第 2 种）

- 全局默认：`config.py` `DEFAULT_AGENT_MODEL` / 环境变量 `DATA_AGENT_PI_MODEL`（**A/B 期间不要动线上默认**）。
- **评测入口（推荐）**：按请求指定 `ChatRequest.agent_model="claude-sonnet-4-6"`（已验证 `resolve_agent_model` 接受该值），或给 replay runner 传模型参数，逐模型各跑一轮，互不影响线上默认。
- 校验：`resolve_agent_model(x)` 对未启用模型会 `raise ValueError`（不是静默回退），可用来防打错模型名。

---

## 4. 方法：10 题 × N 连跑

- 对每个候选模型，把 10 题各跑 **N=3~5 次**（因已观测到 `fail/fail/pass` 抖动，单跑不足以判稳定性）。
- 记录每题每次：`replay_status`、`query_records`（数量/失败数/`error_code`）、`failure_categories`、`assistant_must_include/​must_not_include` 命中情况、`prompt_tokens`/`completion_tokens`、端到端时延。
- 数据来源：`tools/scripts/pi_replay_regression.py` 产出 + MySQL trace/`query_records` + `eval/PI调用日志复核_*` 复核报告。

---

## 5. 四指标定义（+ blocked 严格口径）

| 指标 | 定义 | 采集 |
|---|---|---|
| **pass 率** | (pass 次数)/(10×N)；同题跨次的 **flaky 翻转率**单列（同题有 pass 又有 fail 即算 flaky） | replay_status |
| **schema/SQL 错误率** | 出现 `ck_schema_mismatch`、嵌套聚合入 WHERE、对无 dt 视图 `max(dt)`、`intermediate_sql_failed` 的次数占比 | query_records.error_code / failure_categories |
| **禁词违规率** | 触发 `assistant_must_not_include`（`立即停投/放量`、`SELECT *`、`appsflyer_id`、`customer_user_id`、`Aggregate function inside another`）的次数占比 | must_not_include 命中 |
| **token 成本 + 时延** | 每题平均 prompt+completion token、端到端 P50/P95 时延 | D-1 计量 + trace |

**blocked 严格定义**（防作弊凑绿）：只有 **freshness-BLOCKED** 计 `blocked`（不计入 fail 也不计入 pass 分母的通过判定，另列）；`intermediate_sql_failed` / `final_answer_failed` / 超时 **一律计 fail**，不得归类为 blocked。

## 6. 判定规则

1. **合规是前置门槛**（本项目：公司网关 + 已脱敏，已满足；仍须确认 A/B 期间无 PII/密钥外泄）。
2. 在合规前提下，**优先级：pass 率高 > flaky 翻转率低（方差小）> schema/禁词违规率低 > token 成本+时延可接受**。
3. **只有挑战者在 pass 率与稳定性上"显著优于"基线**（建议阈值：pass 率高出基线 ≥1 个台阶且 flaky 翻转率更低），**才建议切换线上默认**；否则维持 qwen3.7-max、把差距留给 §4-② 护栏补。
4. 切换线上默认是 **owner 拍板 + 基建决策**（用户侧可决定），A/B 只提供数据与建议，不自动切。
5. 若 `claude-sonnet-4-6` 显著优、且团队确要 `sonnet-5`：以本轮数据为依据向基建提"内网网关新增 sonnet-5"，加好后按同协议补跑一轮再定。
