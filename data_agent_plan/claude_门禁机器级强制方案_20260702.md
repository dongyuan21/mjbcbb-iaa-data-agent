> 状态：`archived_snapshot`（原 `plan_pending_execution`，2026-07-02 生成；当前门禁执行方式以 `tools/scripts/check_*.py` + AGENTS.md 规则为准）

> 关联：`claude_工程深度评估与下一步方向_20260702.md` §4-③（本方案是该方向的详细展开）。
> 目标：把当前"靠 AGENTS.md 约定 + 手动/`--mode verify` 触发"的门禁，升级为"破坏门禁的提交/推送被机器自动拦截"，跨越"稳健有门禁(4)→生产级闭环(5)"的分界。

## 1. 现状与问题（已核实）

| 事实 | 证据 |
|---|---|
| 无任何机器级强制 | `.github/workflows`、`.pre-commit-config.yaml`、`Makefile`、自定义 git hook 均不存在；`.git/hooks` 只有 `.sample` |
| 门禁本体真实有效 | `eval/agent_regression/run_regression.py` 内部 fan-out 6 个 `check_*.py`：`sql_promotion / sql_partition_guardrails / table_card_quality / knowledge_consistency / agent_retrieval_map / metric_layer_boundary`，另含语义 build+compose |
| 退出码语义已确定 | `run_regression.py` `main()`：`return 1`(FAIL) / `return 2`(freshness BLOCKED) / `return 0`(PASS)；`sys.exit(main())` |
| cron 只覆盖 2 项 | `tools/scripts/cron_freshness_6h.sh`、`cron_redline_bidaily_review.sh`；**不含** `run_regression`、`run_agent_iteration`、`refresh_data_agent_snapshots` |
| 已有先例可复用 | `run_agent_iteration.py` 里 `REGRESSION_GATE(ok_codes={0,2})` 已把"PASS 或 BLOCKED"都视为通过 |

**核心问题**：一次改坏表卡/破坏 catalog 一致性/引入 PII 泄漏的提交，当前不会被任何机器拦截，完全依赖人记得去跑门禁。这是唯一把整体成熟度压在 4 而非 5 的治理缺口。

---

## 2. 设计原则

1. **单一入口，不重复列门禁**：`run_regression.py` 已内部串起 6 个 check，钩子只调它一个，不要再单独列 `check_*.py`（否则重复且易漂移）。
2. **退出码语义对齐保护态**：`0`(PASS) 与 `2`(freshness BLOCKED) 都放行——freshness 延迟是上游数据没到，是**有效保护态**不是代码错误；只有 `1`(FAIL) 才阻断。**绝不允许**为了过钩子去篡改 snapshot。
3. **CI / 服务端 gate 是主门禁，本地 hook 只是快速反馈**：`core.hooksPath` 是每个 clone 的本地配置，且 `--no-verify` 可绕过；真正能支撑"机器级强制"的是不可被普通开发者绕过的 CI/PR gate 或 forge pre-receive。没有服务端 gate，本方案只能算"本地自愿级"。
4. **分层拦截、按耗时分配**：秒级静态检查放 `pre-commit`（每次提交都跑）；较重的全量回归放 `pre-push` 与 CI/PR gate；需要活库的运行时行为门禁放"部署后钩子"（不阻塞本地开发）。
5. **不引入新依赖优先**：本地快速反馈用原生 git hook（纯 shell，零依赖）；服务端侧优先复用现有 forge/CI runner；`pre-commit` 框架作为可选增强。
6. **可绕过但留痕**：本地 hook 可被绕过是 git 的既定行为；配套用 CI/PR gate + 部署后钩子 + 定时全量兜底，保证绕过本地 hook 的破坏最终会被拦截或暴露。

## 3. 四层门禁设计

### 层 0 · CI / 服务端 gate（主门禁，不可绕过）

这是"机器级强制"的核心层。push/PR 必须跑同一条离线总门禁，并复用 `run_regression.py` 的退出码语义：

```sh
python3 eval/agent_regression/run_regression.py
```

- `0`：PASS，放行。
- `2`：freshness-BLOCKED，放行但报告必须保留 blocker；这是数据延迟保护态，不是代码失败。
- `1`：FAIL，阻断。
- 其他退出码：按脚本崩溃 / 环境异常处理，阻断并提示排查 CI 环境，而不是归类为业务回归失败。

> 若当前 forge 暂无 CI/PR gate，必须把"主门禁缺失"列为实施 blocker；本地 hook 只能先提供快速反馈，不能单独宣称跨越 4→5。

### 层 1 · pre-commit（秒级，每次提交）

只挂"改了就必须秒级过"的静态检查，不能慢，否则会被 `--no-verify` 习惯性绕过。

| 检查 | 触发条件 | 命令 | 预期耗时 |
|---|---|---|---|
| 外发合规/敏感词脱敏 | 有 staged 文件改动 | 先给 `check_company_sensitive_terms.py` 增加 staged/file-list 模式，再用 `git diff --cached --name-only` 喂入文件列表；不要裸扫全仓 | 秒级 |
| 检索地图硬门禁 | 改了 `AGENT_RETRIEVAL_MAP.yaml` / `task_routes/**` | `python3 tools/scripts/check_agent_retrieval_map.py` | 秒级 |
| 指标层边界 | 改了 `ai_ck/agent_knowledge/metrics/**` 或 `semantic_contract/metrics.yaml` | `python3 tools/scripts/check_metric_layer_boundary.py` | 秒级 |

> 用改动路径判断是否触发对应 check，避免每次提交都跑全部。改动检测：`git diff --cached --name-only`。

### 层 2 · pre-push（较重，推送前一次）

单一入口跑全量回归，退出码映射保护态。

```sh
#!/bin/sh
# .githooks/pre-push  —— 全量回归门禁
echo "[pre-push] running run_regression.py ..."
python3 eval/agent_regression/run_regression.py
code=$?
if [ "$code" -eq 0 ]; then
  echo "[pre-push] 回归通过（code=0）。"
  exit 0
fi
if [ "$code" -eq 1 ]; then
  echo "[pre-push] BLOCKED: 回归 FAIL（真实失败），推送被拦截。修复后重试，或 git push --no-verify 显式绕过（不推荐）。"
  exit 1
fi
if [ "$code" -eq 2 ]; then
  echo "[pre-push] 回归 freshness-BLOCKED（有效保护态），放行推送。不要篡改 snapshot。"
  exit 0
fi
echo "[pre-push] BLOCKED: run_regression.py 异常退出 code=$code，疑似脚本崩溃或本机环境问题；请先排查，不要归类为业务回归 FAIL。"
exit 1
```

> `run_regression.py` 大部分 check 是离线的（读工程制品），不需活库；freshness gate 读 snapshot。因此 pre-push 可在无 MC/CK 凭据的开发机上跑，`2` 放行即可。

### 层 3 · 部署后钩子（活库运行时行为，不阻塞本地）

`pi_replay`(10 题需活库)、`runtime_deploy_smoke`、`audit_route_confusion` 依赖已部署 PI 运行时 + MySQL trace，**不能**放本地钩子。做法：

1. 把 `pi_replay` 里 **已标 `review_status: static_route_smoke`** 的 case（当前 `cases.yaml` 首例 `PI_STREAM_TRANSPORT_LONG_SQL_TRACE_ROUTE_SMOKE`，仅校验 route + 禁词、无 `required_preflight_checks`）抽成"离线路由/禁词 smoke 子集"，纳入层 2 的 `run_regression`；不要把它称为 transport gate，真正 SSE 截断门禁必须另写 done-aware 客户端；
2. 其余 9 条需活库的 case + `runtime_deploy_smoke`，做成"部署完成后必跑并归档"的一步（挂在 `skills/shanhai-deploy-all-services` 部署流程尾部，或独立 `cron_pi_replay_postdeploy.sh`），产物顶部标 `snapshot_only`，报告里显式写"离线门禁通过 ≠ 运行时行为通过"。
3. 真正 SSE transport gate 作为独立后续：覆盖前端真实路径 `/api/jobs` + `/api/jobs/{job_id}/events`，用 done-aware 客户端校验 `answer` 一次、随后 `status.stage=done`、session/job id 一致、无半帧残留、无 JSON parse error、无 `error` 事件。

### 兜底 · 定时全量（可选）

新增 `cron_regression_daily.sh`：每日跑一次 `run_regression`（`ok_codes={0,2}`）+ `run_agent_iteration --mode report`，把绕过 `--no-verify` 的破坏在 24h 内暴露。节拍与现有 `cron_freshness_6h`/`cron_redline_bidaily` 并列。

## 4. 落地步骤（建议顺序）

1. **先建 CI / 服务端 gate（主门禁）**：
   - 在远端 forge 的 push/PR 流程跑 `python3 eval/agent_regression/run_regression.py`；
   - 显式映射退出码：`0` 放行、`2` 放行并保留 freshness blocker、`1` 阻断、其他退出码按环境/脚本异常阻断；
   - 若暂无 CI runner，记录为实施 blocker，不把本地 hook 当作已完成的机器级强制。
2. **建钩子目录并接管本地快速反馈**（不动 `.git/hooks`，用可提交的 `.githooks/`）：
   - 新增 `.githooks/pre-commit`、`.githooks/pre-push`（内容见上）；
   - 新增 `tools/scripts/install_git_hooks.sh`，执行 `git config core.hooksPath .githooks`；
   - 写进 `runtime/本地启动说明.md` 或根 README 的"开发准备"。注意：安装脚本和 README 只能降低漏装概率，不能替代 CI 主门禁。
3. **补 `check_company_sensitive_terms` 进门禁**：先给脚本补 staged/file-list 模式；本地跑 baseline 确认排除规则稳定，再挂 pre-commit（当前它孤立存在、未被任何门禁引用，是 §6 完整性缺口之一）。
4. **抽 `static_route_smoke` 离线子集**：改 `run_regression.py`，读 `pi_replay_regression/cases.yaml` 中 `review_status==static_route_smoke` 且无 `required_preflight_checks` 的 case，做 route+禁词离线校验，纳入统一 run 的判定；该子集不是 SSE transport gate。
5. **部署后钩子**：在部署 SOP 尾部追加"跑 9 条活库 pi_replay + deploy_smoke 并归档"；SSE transport gate 另以 done-aware 客户端实现。
6. **文档**：在根 `AGENTS.md` "Always Applied Rules" 或 `AGENT_AUTONOMY.md §8` 补一句"CI/服务端 gate 是主门禁；本地 `.githooks` 是快速反馈，开发机应执行安装脚本"。

## 5. 验收信号

- 故意改坏一张表卡的 fqn → CI/PR gate 阻断；已安装本地 hook 的开发机上，`git push` 前也会被 pre-push 拦截。
- 制造一次 freshness 延迟 → 回归 `2` → CI/PR gate 与 pre-push **均放行**（验证保护态不误伤），报告保留 blocker。
- 让 `run_regression.py` 异常退出非 `0/1/2` → CI/PR gate 与 pre-push 阻断并提示"环境/脚本异常"，不伪装成业务回归 FAIL。
- 提交含敏感词的 staged 文件 → pre-commit 拦截；未安装本地 hook 时，CI/PR gate 或定时全量兜底发现。
- 部署一次 → 产出归档的 pi_replay 活库报告，且报告显式区分"离线通过 ≠ 运行时通过"。

## 6. 风险与边界

- **CI/服务端 gate 是硬前提**：本地 hook 不可替代 CI。若没有远端 gate，本方案只能提供快速反馈，不能称为不可绕过的机器级强制。
- **不改门禁判定逻辑**：本方案只做"何时自动触发"，不碰 `run_regression` 内部规则；新增 static smoke / staged 扫描时也应保持原门禁语义。
- **`--no-verify` 可绕过本地 hook**：git 既定行为，靠 CI/PR gate、层 3 部署后钩子 + 定时全量兜底，不追求本地不可绕过。
- **freshness 保护态严禁改绿**：钩子把 `2` 放行是设计，不是让人去删/伪造 snapshot 让它变 `0`。
- **pre-push 耗时**：`run_regression` 含 80 golden 路由回归 + 语义 build+compose，若耗时偏高影响推送体验，可把最重的 golden 只保留在 CI/定时，本地 pre-push 退为静态门禁子集——但 CI 主门禁不能降级。
