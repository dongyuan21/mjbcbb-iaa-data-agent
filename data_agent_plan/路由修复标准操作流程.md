# 路由修复标准操作流程（SOP）

> 状态：active
> 创建：2026-07-24
> 范围：路由质量周报发现异常 case 后的标准修复流程，从诊断到验证的完整闭环。
> 关联：`路由监控数据驱动迭代方案.md`（诊断决策树）、`低置信度Fallback与路由监控方案.md`（监控指标）、`eval/agent_regression/regression_cases.yaml`（golden case）。

## 一、周报触发 → 诊断决策树

每周一运行 `route_quality_weekly_report.py --days 7` 后，对报告中的异常 case 按以下决策树诊断：

```
异常 case
  │
  ├── A. 低置信度（confidence < 0.6）
  │     │
  │     ├── 问题确实属于某个已有 route，只是措辞没命中
  │     │     └── FIX: 加 trigger_example 或 positive_signal（SOP 5.1 / 5.2）
  │     │
  │     ├── 问题属于全新模式，18 route 都不覆盖
  │     │     ├── 出现 >= 5 次/周 → FIX: 新建 route（SOP 5.4）
  │     │     ├── 出现 2-4 次/周 → MONITOR: 继续观察
  │     │     └── 出现 1 次 → IGNORE: 可能是噪音
  │     │
  │     └── 问题属于产品边界外（竞品/非我方数据）
  │           └── LABEL: out-of-scope，由 fallback 兜底返回
  │
  ├── B. 双峰（margin ≤ 3，两个 route 分数接近）
  │     │
  │     ├── 问题本质只属于一个 route
  │     │     └── FIX: 加 negative_signal 到不该命中的 route（SOP 5.2）
  │     │
  │     └── 问题确实跨域（需要两个 route 的知识）
  │           └── FIX: 参考「多问题拆分与跨路由组合方案.md」Secondary Read
  │
  └── C. 路由正确但答案错误（answer quality 矩阵）
        │
        ├── 答错原因是知识缺口（表卡/SOP/verified_sql 不够）
        │     └── FIX: 补知识（不改路由）→ 补表卡字段 / 加 verified_sql / 更新 SOP
        │
        ├── 答错原因是 SQL 错误（选错表/字段/条件）
        │     └── FIX: 加 known_pitfall 或 query_rules → 更新表卡 / 加 output_guardrail
        │
        └── 答错原因是 freshness（数据过期）
              └── NOT A FIX: 是数据源 SLA 问题 → 记录 freshness blocker
```

## 二、修复操作清单

### 5.1 加 trigger_example（最常见，5 分钟）

```bash
# 1. 编辑 INDEX.yaml，在对应 route 的 trigger_examples 列表中加新条目
vi task_routes/INDEX.yaml

# 2. 加 golden case
vi eval/agent_regression/regression_cases.yaml
# 在 route_golden_cases 中加一条 expect_task_type 断言

# 3. 跑门禁
python3 tools/scripts/check_agent_retrieval_map.py
python3 eval/agent_regression/run_regression.py --scope route_golden

# 4. 验证不回退
# golden 全绿 + agent regression 无 hard_failed
```

### 5.2 加 positive_signal / negative_signal（10 分钟）

```bash
# 1. 编辑 INDEX.yaml 的 positive_signals 或 negative_signals
vi task_routes/INDEX.yaml

# 2. 如果加了 negative_signal，加对应的 hard-negative golden case
vi eval/agent_regression/regression_cases.yaml
# 加 must_not_task_type 断言

# 3. 跑门禁
python3 tools/scripts/check_agent_retrieval_map.py
python3 eval/agent_regression/run_regression.py --scope route_golden
```

### 5.3 调 booster / 新增 _looks_like_* 函数（30 分钟）

```bash
# 1. 编辑 knowledge.py 中的 _looks_like_* 函数或 keyword_scores
vi runtime/backend/app/services/knowledge.py

# 2. 加 3+ golden case（正例 + 反例 + 边界 case）
vi eval/agent_regression/regression_cases.yaml

# 3. 跑全量 route_golden
python3 eval/agent_regression/run_regression.py --scope route_golden

# 4. 跑 backend 单元测试
cd runtime/backend && .venv/bin/python -m pytest tests/test_iaa_business_routes.py tests/test_route_confidence.py tests/test_route_llm_selection.py tests/test_question_decompose.py -v

# 5. 验证不回退
```

### 5.4 新建 route（2-4 小时，低频高价值）

```bash
# 1. 确认该问题模式出现 >= 5 次/周（从周报数据确认）

# 2. 写 task route YAML
vi task_routes/<new_id>.yaml
# 必填: id, objective, first_read, trigger_examples, positive_signals,
#        negative_signals, disambiguation, output_guardrails

# 3. 注册到 INDEX.yaml
vi task_routes/INDEX.yaml
# 在 tasks 列表加条目 + 在 taxonomy.remote_default_task_ids 加 id（如对外可见）

# 4. 加 5+ golden case（3 正例 + 2 hard-negative）
vi eval/agent_regression/regression_cases.yaml

# 5. 跑全量门禁
python3 tools/scripts/check_agent_retrieval_map.py
python3 tools/scripts/check_knowledge_consistency.py
python3 eval/agent_regression/run_regression.py

# 6. 验证所有已有 route 不回退
```

## 三、Answer Quality 修复方向

| 现象 | 诊断 | 修复方向 |
|------|------|---------|
| 路由错了 + 答案错了 | 路由缺口 | 修路由（第二节） |
| 路由对了 + 答案对了 | 正常 | 无需修复 |
| 路由对了 + 答案错了 | 知识/执行缺口 | 补知识/修 SQL/加 guardrail |
| 路由错了 + 答案对了 | 偶然正确（运气） | 仍需修路由（下次可能不 lucky） |

### 路由对了 + 答案错了 的具体修复

| answer_quality 分类 | 含义 | 修复 |
|---------------------|------|------|
| `execution_failure` | Runtime 执行失败（tool_failure/timeout） | 检查 freshness / SQL 超时 / 工具配置 |
| `zero_rows_possible_wrong_filter` | SQL 返回 0 行 | 检查 must_filter / 日期条件 / 表选择 |
| `high_tool_failure_rate` | >50% 工具调用失败 | 检查 freshness blocker / CK 连接 / MC 超时 |
| `empty_answer` | 回答内容过短 | 检查 context_budget / Runtime 输出限制 / prompt 截断 |

```bash
# 3. route_golden 回归
python3 eval/agent_regression/run_regression.py --scope route_golden

```

## 五、节奏

| 频率 | 动作 | 输出 |
|------|------|------|
| 每日（自动） | `route_quality_weekly_report.py --days 1` | 轻量日报（只看告警指标） |
| 每周一（人工） | review 周报 + 诊断低分 cluster + 执行修复 | 修复 + 新 golden case |
| 每月（人工） | 扩充混淆矩阵样本集 + 校准健康指标阈值 | 更新阈值 + 月度趋势 |
| 每季度（可选） | 评估是否需要新 route / 调整 domain_category | 路由架构变更提案 |
