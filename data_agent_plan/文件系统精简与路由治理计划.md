# 文件系统精简与 Agent 路由治理计划

> 状态：active_governance
> 更新时间：2026-06-18
> 范围：目录职责、默认召回、canonical owner、重复内容治理。
> 边界：本文件不定义业务口径，不替 DA / UA / owner 拍板。

## 结论

当前目录结构可以继续沿用，不建议大搬家。下一步优先做的是：

1. 用 `AGENT_RETRIEVAL_MAP.yaml` 固定自然语言问题的检索路线。
2. 用 canonical owner 约束重复内容，避免多个文件同时装作真理源。
3. 用门禁脚本检查路由、状态和默认召回边界。
4. 后续只精简不再被路由命中的旧摘要、重复 SQL 和过期 snapshot。

## Canonical Owner

| 内容 | 唯一真理源 | 其他文件怎么写 |
|---|---|---|
| MaxCompute 表结构、PII、分区和 query_rules | `ai_hive/` | 只写摘要并链接表卡 |
| ClickHouse / MI ROI360 表结构和页面口径 | `ai_ck/` | 只写使用场景和链接 |
| 指标、维度、实体、join、诊断字段 | `knowledge/agent_knowledge/semantic_contract/` | 不重复完整公式 |
| 投放治理、分析协议、业务政策 | `knowledge/` | SOP / case 引用政策，不复制政策全文 |
| 可复用 SQL | `da_assets/verified_sql/` | SOP / case 引用 SQL，不复制多份 |
| 分析流程 | `da_assets/analysis_sop/` | verified SQL 只写适用流程链接 |
| 闭环案例 | `da_assets/decision_cases/` | case 记录事实链和后验，不泛化为政策 |
| 待办、待问、待拍板 | `TODO/` | 完成后迁出，不长期当事实 |
| 路线图、POC、历史快照 | `data_agent_plan/` | 不覆盖当前回归和 freshness 状态 |

## 重复内容处理规则

| 重复类型 | 保留策略 |
|---|---|
| 视角重复 | 允许。人读版和机器版可以并存，但要互相链接。 |
| 索引重复 | 允许。README、manifest、index、catalog 可以重复指向同一资产。 |
| 事实重复 | 收敛。完整公式、阈值、SQL、join 只能有一个 canonical owner。 |
| 旧快照重复 | 降级。标为 snapshot / historical，不当当前事实。 |
| SQL 重复 | 收敛。SOP / case 中保留 SQL 摘要，完整 SQL 归 `verified_sql/`。 |

## AI 可直接做

- 更新 `AGENT_RETRIEVAL_MAP.yaml` 的任务路由、默认召回和禁区。
- 给新资产补 `status`、`default_recall`、`confidence`、`freshness_required`、`owner_decision_required`。
- 把非 canonical 文件里的重复事实改成链接和摘要。
- 将旧 snapshot / handoff 标为 historical 或 `default_recall: false`。
- 运行并修复工程门禁：SQL 晋升、表卡质量、knowledge 一致性、retrieval map。

## 必须等待人拍板

- 放量、停投、降预算、观察的正式阈值。
- organic 是否计入官方 KPI。
- SDK / AF 回收作为正式复盘口径的优先级。
- 折前 / 折后成本的正式使用边界。
- AF install / media install 分母的正式使用边界。
- 数据延迟的上游责任归因和替代表选择。
- 广告平台 API 凭据、账号映射和操作日志权限。
