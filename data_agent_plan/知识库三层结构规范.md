# 知识库三层结构与归属规范

> 状态：active_governance
> 更新时间：2026-06-20
> 范围：`ai_hive/`、`ai_ck/`、`knowledge/` 三个知识库的目录分层、manifest 约定、跨库归属和门禁边界。
> 定位：这是三层结构的**唯一 canonical 定义**。各知识库 README 只描述本库的具体文件，不再复制本规范的通用定义；改三层规则改这里一处。
> 边界：本文件不定义业务口径，不替 DA / UA / owner 拍板。

## 一、三层模型

每个知识库根目录固定按用途分三层物理存放。新增文件先判断属于哪一层，再决定是否进入 Agent 默认召回。

| 层级 | 目录 | 用途 | 默认召回 |
|---|---|---|---:|
| Agent 知识层 | `agent_knowledge/` | 日常问答、选表、写 SQL、解释口径，是真正要召回的材料 | 是，按命中读取 |
| 工程沉淀层 | `engineering_artifacts/` | 构建、同步、探测、门禁、回归、schema/freshness 快照等可复跑产物 | 否 |
| 审计归档层 | `audit_archive/` | 来源追溯、历史探索、smoke test、未晋升材料、被表卡引用的证据 | 否 |

规则：

1. 工程沉淀层和审计归档层都**不进默认问答上下文**；只在维护、排障、追溯、验收时读取。
2. 审计归档层可以被 Agent 知识层引用为 `source_docs` / `evidence`，但其本身不是当前事实。
3. 快照类产物（`freshness_snapshot.json` 等）只是快照，评估当前状态前必须刷新，不得当实时事实。

## 二、manifest / 注册表约定（三库统一）

| 文件 | 位置 | 作用 |
|---|---|---|
| `agent_manifest.yaml` | 各知识库根 | 外部 Agent 挂载清单：asset_layers、bootstrap/maintenance 读序、hard_rules、source_priority |
| `agent_knowledge/catalog.yaml` | 各知识库 `agent_knowledge/` 下 | 机器可读召回注册表 |

统一规则：**每个知识库都用 `agent_manifest.yaml`(挂载) + `agent_knowledge/catalog.yaml`(召回注册表)**，不再出现 `manifest.yaml` 与 `agent_manifest.yaml` 这类近似名并存。

注册表内容按库性质不同，但文件名一致：

- `ai_hive` / `ai_ck`：`catalog.yaml` 是**表目录**（表名、层级、优先级、表卡路径）。
- `knowledge`：`catalog.yaml` 是**文档注册表**（文件、status、default_recall、applies_to_current、confidence）。

> 例外说明：`knowledge/agent_knowledge/semantic_contract/agent_manifest.yaml` 是语义契约子组件的挂载清单，运行时入口是 `model.json`；它是 `knowledge` 内部的机器契约子层，不是第四个知识库根。

### 控制面加载与上下文预算（default_bootstrap 瘦身 + task_routes）

`AGENT_RETRIEVAL_MAP.yaml` 是控制面入口，但**不把重索引塞进常驻上下文**：

- `default_bootstrap` 只放轻量控制面（README、AGENTS、路由图、`task_routes/INDEX.yaml`、三库 `agent_manifest.yaml`、默认召回边界、TODO 入口）。
- 重索引（语义 `model.json`、`da_assets/index.yaml`、各库 `catalog.yaml`、各任务协议）不进 bootstrap，按任务命中后由 `task_routes/<id>.yaml` 的 `first_read` 拉取。
- 任务路由是**一任务一文件** `task_routes/<id>.yaml`；`task_routes/INDEX.yaml` 是轻量路由器（触发词 → 任务文件）。Agent 先读 INDEX 选任务，再只加载该任务文件，而不是加载所有任务定义。
- 表卡层（`agent_knowledge/tables/`，约 1 MB 量级）永远命中才读单卡，不整包加载。

由此单轮真实上下文 ≈ 控制面 + 命中的少量表卡/协议，而非全量知识。`check_agent_retrieval_map.py` 校验 task_routes 与 INDEX 一致、任务字段齐全、顶层目录全部分类。

### Runtime 源码目录边界

`runtime/` 是 Data Agent Web Runtime 的源码和部署工件目录，不属于 `ai_hive` / `ai_ck` / `knowledge` 三个业务知识库的三层模型。

规则：

1. `runtime/` 可以读取控制面、表卡、verified SQL 和语义契约，但不得复制业务口径正文作为新的事实来源。
2. `runtime/` 不进入 Agent 默认业务召回；只有做 Runtime 开发、部署、排障或预检时才按需读取。
3. `runtime/` 必须在 `AGENT_RETRIEVAL_MAP.yaml` 中分类，避免顶层目录游离于检索治理之外。

## 三、跨库归属规则

三层划分解决"放哪一层"，本节解决"放哪个库"。归属错误会导致同一事实双写、表卡退化成业务百科、上下文膨胀。

| 新增内容 | 归属 |
|---|---|
| MaxCompute / Hive 表、字段、分区、PII、must_filter、单表 example SQL | `ai_hive/agent_knowledge/tables/` |
| CK / MI 表、字段画像、CK 样例验证、MI 页面能力 | `ai_ck/agent_knowledge/` |
| CK / MI 专属指标解释（ROI360 页面字段、蓝底预估、页面筛选器） | `ai_ck/agent_knowledge/metrics/` |
| 跨表实体、指标、维度、join、治理状态、异常诊断 | `knowledge/agent_knowledge/semantic_contract/` |
| SQL 写作协议、业务分析协议、投放治理政策、默认召回边界 | `knowledge/agent_knowledge/policies/` |
| 历史报告抽出的阈值、经验、试运行规则（必须带周期和适用边界） | `knowledge/agent_knowledge/report_knowledge/` |
| 可复用且已验证 SQL | `da_assets/verified_sql/` |
| 候选 / 未验证 SQL 样例 | `da_assets/candidate_sql/` |
| MC 侧表卡来源证据、血缘、审计现场 | `ai_hive/audit_archive/evidence/` |
| CK / MI 侧对账、反推验证现场 | `ai_ck/audit_archive/` |
| 待 DA / owner 拍板事项 | `TODO/` |
| 原始导出、截图、docx、未审核草稿 | `raw_exports/`、`da_assets/raw/` 或对应 `audit_archive/`，不进默认召回 |

关键原则：

1. **表卡只写单表事实**（过滤、PII、join 证据、安全示例），不写成业务百科；跨表指标语义不得回流到 `ai_hive` / `ai_ck` 表卡正文。
2. **政策不复制进语义契约**；语义契约引用政策结论或状态，不搬运整段政策正文。
3. **跨表语义按合约归属，不按物理库归属**：`semantic_contract` 消费 `ai_hive` / `ai_ck` / `policies`，但不拥有物理表，因此不能并入 `ai_hive` / `ai_ck`。
4. **CK/MI 页面指标 vs 跨表机器指标分层**：`ai_ck/agent_knowledge/metrics/` 解释页面与指标，`knowledge/agent_knowledge/semantic_contract/metrics.yaml` 定义可组合的跨表机器指标，二者不得复制同一公式。

## 四、门禁化边界（不靠人盯）

下列边界由脚本门禁强制，不依赖人工记忆：

| 边界 | 门禁 |
|---|---|
| 三层注册表一致性、知识 default_recall 状态 | `tools/scripts/check_knowledge_consistency.py` |
| 顶层目录必须被路由图分类、弃用路径不得回潮 | `tools/scripts/check_agent_retrieval_map.py` |
| 表卡 `source_docs` 仓内路径必须解析、表卡正文不得含跨表指标语义 | `tools/scripts/check_table_card_quality.py` |
| `ai_ck/metrics` 与 `semantic_contract/metrics` 不得复制同一公式、边界声明齐全 | `tools/scripts/check_metric_layer_boundary.py` |
| 弃用顶层目录（`case_studies/`、`examples/`、旧 `semantic_model/`、`agent_knowledge/manifest.yaml`）不得再被引用 | 上述路径门禁的 deprecated_route_paths |
