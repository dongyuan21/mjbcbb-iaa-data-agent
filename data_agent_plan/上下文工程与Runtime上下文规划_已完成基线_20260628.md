## 三、PI 的角色边界

**PI（earendil-works/pi）是执行框架，不做上下文压缩。**

| 能力 | PI 是否实现 | 实际在哪 |
|---|---|---|
| 知识按需加载 / 路由 | ❌ | Python `KnowledgeRouter` |
| 文件内容截断 | ❌ | `_safe_read(max_chars=...)` |
| LLM 摘要压缩历史 | ❌ | 未做（`--no-session` 无历史） |
| semantic model 切片检索 | ❌ | 规划中（相位 C） |
| per-stage token 计量 | ❌ | 规划中（相位 D） |
| KV cache 命中观测 | ❌ | TODO 仅计划 |

PI 的职责：收 prompt → 调 `data_query.py` 查数 → 多轮 tool loop → 回文本。每请求 spawn 新进程（`--no-session`），无跨轮 session，也无 PI 层历史压缩。

## 四、当前压缩手段（归档）

```
压缩 = 控制面/bootstrap 瘦身 + 任务路由按需加载 + 命中才读 + 字符硬截断
```

当前不具备：语义摘要、embedding 检索、多轮历史压缩、token 预算与计量、KV cache 优化。
