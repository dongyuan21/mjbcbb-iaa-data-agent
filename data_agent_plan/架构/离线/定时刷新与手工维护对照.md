## 一句话

**定时只刷新「数据/探测状态」；知识正文与晋升永远是事件驱动或人工。**

## A. 定时 / Worker 会做的

| 刷新什么 | 谁跑 | 典型周期 | 产物 | 说明 |
|---|---|---|---|---|
| 分析库新鲜度快照 | 本机定时脚本 / 分析库刷新脚本；山海新鲜度服务 | 本机常见 6h（也可 2h）；共享宿主周期待运维确认 | `ai_ck/engineering_artifacts/freshness_snapshot.json` | **偏分析库 (CK)**；不等于全局当前 |
| 数仓+分析库全量新鲜度 | `refresh_freshness_pipeline.py --mode full` | 多为按需 / 评估前手动；数仓定时全链路仍开放 | `ai_hive/.../freshness_snapshot.json` + 分析库同上；同运行标识 (run_id) | 评估当前窗口前应走这条或等价实时探测 |
| 新鲜度健康看板/趋势 | 流水线内或健康检查脚本 + 趋势追加脚本 | 随刷新 | `tools/runbooks/logs/freshness_health_*.json*` | 告警通道宿主侧仍可能阻塞 |
| （可选）健康检查/回归 | `--mode full` 且未 `--skip-regression` | 随全量 | `eval/DataAgent健康检查报告.md` 等 | 新鲜度阻塞是有效保护，不是脚本坏了 |

### 明确「定时不做什么」

- 不改表卡 / 策略 (policy) / 标准流程 (SOP) / 语义正文
- 不把候选 SQL (candidate_sql) 升成已验证 SQL (verified_sql)
- 不更新权威映射 (authority_map) 切面绑定
- 不重建「业务结论」；快照过期只能标阻塞 (blocker) / 降级

## B. 事件驱动 / 手工维护（不是定时任务 cron）

| 维护什么 | 典型触发 | 入口 | 完成后在线侧 |
|---|---|---|---|
| **新表入库** | 给了表名 / 表准入 | 表准入技能 (skills/table-intake) | 表卡 + 目录 (catalog) → 注册表可解析（状态过线） |
| **报告/知识入库** | 给了文档 (docx) / 周报 | 文档入库技能 (skills/docx报告入库技能) | 原始归档 → 标准流程/案例/阈值；挂权威映射后才成事实切面 |
| **SQL 晋升** | 小窗口验证 + 补文档 | `da_assets/SQL晋升治理.md` | 进已验证目录 + 索引 → 架构层 L3 可读 |
| **表卡/口径修订** | 表结构漂移、口径变更 | 各库维护流程 · `maintain_data_base.py`（分流） | 重建目录；高风险变更要人确认 |
| **默认召回边界** | 新知识要进默认可召回 | `默认召回边界与晋升规则` 等 | 目录默认召回字段 + 门禁 |
| **路由 / 检索图** | 新任务、误路由 | 任务路由 (task_routes/) · 检索映射 (AGENT_RETRIEVAL_MAP.yaml) | 建议菜单更新；≠ 资产授权 |
| **发布到测试 (test)** | 提交后要线上一致 | 山海全服务部署技能 | 接口 + 工作进程 + **新鲜度** 同提交 |

## C. 评估「当前能不能信数据」时

```text
1. 连通先行（数仓/分析库 SELECT 1 + 目标表轻量 max(分区)）
2. 刷新或确认新鲜度快照（同 run_id 的全量更稳）
3. 再谈回归 / 问答；旧快照只能标「仅快照」(snapshot_only)
```

不要：只读旧 `freshness_snapshot.json` 就宣布「现在新鲜」。

## D. 架构归位

| 平面 | 定时刷新 | 入库/晋升 |
|---|---|---|
