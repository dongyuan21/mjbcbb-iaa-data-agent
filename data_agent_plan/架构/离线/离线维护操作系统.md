# 离线维护操作系统

> 状态：`active` · 更新：2026-08-08
> 定位：离线知识库的**操作总控说明书**——谁触发、按什么顺序、何时停等人。
> 不替代：各库维护流程、技能 (skills)、SQL 晋升治理正文。

## 0. 操作系统一句话

```text
事件进来 → 归档/改对象 → 门禁 →（过人拍板）→ 注册投影 → 提交/部署
定时任务只刷新新鲜度 (freshness) 等状态，不改业务知识、不晋升。
```

## 1. 角色

| 角色 | 做什么 |
|---|---|
| **人 / 数据分析 (DA) / 负责人 (owner)** | 给材料、拍口径/关联 (join)/隐私字段 (PII)/阈值/默认召回；收待办 (TODO) |
| **智能体 (Agent，本工作区)** | 按技能入库、写数据资产目录/标准流程 (SOP)、跑门禁、写待办；不伪造已确认 (confirmed) |
| **脚本** | 目录重建 (catalog rebuild)、盖章、探测 (probe)、检查脚本 (check_*)、新鲜度流水线 |
| **分析平台新鲜度 Worker / 定时任务 (cron)** | 定时刷快照 (snapshot)；不写已验证 (verified) |

## 2. 四条主操作剧本

### 2.1 新表入库

```text
输入：表全名 (FQN) + 用途
  → 表准入技能 (skills/table-intake)
  → 连通 + 表结构 (schema)/分区探测 (probe)
  → 写数据资产目录（缺口进待办 TODO）
  → 数据资产目录 质量检查 + 重建目录 (catalog)
  → 注册表 (Registry) 可解析（状态 status 过线）
  → 提交 (commit)；需要线上则全服务同提交部署
```

易读图：[`图/一张表怎么入库.png`](图/一张表怎么入库.png)

### 2.2 报告/知识入库

```text
输入：Word 文档 (docx) / 周报
  → 文档入库技能 (skills/docx报告入库技能)
  → 原始归档 (da_assets/raw)（来源/周期/图片清单）
  → 抽取标准流程 (SOP) / 决策案例 (case) / 阈值候选 / 候选 SQL (candidate_sql)
  → 分层：已审阅 (reviewed) ≠ 已验证 (verified)；图表不反推精确数
  → 更新资产索引 (index.yaml)；默认可信则挂权威映射 (authority_map) 路径
  → 知识一致性检查 / 权威映射检查（若动 knowledge）
```

易读图：[`图/一份知识怎么入库.png`](图/一份知识怎么入库.png)

### 2.3 SQL 晋升

```text
候选 SQL (candidate_sql)（或本轮跑通线索）
  → 门禁 A 结构 → 门禁 B 小窗口验证 → 门禁 C 召回字段/正文四节
  → 进入已验证目录 (verified_sql/) + 索引（晋升状态 promotion_status=verified_sql）
  → 可选挂权威映射 SQL 实现切面 / 标准流程关联
  → SQL 晋升检查 (check_sql_promotion)；架构层 L3 此后可读
```

易读图：[`图/一条SQL怎么晋升.png`](图/一条SQL怎么晋升.png)
术语：[`../../术语解释/SQL晋升状态.md`](../../术语解释/SQL晋升状态.md)

### 2.4 例行状态刷新（定时或评估前）

```text
连通先行 → 新鲜度流水线 (refresh_freshness_pipeline)（全量 full 更稳）→ 看快照 / 健康检查
  → 不升知识；过期只标阻塞 (blocker)
```

对照：[`定时刷新与手工维护对照.md`](定时刷新与手工维护对照.md)

## 3. 建议节奏（可按团队裁剪）

| 频率 | 做什么 |
|---|---|
| **每次入库/改卡后** | 对应门禁地图「必跑」列 |
| **评估当前窗口前** | 实时连通 + 新鲜度刷新（勿只用旧快照） |
| **每日/每 6h（宿主）** | 分析库新鲜度定时任务 / 分析平台新鲜度 Worker |
| **每周** | 扫待办拍板项；路由/回归失败分流；表结构漂移 (schema drift) 报告 |
| **发布测试 (test) 前** | 知识门禁并集 + 验证脚本 (verify.py)；三服务同提交部署 |

## 4. 分流入口

| 入口 | 行为 |
|---|---|
| `tools/scripts/maintain_data_base.py` | **只分流**到分析库/数仓维护流程；不自动修、不替代技能 |
| `数据资产目录/.../CK维护流程.md` | 分析库变更类型与人/脚本分工 |
| `数据资产目录/.../Hive维护流程.md` | 数仓变更类型与人/脚本分工 |
| `TODO/数据底座维护Harness.md` | 完整 数据资产目录/默认召回联动等仍开项 |

高风险（默认选表、关联 join、隐私字段 PII、官方口径、语义晋升）→ **停，写待办，等人**。

## 5. 真相源纪律（防双写）

| 层 | 角色 |
|---|---|
| 数据资产目录 YAML | 单表合同**权威** |
| 目录 (catalog.yaml) | **投影**（重建覆盖手改状态） |
| 探索资产注册表 (ExplorationAssetRegistry) | 运行时**裁判**（可查 ≠ 可信看状态） |
| 权威映射 (authority_map) | 事实切面**绑路径**，不复制正文 |
| 新鲜度快照 (freshness_snapshot) | **状态快照**，评估前要可追溯刷新 |

## 6. 完成定义 (Definition of Done)

一次离线变更「做完」至少满足：

1. 对象落在正确目录，晋升状态 (promotion_status) / 文档状态 (documentation_status) 诚实。
2. 门禁地图对应项硬错误为 0（或明确阻塞 BLOCKED + 原因）。
3. 需要默认可信的已挂权威映射 / 注册表可解析；否则保持草稿 (draft)/候选 (candidate)。
4. 缺口在 `TODO/`，不伪装已验证 (verified)。
5. 若要线上一致：同提交部署接口 (API) + 工作进程 (worker) + 新鲜度服务。
