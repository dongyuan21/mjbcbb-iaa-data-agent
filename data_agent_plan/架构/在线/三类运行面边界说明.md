# 三类运行面边界说明

> 状态：`active_architecture`
>
> 适用范围：Data Agent 的离线内容维护、在线 Runtime 读取和 L5 查询执行。
>
> 本文的“面”是同一资产在不同生命周期和权限边界下的视图，不是新增的 L1–L6 架构层，也不是三套平行内容库。

## 一、先记住一句话

```text
离线维护面
  → Runtime 可读面
  → Runtime 可执行面
```

它们分别回答三个问题：

| 面 | 要回答的问题 |
|---|---|
| 离线维护面 | 这份内容是否被建设、校验、版本化和登记？ |
| Runtime 可读面 | 当前线上 Runtime 是否允许发现、读取和交付这份内容？ |
| Runtime 可执行面 | 当前这一次请求是否可以依据这些内容执行真实查询？ |

三者不能合并，因为“文件存在”“可以被读取”和“可以产生执行动作”是不同的事实。

## 二、离线维护面

离线维护面是仓库中由人和构建/校验脚本维护的内容、规则、索引及验证产物。这里的“维护好”不自动等于“线上已发布”。

### 1. 主要内容资产

| 内容 | 主要回答什么 | 主要位置 |
|---|---|---|
| MC 表卡 / 数据资产目录 | 表、字段、粒度、分区、PII、单表查询限制是什么 | `数据资产目录/agent_knowledge/tables/` |
| CK 表卡 / 数据资产目录 | ClickHouse 表、View、字段和查询限制是什么 | `数据资产目录/agent_knowledge/tables/` |
| Semantic Contract 源文件 | 指标、实体、维度、join、口径和失败语义是什么 | `knowledge/agent_knowledge/semantic_contract/` |
| 业务政策和分析协议 | 业务规则、默认解释、治理边界是什么 | `knowledge/agent_knowledge/policies/`、`governance/` |
| verified SQL | 哪些 SQL 已经过晋升和验证，可以作为复用资产 | `da_assets/verified_sql/` |
| SOP / decision case / 报告政策 | 分析方法、已确认案例和报告约束是什么 | `da_assets/` |
| 路由和召回配置 | 什么请求优先读取哪些内容，哪些目录不能默认召回 | `task_routes/`、`AGENT_RETRIEVAL_MAP.yaml` |
| catalog / manifest | 内容的 ID、路径、状态、归属和索引是什么 | 各 `catalog.yaml`、`agent_manifest.yaml` |

### 2. 不属于当前正式发布内容的离线文件

以下内容可以存在于仓库并参与审计或后续建设，但不能直接当作当前 Runtime 事实：

- `raw_exports/`、`da_assets/raw/`
- `draft`、`candidate`、`TODO`
- `audit_archive/`、历史 snapshot、旧 handoff
- builder、回归脚本和回归报告本身

它们是输入、线索、验证过程或历史记录，不等于已发布资产。

## 三、Runtime 可读面

Runtime 可读面是离线内容经过登记、状态和安全策略筛选后，线上可以受控发现和读取的部分。

当前主要读取入口如下：

| Runtime 入口 | 读取结果 | 注意事项 |
|---|---|---|
| `search_catalog` | 资产摘要、候选 ID、状态和索引信息 | 只能发现候选，不返回正文，也不产生执行授权 |
| `read_data_contract_view` | 表卡的受控 DataContractView | 是表合同进入本轮 Runtime 的正式入口 |
| `read_policy` | 已登记政策、数值事实、指标解释 | 用于解释和约束，不直接授权 SQL |
| `retrieve_semantic_contract` | 按问题检索的语义合同片段 | 用于理解指标、实体、维度和 join，不直接授权 SQL |
| `retrieve_verified_sql` | verified SQL 的元数据 | 不返回 SQL 正文 |
| `read_verified_sql` | verified SQL 正文 | 仍需对其中物理表重新做当前 Runtime 合同绑定 |

Runtime 并不是把仓库所有文件都开放出来。Registry、状态、引擎开关、路径 deny 规则、读取预算和当前任务的工具面共同决定能否读取。

还要区分：

```text
可搜索摘要
  ≠ 可读取正文
  ≠ 当前请求已看见
```

路由文件中的 `first_read` 只是按需读取建议；`allowed_assets` 也不是单独的最终授权。最终授权仍由 Registry、资产状态和 Runtime 安全代码决定。

## 四、Runtime 可执行面

Runtime 可执行面不是“能读取更多文件”，而是 Runtime 在当前请求中获得了有限的只读查询动作能力。

对于一条真实 MC/CK SQL，至少需要经过以下链路：

```text
用户问题
  → 找到候选表 / 语义 / SQL
  → 成功读取当前表的 DataContractView
  → 形成 DataContractBinding
  → SQL AST 物理表与 contract revision 匹配
  → 只读、PII、must_filter、引擎、扫描范围、预算检查
  → 允许调用 MC / CK executor
```

可用一个公式记忆：

```text
可执行
  = 当前表合同已读并绑定
  + SQL 安全门通过
  + 当前 Runtime 资源和引擎允许
```

### 关键限制

- 搜索到的 asset ID 不是执行凭证；
- 语义合同不是 SQL 授权凭证；
- policy 读取不是 SQL 授权凭证；
- verified SQL 读取不是表合同授权凭证；
- 表卡内容发生版本漂移或本轮没有成功读取时，必须 fail closed；
- 只有 Runtime 服务端根据本轮读取记录生成的 `DataContractBinding`，才能参与物理表授权。

## 五、三类面之间的关系

### 1. 不是三个副本

同一张表卡可以经历以下状态：

```text
仓库中维护的表卡
  → catalog 登记且状态可查询
  → Registry 收录
  → 当前 turn 成功 read_data_contract_view
  → 生成 read receipt / contract revision
  → 绑定到本轮 SQL
  → 通过 L5 安全检查后执行
```

每一步增加的是“当前性”和“授权证据”，不是复制一份新的表卡。

### 2. 允许出现的组合

| 状态 | 含义 |
|---|---|
| 离线有，Runtime 不可读 | draft、raw、历史归档、未登记、状态不允许或引擎未启用 |
| Runtime 可读，但不可执行 | 语义合同、policy、指标解释、catalog 摘要、未形成表绑定的 verified SQL |
| Runtime 可执行 | 当前表卡已读、contract revision 已绑定，且 SQL 通过 L5 所有安全门 |
| Runtime 已执行，但结果不可用 | 查询失败、空结果、freshness 不足或证据不完整；执行成功不自动等于业务结论可信 |

### 3. 运行时产生的内容不属于离线维护面

以下是 Runtime 在本轮动态产生或持久化的状态/证据，不应倒过来当作离线正式内容：

- `QuestionContract` 和 revision；
- route decision、AssetRef、model-visible 状态；
- read receipt、Registry revision、DataContractBinding；
- tool execution、query record、SQL evidence；
- freshness 结果、失败类型和终态判断。

它们记录“这一次发生了什么”，而离线维护面记录“系统准备了什么”。

## 六、和 L3、L5、L6 的对应关系

| 三类运行面 | 主要架构层 | 说明 |
|---|---|---|
| 离线维护面 | L6 | 建设表卡、语义合同、policy、verified SQL、freshness/catalog 等底座资产 |
| Runtime 可读面 | L3 | 发现、筛选、读取和交付可信资产；代码执行状态和预算控制 |
| Runtime 可执行面 | L5 | 把本轮已读取的表合同绑定到 SQL，并执行只读、安全和资源门禁 |
| 三面之间的状态和审计 | 横切面 | 保存 revision、receipt、binding、query record、证据和终态 |

因此，之前讨论的表卡和语义合同继续这样归位：

> **表卡/语义合同的持续建设是 L6；它们被 L3 受控读取；其中表卡只有在 L5 形成当前绑定并通过 SQL 安全门后，才参与真实查询执行。**

## 七、以后判断一个改动属于哪一面

遇到新的改动，先问三个问题：

1. 是在补字段、口径、join、PII、分区或业务规则吗？
   - 主要是离线维护面 / L6。
2. 是在调整 catalog、Registry、检索、读取、状态或上下文交付吗？
   - 主要是 Runtime 可读面 / L3。
3. 是在调整 DataContractBinding、SQL AST、PII、must_filter、扫描、预算或 executor 调用吗？
   - 主要是 Runtime 可执行面 / L5。

如果一个改动同时涉及多个面，要分别写清楚：

```text
离线资产改了什么
Runtime 现在能读到什么
L5 现在允许执行什么
对应的验证证据是什么
```
