## 一、架构总评

**骨架是对的，不推倒；重心错了，要翻转。**

六层主链、两个横切面、"模型只提建议、系统做裁决"这套骨架，和业界最成熟的对话系统架构是同构的。Rasa 的 CALM 架构（2023 年至今的主流商用对话框架）做法完全一致：大模型把用户的话翻译成一小组固定指令（开始某任务 / 填某槽位 / 纠正某值 / 请求澄清 / 取消），确定性引擎负责执行和管理状态，模型永远不直接改状态。这个方向经过了行业验证，值得坚持。

问题在于原方案把力气花错了地方：

1. **护栏建得比能力早。** 原方案约九成篇幅在讲怎么防模型出错（六道校验、五个实施阶段、审计、回滚、灰度），这是给已上线、有真实流量的系统设计的流程。但系统还没上线，当前真正的瓶颈是**规则看不懂中文**：轮次关系判定总共约 31 条正则，产品词表只有 2 个产品，国家只认美日韩中，拆分靠"。另外"这类标点。护栏再厚，理解力上不去，效果就是差。

2. **规则和模型的主从关系反了。** 原方案让规则做主判、模型做影子候选，Phase 4 还要求"先只接受模型与规则一致的结果"——这等于模型永远不可能超过规则。Rasa CALM 的做法正相反：模型负责理解，规则只做守门和兜底。没上线、不用兼容，应该直接翻转。

3. **候选目录机制有个死结。** 原方案要求模型只能从系统预先构造的候选 ID 里选值，但候选目录本身是规则构造的——规则抽不出"英国"，模型再聪明也无 ID 可选。这等于把规则的泛化瓶颈原样复制给了模型。解法见 4.2 节的"槽位值双轨"。

4. **协议过度设计。** 要求模型标注证据 ID、维护单独的拆分候选目录，对轻量模型太难、对强模型多余。v2 协议砍掉这两项（见 4.2 节）。

5. **JSON 格式的担心基本过时。** 这正是本次实测要回答的问题，结论见 4.4 节：网关上多个模型的严格结构化输出经对抗测试确认可用，格式合法性是已解决的问题；真正的风险是"格式对但理解错"，那由服务端校验层兜住。选 JSON 没错，不必再讨论 YAML 或自定义格式。

6. **术语是灾难。** "受控 PE"、PE-1/PE-2、T1–T7、F1–F8，再叠加架构 L2 ≠ 评测 L2 的撞名，人没法读。本文全篇用大白话，评测层命名裁决见第三部分。

## 二、当前实现的问题清单（带代码证据）

以下全部核实于当前代码（2026-08-06）。

### 2.1 轮次关系判定：约 31 条正则，命中即返回

`resolve_turn()` 按固定优先级扫正则表，每条正则自带一个拍出来的置信度常数，命中即返回：

```52:68:runtime/backend/app/services/turn_resolver.py
_CORRECTION_MARKERS: list[tuple[str, float]] = [
    # "不是 X，是 Y"
    (r"不是[^，,。\.…]+[，,，\s]*是\s*(\S+)", 0.98),  # noqa: RUF001
    # "我说的是 Y" / "我想问的是 Y"
    (r"(?:我说|我想问)的是\s*(\S+)", 0.97),
    # ... 共 8 条 ...
]
```

规模：纠正 8 条、换题 6 条（71–78 行）、槽位替换 11 条（81–94 行）、澄清回复 3 条（97–101 行）、取消 3 条（104–108 行）。

典型漏判：

- "刚才那个国家说错了，看日本"——没有"不是/改成/我说的是"字样，判不成纠正；
- "那先看下留存吧"——换题前缀只认"不看/不问了/换个/切换到"等 6 种；
- "是的，看美国"——澄清回复正则要求整句几乎只有"是的"，带补充信息就匹配不上；
- 更荒唐的反向误伤：首轮问"最近 7 天 ROI"，若会话有先前状态，第 63 行的 `最近\s*\d+\s*天` 模式会把它扫成"纠正"。

### 2.2 槽位抽取：词表小到只能算演示

- 产品别名表 `product_aliases.yaml` 只有 `block_blast` 和 `double_tile` 两个产品；"皇室麻将"、"Nova" 无从识别。
- 国家只认美日韩中加全球（`turn_resolver.py` 84 行、334–343 行）；"英国"、"东南亚"抽不出。
- 问题合同侧的筛选条件抽取只认"字段=值"句式；"美国 Facebook 的量"抽不出国家和媒体。

### 2.3 拆分：靠标点

```37:38:runtime/backend/app/services/question_decompose.py
    r"[。！？]\s*(?=另外|此外|除此之外|还有|顺便|再问|第二个问题|还想|然后|接着|再帮我|再看看|还有个)",
    r"[；;]\s*(?=另外|此外|还有|顺便)",
```

"BB 美国 DNU 呢还有素材冷启动"没有句号加分隔词，不拆。

### 2.4 三条各自为政的模型旁路（默认全关）

`config.py` 252–258 行：`MODEL_RESOLVER_*`（轮次关系兜底）、`ROUTE_LLM_*`（低置信路由）、加上双峰拆分 `llm_classify_and_split`。三条旁路各写各的提示词、各解析各的文本输出（靠提示词约定 JSON，不是严格结构化输出）。原方案说"逐步收敛为 PE-1"，开发阶段应该直接删掉，合成一次调用。

### 2.5 路由与澄清：机制尚可，输入信号太弱

路由是关键词加权打分（子串命中 + 启发式加减分），13 个候选路由；分差 ≤3 触发澄清候选 T2（`clarification_gate.py` 313 行）。机制本身没大问题，问题是打分输入全是子串命中，中文口语表达一换就失灵。澄清触发器 T1/T2 默认影子运行，T3/T6 不在允许清单里。

## 四、L2 重构方案（层次不动，内部翻转）

### 4.1 主从翻转（单主链冷启动）

一次 `question_control` 模型调用做主判，一口气产出四件事：轮次关系、路由、槽位补丁、是否需要澄清。规则降级为三件事：

1. **高置信短路**：整句"取消/重来"、澄清后的纯"是/否"短答，正则直接判，不花模型调用；
2. **失败兜底**：模型超时、网关故障、校验整体拒绝时，退回精简版规则判定；
3. **词表校验器**：模型输出的每个值都过确定性词表校验（见第五部分），模型说了不算。

单主链原则：

- 删除三条旧模型旁路（`MODEL_RESOLVER_*`、`ROUTE_LLM_*`、`llm_classify_and_split`）及配置开关，**不保留长期双轨运行**——教师/学生对比只存在于评测管线（第七部分），运行链路只有一条；
- 保留一个 **V2 总开关（kill switch）**：单个配置项，一键退回规则主判（即兜底路径转正），不需要状态迁移；
- 模型的 route 输出只影响排序与任务建议：KnowledgeRouter 词表、DataContractView、L5 SQL 绑定仍是独立授权面，模型说了不算。

拆分不进入 V2 生效范围：一句多问先按"复合问题"整体处理或触发澄清。Rasa CALM 用"一次输出多条指令"天然表达多意图，等 V2 跑稳后再评估是否需要。

### 4.2 协议 `question_control.v2`（逐字段定义）

相对原方案 v1 的改动：**砍掉证据 ID（evidence_ids）、拆分候选目录（split_candidates）、自报置信度；槽位值从"只能选目录 ID"改为"标准值双轨"。**

```json
{
  "turn_kind": "correction",
  "route": "roi_or_campaign_analysis",
  "slots": [
    {"slot": "country", "action": "replace", "value": "JP"}
  ],
  "clarification": {"needed": false, "missing_slots": []}
}
```

字段定义：

| 字段 | 类型与约束 | 说明 |
|---|---|---|
| `turn_kind` | 7 值枚举：`standalone` / `follow_up` / `correction` / `topic_switch` / `clarification_answer` / `cancel_or_restart` / `unknown` | 与现有 `TurnKind` 对齐，多一个 `unknown` 兜底 |
| `route` | 字符串，≤80 字符 | 必须落在本轮下发的路由候选内，由校验层兜住（不做动态枚举，避免 schema 每轮变化打爆网关的语法缓存） |
| `slots` | 数组 ≤5 项，每项 `{slot, action, value}` | `slot` 6 值枚举（product/time_range/metric/country/media/dimension）；`action` 只有 `replace`/`clear`；`clear` 时 `value` 固定为 `"none"` |
| `slots[].value` | 字符串 ≤80 字符，**标准值双轨** | 模型优先输出下发词表里的标准值；词表没有的，输出归一化原文（如"英国"→`UK` 做不到就原样"英国"），由服务端词表校验器定夺。这是解开候选目录死结的关键：模型的泛化力不再被规则构造的目录卡死，而词表校验是确定性的，模型说了不算 |
| `clarification` | `{needed: bool, missing_slots: [≤3]}` | 模型只建议"该不该问、缺什么"；澄清问题的文案由系统模板生成，不让模型自由写 |

Schema 工程约束（针对轻量模型和约束解码框架减负）：顶层 4 个必填字段、嵌套不超过 2 层、无 `oneOf`/`anyOf`/`$ref`、`additionalProperties: false`。约束解码基准（JSONSchemaBench，2025）显示各框架在扁平简单 schema 上覆盖率和合规率最高，复杂组合类型是主要失败区。

### 4.3 输入构造（下发给模型什么）

- 当前用户输入原文（网关与应用均在公司内网，直接用原文，不做摘要化；受限历史与已提交状态同理）；
- 已提交会话状态摘要：当前路由 + 已填槽位表，≤300 token；
- 最近历史 ≤8 条，每条截断 ≤80 字；
- 路由候选目录：13 个路由 id + 每个一句话中文描述（取自 `task_routes/INDEX.yaml`）；
- 槽位词表节选：产品全量（很小）、国家常用 30 个 + "词表外按原文输出"指令、指标/维度取语义合同高频子集；
- few-shot 示例 8–12 条，全中文，覆盖 7 类轮次关系 + 槽位继承/纠正/该澄清的典型场景。**实测已经采到第一个必收样本**：见 4.4 节，"不对，我说的是日本"被 qwen3.7-max 判成 `follow_up` 而非 `correction`。

预算：输入 ≤1500 token、输出 ≤250 token、超时 5 秒（gpt-5.4-mini 实测 20 次最大 3.01 秒，3 秒超时会误杀尾部）、温度 0（Claude 与 GPT 推理系不带温度参数）；超时或失败直接走规则兜底，不重试、不做"修复对话"。

### 4.4 输出格式结论与网关实测

**结论：JSON Schema + 网关原生严格结构化输出，成立，直接用。** 不需要 YAML、行协议或自定义格式，也不需要三级降级设计。

实测方法与样本量：2026-08-06，对 Stargate 网关（LiteLLM 代理，`https://stargate.youxi123.com`）共 48 次真实调用——能力矩阵 28 次（12 个模型 × 真约束/对抗两测试，部分模型重测）+ 延迟采样 20 次。schema 用 4.2 节协议的同构简化版。可复跑：`tools/scripts/probe_llm_structured_output.py`（matrix / latency 两种模式）；脱敏结果工件在 `eval/llm_gateway_probe/stargate结构化输出探测_20260806.json`。

- **真约束测试**：请求带严格 schema，但提示词完全不提 JSON——输出仍合规才说明是解码级约束，不是提示词注入；
- **对抗枚举测试**：提示词强硬要求把 `turn_kind` 设为枚举外的 `banana`——约束真存在就不可能出现；
- **延迟采样**：20 条不同中文输入轮换调用（相同请求会命中网关响应缓存，见下方发现 4），统计分布。

| `deepseek-v4-pro` / `flash` | ❌ 上游拒绝（400） | — | — | 不可用 |
| `glm-5.2` / `MiniMax-M3` | ❌ 参数被静默忽略，输出散文/代码块 | — | — | 不可用 |

样本量声明：以上足以证明**网关能力**（是否真约束、参数是否透传）；gpt-5.4-mini 的延迟为 20 次初测分布，正式的 P95、成本与语义主判资格以第七部分金标评测和 ≥100 次延迟采样为准。

四个必须写进设计的实测教训：

1. **"网关接受参数"≠"真约束"**：claude-haiku 接受了 schema 参数却照样输出 `banana`。所以服务端结构校验（第五部分第 2 道）不管网关声称什么都必须存在，并在本不该失败的地方失败时报警。
2. **降级路径的风险被坐实**：qwen3.6-plus 走 json_object 降级，语义判对了（`correction` + 日本）但格式发明了枚举外的 `update`，还烧了 1768 个思考 token、31 秒。降级路径不做，失败直接走规则兜底。
3. **格式能力和理解质量是两回事**：同一道题，qwen3.7-max 严格模式格式全对但轮次关系判成 `follow_up`（按协议应为 `correction`，槽位补丁倒是对的）；而降级模式的 qwen3.6-plus 反而判对了 `correction`。所以评测必须把"格式合规率"和"语义正确率"分开度量，前者预期恒为 100%，后者才是真正要优化的。
4. **网关对相同请求有响应缓存**：完全相同的请求第二次起约 0.12 秒返回（首个 2.31 秒）。好处是重复澄清恢复等场景可能白赚缓存；坏处是任何延迟/成本测量必须变换输入，评测脚本若复用固定用例要留意缓存假象。

落地注意：当前 `config.py` 第 31 行 `ALLOWED_AGENT_MODEL_FAMILIES = ("qwen", "deepseek", "claude")` 会挡掉 gpt/gemini 系。该限制针对 L4 执行主链模型；L2 的 `question_control` 客户端是独立通道，应有自己的模型配置项，不受这条限制（一行配置的事，开发阶段直接放开）。

### 4.5 轻量模型落地策略

- **档位选择**：主力 `gpt-5.4-mini`（真约束 + 最快），教师 `qwen3.7-max` 或 `claude-sonnet-5`。若后续必须换更小/更便宜的档位，先跑第七部分基准，过不了门槛就是"该档位不可用"，不魔改提示词救火。
- **教师-学生对比（只在评测管线，不在运行链路）**：开发期教师模型跑全量基准产出"教师标注"，轻量模型跑同一基准；两者分歧的样本自动进入 few-shot 候选池，经人工裁决后回填提示词（提示词蒸馏）。没有微调渠道也能持续提升轻量档位。运行链路始终只有一次学生模型调用，不存在双模型在线并跑。
- **提示词与 schema 版本化**：提示词模板、few-shot 集、schema 三者各带版本号，任一变更必须重跑基准（见第七部分回归绑定）。

## 五、校验设计：从模型输出到可信决定

对象流与类型隔离：

```text
网关原始字节
  → 解析后的候选（ParsedProposal，只代表格式合法）
  → 校验通过的决定（AuthorizedDecision，唯一可提交的类型）
  → 会话状态提交（事务 + 版本号乐观锁）
```

前两级对象在类型上就传不进状态提交函数；任何下游只准消费 AuthorizedDecision。

### 5.1 五道校验

**第 1 道 · 传输校验**
检查：超时（5 秒，见 4.3 预算）、HTTP 错误、空响应、响应长度上限（8KB）。
失败码 `qc_provider_unavailable` → 整体走规则兜底。不重试。

**第 2 道 · 解析与结构校验**
检查：`json.loads` + Pydantic 严格模式（`extra="forbid"`），必填字段、枚举、数组上限、字符串长度一次查完。
失败码 `qc_schema_invalid` → 整体走规则兜底。
真约束网关下此层失败率应为 0；出现即打 warning 日志（说明网关没有真正约束——haiku 实测就是这种情况）。

**第 3 道 · 词表与值域校验（逐项定夺，按槽位关键度分级处理）**

- `route`：必须 ∈ 本轮下发的路由 id 集合。不在 → route 降级为规则路由结果，其余字段继续处理，记 `qc_route_unresolved`；
- `slots[].value` 三步定夺：
  1. 精确命中标准值词表 → 通过；
  2. NFKC + casefold 归一后命中别名表 → 替换为标准值，通过；
  3. 均未命中 → 记 `qc_value_unresolved`，按下面的关键度分级处理。**任何情况下不猜测映射**；`media_source` 里 `Share-*`、`None`、`invite`、`activity` 这类历史脏值延续现有筛选值别名政策，继续 fail-closed（拒绝，不映射）；
- **关键槽位未解析 → 澄清或拒绝本次状态变更，不得静默继承旧值**。`product`、`metric`、`time_range` 以及影响路由的过滤值是关键槽位：用户明明改了它，系统识别不了却把补丁丢掉，等于拿旧产品/旧指标/旧时间继续回答——错得比报错更隐蔽。处理：本轮转澄清（"你说的『X』我没识别，是指……吗"），澄清不可用时拒绝该次状态变更并说明原因；
- **非关键槽位未解析 → 丢弃该条补丁**（如 `dimension` 的一个没认出的拆分维度），其余补丁继续，该槽位进澄清候选，不阻塞本轮；
- `time_range` 类值：交给现有确定性时间解析器重算，重算失败按关键槽位规则处理（time_range 是关键槽位）。

**第 4 道 · 状态转移校验**
检查（失败码 `qc_state_rejected` → 整体走兜底）：

- 会话状态版本号乐观锁（复用现有 ConversationState 机制）；
- 轮次关系合法转移表：

| 模型判定 | 前置条件不满足时 | 处理 |
|---|---|---|
| `correction` / `follow_up` | 无先前状态 | 降级为 `standalone` |
| `clarification_answer` | 无待回答的澄清 | 降级为 `standalone` |
| 任意（待澄清期间） | 只接受 `clarification_answer` / `cancel_or_restart` / `topic_switch` | 其余降级为 `clarification_answer` 处理或整体兜底 |
| `topic_switch` | — | 槽位补丁只允许 clear + 新值，不允许静默继承旧槽位 |

**第 5 道 · 业务上限校验**
检查：补丁 ≤5 条（schema 已保证，双保险）；不允许一次 clear 全部槽位（隐式重置必须走 `cancel_or_restart`）；`clarification.missing_slots` 必须真缺（与当前状态对照，已填的槽位不能算缺）。
超限项丢弃并记 `qc_limit_rejected`；clear 全部槽位这类越权整体兜底。

### 5.2 整体拒绝、澄清阻塞与逐项丢弃的裁决表

| 失败类型 | 处理 | 理由 |
|---|---|---|
| 传输 / 结构 / turn_kind 非法转移 / 越权重置 | **整体拒绝**，走规则兜底 | 轮次关系错会污染整个状态转移 |
| **关键槽位**（product / metric / time_range / 影响路由的过滤值）值未解析 | **转澄清；澄清不可用则拒绝该次状态变更** | 静默丢弃会导致拿旧值继续回答，错得比报错更隐蔽 |
| 非关键槽位值未解析 / 单条超限 | **丢弃该条**，其余继续，槽位转澄清候选 | 局部损失不应浪费整次调用，且词表缺口本来就该问用户 |
| `media_source` 命中 `Share-*` / `None` / `invite` / `activity` 类脏值 | **fail-closed 拒绝**，不猜测映射 | 延续现有筛选值别名政策 |
| route 不在候选内 | route 单项降级为规则路由，其余继续 | 路由有现成的确定性备胎 |

所有兜底结果带 `decision_source=rule_fallback` 标记；所有被拒/被丢项带失败码进决策时间线，可按轮回放。

### 5.3 负例测试清单（实施时照抄成 pytest）

每个负例断言三件事：ConversationState / Job / Outbox 零写入、失败码正确、兜底被调用。

- 第 2 道：缺字段、多字段、`turn_kind: "banana"`、6 条补丁、value 超 80 字符、根不是对象；
- 第 3 道：route 不在候选、`country: "火星"`、伪造标准值（形似 `US` 实为 `USS`）、时间表达重算失败（"最近负三天"）、**关键槽位未解析必须产出澄清或拒绝而不是继承旧值**（如 `product: "皇室战争"` 词表外）、`media_source: "Share-xxx"` fail-closed；
- 第 4 道：过期版本号、无待澄清时的 `clarification_answer`、待澄清期间的 `follow_up`、`topic_switch` 带继承补丁；
- 第 5 道：一次 clear 全部 6 个槽位、`missing_slots` 报已填槽位。

### 5.4 决策记录（Runtime 自动生成，可验证性不靠模型自报）

砍掉模型自报证据 ID 后，可回放性由 Runtime 侧自动记录承担。每轮 `question_control` 调用自动保存：

```text
turn_id
→ input_hash（用户原文哈希）+ 会话状态版本号（调用前）
→ 词表版本（canonical vocabulary revision）+ 路由目录哈希
→ 提示词版本 + schema 版本 + 模型 id
→ 模型原始输出哈希 + 解析后候选
→ 各道校验结果与失败码
→ 最终决定（AuthorizedDecision 或 rule_fallback）+ 状态版本号（提交后）
```

这些字段全部由 Runtime 生成，模型输出里一个都不占。任何一轮判定都可以凭 turn_id 完整回放"模型看到什么、说了什么、被拒了什么、最终生效了什么"。

## 七、评测方案

### 7.1 数据

| 资产 | 规模 | 用法 |
|---|---|---|
| B1 基准集（复用） | 82 条合成题，其中 65 条带多轮关系，14 个关系家族 | 轮次关系 + 问题合同字段的结构标签 |
| `eval/multi_turn/conversations.yaml`（复用） | 12 会话约 47 轮，带 turn_kind 标签 | 轮次关系最直接的对照集 |
| 现有影子对比 + 差异归因管线（复用） | — | 确定性重放、匿名报告、人工裁决工作流 |
| 23 个 turn_resolver 单测（复用） | — | 规则基线回归，翻转后作 fail-closed 对照 |
| **自然口语追问集（新增，最大缺口）** | 目标 ≥100 轮 | 省略、指代、隐式纠正、无标点多问；双人标注 + 分歧仲裁，标签对齐 v2 协议字段（现有"金标"多为模型标注或单人，不算人类真值） |

### 7.2 指标（分任务，禁止用格式合规率冒充语义指标）

- **轮次关系**：混淆矩阵 + 分类准确率；重点盯 `correction` 召回（实测已知教师模型都会漏）和 `standalone` 误判率；
- **路由**：top-1 准确率 + 兜底率；
- **槽位**：补丁级精确率/召回率 + `qc_value_unresolved` 转澄清率；
- **澄清**：误触发率 / 漏触发率（对照人工"该不该问"标注）；
- **工程**：格式失败率（真约束下预期恒 0，>0 即网关异常）、P95 延迟、单轮成本、规则兜底率。

### 7.3 晋级门槛（以人工金标的绝对正确性为准，规则只是对照）

晋级依据是**人工金标上的绝对正确性与增益**，不是与旧规则的一致性——旧规则是对照基线和失败兜底，不是模型能力上限。自然口语、多轮省略、隐式纠正、无标点多问必须进入金标集。

轻量模型在人工金标上同时满足以下各条即切主判（锚点数字，可按金标难度校调）：

1. 轮次关系准确率 ≥ 0.85，且 `correction` 召回 ≥ 0.80、`standalone` 误判率 ≤ 0.10；
2. 路由 top-1 准确率 ≥ 0.85；
3. 关键槽位补丁精确率 ≥ 0.90（宁可转澄清，不接受错值入状态）；
4. 澄清判断与人工"该不该问"标注一致率 ≥ 0.80；
5. 格式失败率 = 0（真约束下应恒成立，>0 即网关异常）；
6. P95 延迟 ≤ 3 秒（≥100 次变换输入采样；20 次初测 p90 2.62 秒、最大 3.01 秒，预期可达）。

增益核对（对照项，不是门槛）：以上各项相对规则基线的提升幅度逐项列出，任何一项明显低于规则基线都要先归因再切换。达不到 → 换档位或维持规则主判，不魔改提示词硬凑。**不设"必须与规则一致"的自锁条件**——那会让模型上限被规则封死。

### 7.4 回归绑定

切主判后，`eval_question_control_shadow.py` 纳入 `eval/agent_regression` 门禁；模型、提示词、schema、词表任一版本变更必须重跑基准并留档对比。
