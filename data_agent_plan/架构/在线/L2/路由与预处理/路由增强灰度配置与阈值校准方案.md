## 一、灰度功能清单与开关

| 功能 | 开关 env | 默认 | shadow 行为 | enforce 行为 |
|------|---------|------|------------|-------------|
| Clarification gate | `DATA_AGENT_CLARIFICATION_GATE_ENABLED` | false | shadow 记 T1/T2 metadata | 替换用户答案为反问 |
| Clarification shadow | `DATA_AGENT_CLARIFICATION_SHADOW_ENABLED` | true | 跑决策只写 metadata | gate 开后自动停 shadow |
| Clarification allowlist | `DATA_AGENT_CLARIFICATION_TRIGGER_ALLOWLIST` | T1,T2 | — | 控制 enforce 哪些 trigger |
| Route LLM enabled | `ROUTE_LLM_ENABLED` | false | 不调 LLM | 调 LLM 选 route |
| Route LLM shadow | `ROUTE_LLM_SHADOW` | true | 调 LLM 记 route_llm_event metadata | gate 开后仍可保留 |
| Route LLM enforce | `ROUTE_LLM_ENFORCE` | false | 不应用 LLM 结果 | 强制应用 LLM 选定 route |
| Route LLM timeout | `ROUTE_LLM_TIMEOUT` | 10 | — | LLM 调用超时秒数 |

### 可观测性

- **Clarification shadow**：`answer.metadata["clarification_event"]`（mode=shadow）
- **Route LLM shadow**：`answer.metadata["route_llm_event"]`（含 keyword_route / llm_selected / applied / reason）
- 两者都通过 trace 持久化到 `data_agent_traces` 的 `retrieved` / `tool_calls` JSON 列

## 二、灰度阶段

### Phase 1：Shadow 数据收集（1-2 周）

**目标**：在 test 环境（分析平台 env 811 / vars_group 545）开启所有 shadow 开关，收集 route_llm 和 clarification 的决策数据，不改变用户答案。

**配置**（分析平台 vars_group 545）：
```env
DATA_AGENT_CLARIFICATION_SHADOW_ENABLED=true
DATA_AGENT_CLARIFICATION_GATE_ENABLED=false
DATA_AGENT_CLARIFICATION_TRIGGER_ALLOWLIST=T1,T2
ROUTE_LLM_ENABLED=true
ROUTE_LLM_SHADOW=true
ROUTE_LLM_ENFORCE=false
ROUTE_LLM_TIMEOUT=10
```

**收集**：
- 每日跑 `route_quality_weekly_report.py --days 1`，看 route_llm_event 分布
- 重点观察：
  - LLM route selection 命中率（selected != none_match 的比例）
  - LLM 选择与 keyword 路由的一致率（keyword_route == llm_selected）
  - 不一致时 LLM 选择是否更准确（人工抽检 20 case）
  - clarification T1/T2 误触发率（shadow 事件中 should_clarify=true 但问题实际不模糊的比例）

**校准标准**（Phase 1 通过条件）：
- LLM route selection 命中率 > 60%
- LLM 选择与 keyword 不一致时，LLM 更准确的比例 > 70%
- Clarification T1/T2 误触发率 < 15%

### Phase 2：Clarification gate enforce T1/T2（1 周）

**目标**：在 test 环境开启 clarification enforce（只 T1/T2），观察用户体验影响。

**配置**：
```env
DATA_AGENT_CLARIFICATION_GATE_ENABLED=true
DATA_AGENT_CLARIFICATION_SHADOW_ENABLED=true  # 保留便于回滚
DATA_AGENT_CLARIFICATION_TRIGGER_ALLOWLIST=T1,T2
ROUTE_LLM_ENABLED=true
ROUTE_LLM_SHADOW=true
ROUTE_LLM_ENFORCE=false
```

**观察**：
- enforce 后用户是否被反问阻断（回答率下降 < 5%）
- 反问后用户补充信息后回答准确率是否提升
- T3 暂不开（detect_vague_question 仍在 shadow 积累数据）

**通过条件**：
- 反问阻断率 < 5%
- 反问后回答准确率提升 > 10%

### Phase 3：Route LLM enforce（1 周）

**目标**：在 test 环境开启 route_llm enforce，让 LLM 选定的 route 真正生效。

**配置**：
```env
ROUTE_LLM_ENABLED=true
ROUTE_LLM_SHADOW=true  # 保留便于回滚
ROUTE_LLM_ENFORCE=true
```

**观察**：
- 低置信度问题的回答准确率是否提升（对比 Phase 1 shadow 数据）
- LLM 选 route 后 first_read 加载是否正确
- 延迟增加 < 3s（LLM 调用 + route_by_task_id）

**通过条件**：
- 低置信度问题回答准确率 > 80%（Phase 1 baseline + 10%）
- 延迟增加 < 3s
- 无 AttributeError / 500 错误

### Phase 4：推 prod（持续）

- 在 prod vars_group 配置与 test 最终配置一致
- 持续跑周报监控
- 阈值校准见第三节

## 三、阈值校准

### 3.1 FALLBACK_CONFIDENCE_THRESHOLD（当前 0.6）

```python
# runtime/backend/app/services/knowledge.py
FALLBACK_CONFIDENCE_THRESHOLD = 0.6
```

| 阈值 | 效果 | 适用场景 |
|------|------|---------|
| 0.7 | 更多问题进 fallback，更保守 | Phase 1（多收集数据） |
| 0.6（当前） | 平衡 | Phase 2-3 |
| 0.5 | 少进 fallback，减少 LLM 调用 | Phase 4（prod 稳定后） |

**校准依据**：周报中 `low_confidence_rate`（目标 < 15%）。若 > 20%，降低阈值；若 < 5% 且 fallback 后准确率不达标，提高阈值。

### 3.2 RUNNER_UP_MIN_SCORE（当前 0.5）

```python
# runtime/backend/app/services/question_decompose.py
RUNNER_UP_MIN_SCORE = 0.5
```

控制 Secondary Read 何时触发。若周报中 `close_margin_rate` > 15%，说明双峰太多，考虑提高此阈值。

### 3.3 Clarification allowlist 扩展

| 阶段 | allowlist | 理由 |
|------|-----------|------|
| Phase 1-2 | T1,T2 | 只处理低置信度和低 margin |
| Phase 3 | T1,T2,T3 | 加入 slot 缺失 + 模糊检测 |
| Phase 4+ | 视数据 | 若 T3 误触发率 < 10% 则保留 |

### 3.4 健康指标看板

每周通过 `route_quality_weekly_report.py --days 7` 检查：

| 指标 | 健康 | 警告 | 严重 | 校准动作 |
|------|------|------|------|---------|
| 低置信度率 | <15% | 15-25% | >25% | 调 FALLBACK_CONFIDENCE_THRESHOLD |
| 双峰率 | <10% | 10-20% | >20% | 调 RUNNER_UP_MIN_SCORE |
| 周新增低分 cluster | <3 | 3-5 | >5 | 加 trigger_example |
| LLM 命中率 | >60% | 40-60% | <40% | 检查 prompt / route summary |
| Clarification 误触发率 | <15% | 15-25% | >25% | 收紧 trigger 条件 |

## 四、回滚方案

任一阶段发现严重问题，立即回滚：

```env
# 回滚到纯 shadow（不影响用户答案）
DATA_AGENT_CLARIFICATION_GATE_ENABLED=false
ROUTE_LLM_ENFORCE=false
```

回滚后仍保留 shadow 数据收集，不影响监控。
