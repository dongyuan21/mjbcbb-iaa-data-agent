### 处理层次

```
用户输入
  │
  v
Layer 0: 写操作拦截（极低成本，正则）
  │
  v
Layer 1: 启发式拆分（正则检测分隔词）
  │
  v
Layer 2: TurnResolver（多轮：指代消解、纠正、话题切换）
  │        ↑ 已有详细设计：TODO/多轮对话建设.md
  │
  v
Layer 3: 输入预处理（模糊检测、前缀提取、元问题识别）
  │        ↑ 本文档设计
  │
  v
Layer 4: KnowledgeRouter.route()（主干路由）
  │
  ├── confidence >= 0.6 → 主干
  ├── confidence < 0.6 → Fallback（低置信度Fallback方案）
  └── 双峰 → LLM 判断拆分/组合（多问题拆分方案）
```

## 三、模糊问题处理（Clarification）

### 3.1 问题描述

```
"数据怎么样？"
"看看最近的情况。"
"帮我分析一下。"
"有什么异常吗？"
```

特征：无产品、无指标、无维度、无时间——路由器无法命中任何 route。

### 3.2 现有基础

`TODO/低置信度反问协议TODO.md` 已有提及（具体内容需确认）。`多轮对话建设.md` 的 `TurnResolution` schema 中也有 `clarification.required: true/false` 和 `missing_slots: []`。

### 3.3 方案设计

```python
# 在 Layer 3 中检测

VAGUE_PATTERNS = [
    r"^.{0,10}(数据|情况|效果|表现)(怎么样|如何|咋样|好不好)[？?]?$",
    r"^(帮我|麻烦)(分析|看看|查查)[。？]?$",
    r"^(有什么|有没有)(异常|问题|变化)[？?]?$",
    r"^(最近|近期)(怎么样|如何)[？?]?$",
]

def is_vague_question(question: str) -> bool:
    """
    检测极度模糊的问题（无实体、无指标、无维度）。
    只在 question 极短且无信息量时触发；避免误判含产品名的短句。
    """
    if len(question) > 30:  # 超过 30 字通常有足够信息
        return False
    if any(re.search(p, question) for p in VAGUE_PATTERNS):
        return True
    return False
```

### 3.4 响应策略

不调用 Runtime，直接返回结构化澄清：

```python
CLARIFICATION_RESPONSE = """
请补充以下信息，我可以更精确地帮你分析：

1. **产品/游戏**：Block Blast、Double Tile、皇室麻将、还是其他？
2. **关注指标**：ROI、DNU、消耗、ARPU/变现、留存、还是素材效果？
3. **时间范围**：今天、近 7 天、还是特定日期？
4. **维度**：按媒体渠道、国家、平台、还是 campaign？

你也可以直接问具体问题，例如：
- "BB 美国 Google 最近 7 天 ROI360 怎么样"
- "DT 上周 DNU 下滑了多少"
- "素材冷启动通过率"
"""
```

### 3.5 多轮场景的特殊处理

如果 TurnResolver 有 `ConversationState`（即前面已经聊了产品/指标），则模糊问题可以从 state 继承：

```
第一轮："BB 美国 Google ROI360 怎么样"  → 正常路由
第二轮："那 Meta 呢？"                  → TurnResolver 继承 product+metric，只换 media_source
第三轮："最近怎么样？"                  → 从 state 继承 product=BB, metric=roi360 → 不反问
```

判断规则：
- **有 state 且 slots 充足** → 从 state 继承，不反问
- **无 state 或 slots 严重不足** → 触发 clarification

## 四、元问题处理（Agent Self-Description）

### 4.1 问题描述

```
"你能做什么？"
"你的数据最新到几号？"
"你有哪些表可以查？"
"你支持哪些游戏？"
"你和 MI 有什么区别？"
```

特征：问的是 Agent 自身的能力/数据/范围，不是业务分析。

### 4.2 方案设计

不需要进入 Runtime 工具循环，直接在应用层返回。

```python
META_PATTERNS = [
    r"你(能|可以)(做什么|查什么|帮什么|回答什么)",
    r"你(有|支持)(哪些|什么)(表|数据|游戏|产品|指标|能力)",
    r"(数据|分区)(最新|最近|到几号|到什么时候|更新到)",
    r"你(是什么|是谁|叫什么)",
    r"你(和|跟).{2,10}(什么区别|有什么不同|区别是)",
]

META_SUBTYPES = {
    "capability": ["能做什么", "查什么", "帮什么", "回答什么"],
    "data_scope": ["有哪些表", "支持什么游戏", "有什么数据"],
    "freshness": ["数据最新", "到几号", "更新到"],
    "identity": ["是什么", "是谁"],
    "comparison": ["区别", "不同"],
}
```

### 4.3 响应生成

根据 meta_subtype 动态生成：


## 五、What-if 假设性问题

### 5.1 问题描述

```
"如果 Google 预算翻倍，ROI 会怎样？"
"如果红线从 0.8 调到 0.7，多少 campaign 会掉出来？"
"预装量涨 50% 对 ARPU 影响多大？"
```

特征：不是查现有数据，而是需要**参数化模拟计算**。

### 5.2 两种子类型

| 子类型 | 例子 | 可否用 SQL 回答 |
|--------|------|----------------|
| A. 阈值变更模拟 | "红线改成 0.7 有多少掉出来" | ✅ 可以——改 WHERE 条件即可 |
| B. 因果推断/预测 | "预算翻倍 ROI 会怎样" | ❌ 不可以——需要因果模型 |

### 5.3 方案设计

```python
WHAT_IF_PATTERNS = [
    r"如果.{2,30}(会怎|怎么样|影响|变化|多少)",
    r"假[设如].{2,30}(会怎|影响|结果)",
    r"(改[成到为]|调[成到为]).{2,15}(会|有多少|影响)",
    r"(涨|降|翻倍|减半).{2,15}(会怎|影响|结果)",
]

WHAT_IF_SUBTYPES = {
    "threshold_simulation": [r"(红线|阈值|门槛).{0,10}(改|调|设)", r"(改[成到]).{1,5}\d"],
    "causal_prediction": [r"(预算|量|投入).{0,10}(翻倍|涨|降|减)", r"如果.{2,20}(ROI|收入|效果)会"],
}
```

### 5.4 响应策略

```python
def handle_what_if(question: str, subtype: str) -> str | None:
    if subtype == "threshold_simulation":
        # 路由到正常 route，但标记 intent=simulation
        # Runtime 生成的 SQL 用参数化 WHERE 条件
        # 输出标明"这是模拟计算，不是当前事实"
        return None  # 继续正常路由，附加 simulation_flag

    elif subtype == "causal_prediction":
        # 诚实拒绝，不编造
        return (
            "我只能查询现有数据，无法预测参数变更后的效果。\n\n"
            "我可以帮你做的替代分析：\n"
            "- 查历史上类似条件下的实际数据（如上次调预算后 ROI 变化）\n"
            "- 用当前数据做不同阈值的筛选（如红线改成 X 有多少 campaign 低于）\n"
            "- 提供当前趋势和分布，供你自行判断\n\n"
            "需要我换一种方式帮你看吗？"
        )
```

### 5.5 阈值模拟的 SQL 示例

对于"如果红线从 0.8 调到 0.7"：

```sql
-- 正常查询（红线 0.8）
SELECT count(*) AS below_redline
FROM shucang_market.ads_market_roi_cohort_sdk_multidim
WHERE sdk_roi_day360 < 0.8 ...

-- 模拟查询（红线 0.7）—— 同样 SQL 只改阈值
SELECT count(*) AS below_redline
FROM shucang_market.ads_market_roi_cohort_sdk_multidim
WHERE sdk_roi_day360 < 0.7 ...

-- 输出标记
-- ⚠️ 模拟结果：如果红线调整为 0.7，则当前有 N 个 campaign 低于新红线（比当前标准多/少 M 个）。
-- 这是基于现有数据的静态模拟，不代表调整后的动态行为变化。
```

## 六、大段上下文前缀处理

### 6.1 问题描述

```
"背景：我们上周和 UA 开会，讨论了 BB 美国 Google 渠道 ROI 连续 3 天低于红线。
会上决定先控量观察一周。现在一周过去了。
问题：控量后 ROI 有没有恢复？DNU 损失了多少？"
```

特征：
- 真正的问题在最后
- 前面的背景含重要参数约束（产品、渠道、时间、操作历史）
- 路由器的 token overlap 会被背景文本稀释

### 6.2 方案设计

```python
# 检测"背景+问题"结构
CONTEXT_PREFIX_PATTERNS = [
    r"^(背景|context|前提|情况)[：:]",
    r"(问题|我想问|请问|帮我看)[：:]",
    r"(综上|基于以上|所以我想)",
]

def extract_question_from_long_input(text: str) -> tuple[str, str]:
    """
    从含大段背景的输入中提取：
    - core_question: 用于路由的核心问题句
    - context_prefix: 保留给 Runtime 的背景信息（作为辅助上下文）
    """
    # 策略 1: 显式分隔标记
    for pattern in [r"问题[：:](.+)", r"请问[：,，](.+)", r"帮我(看|查|分析)(.+)"]:
        match = re.search(pattern, text, re.DOTALL)
        if match:
            question_part = match.group(1).strip()
            context_part = text[:match.start()].strip()
            return question_part, context_part

    # 策略 2: 最后一个问号前的句子
    sentences = re.split(r'[。！？\n]', text)
    sentences = [s.strip() for s in sentences if s.strip()]
    if len(sentences) >= 3:
        # 最后 1-2 句视为问题，前面视为背景
        question_part = "。".join(sentences[-2:])
        context_part = "。".join(sentences[:-2])
        return question_part, context_part

    # 策略 3: 无法分离，整体作为问题
    return text, ""
```

### 6.3 使用方式

```python
# 在 Layer 3 中

if len(question) > 100:  # 只对长输入做提取
    core_question, context_prefix = extract_question_from_long_input(question)
else:
    core_question, context_prefix = question, ""

# 用 core_question 做路由（避免噪音稀释）
route = router.route(core_question)

# 把 context_prefix 作为辅助信息注入 Runtime prompt
if context_prefix:
    inject_user_context(context_prefix)
```

### 6.4 从背景中提取参数

背景文本中常含重要约束，可辅助 TurnResolver 填充 slots：

```python
# 从背景中提取实体（简单正则 + 产品映射表）
def extract_params_from_context(context: str) -> dict:
    params = {}
    # 产品
    for product, patterns in PRODUCT_PATTERNS.items():
        if any(re.search(p, context) for p in patterns):
            params["product"] = product
    # 渠道
    for media, patterns in MEDIA_PATTERNS.items():
        if any(re.search(p, context) for p in patterns):
            params["media_source"] = media
    # 时间表达
    time_match = re.search(r"(上周|本周|近\d+天|最近\d+天|\d+月\d+[日号])", context)
    if time_match:
        params["time_hint"] = time_match.group(1)
    return params
```

## 七、写操作拦截

### 7.1 问题描述

```
"帮我停掉这个 campaign。"
"把红线改成 0.7。"
"把这个 campaign 暂停。"
"帮我在 MI 上调预算。"
"把这条 SQL 加到定时任务里。"
```

特征：用户请求执行写操作，违反 Agent 只读边界。

### 7.2 方案设计

在 Layer 0（最早）拦截，零 LLM 成本：

```python
WRITE_ACTION_PATTERNS = [
    r"(帮我|请|麻烦).{0,10}(停[掉了]|暂停|关[掉了]|关闭)",
    r"(帮我|请|麻烦).{0,10}(调|改|设置|修改).{0,10}(预算|出价|bid|budget)",
    r"(帮我|请|麻烦).{0,10}(放量|加量|扩量|提[高升]预算)",
    r"(帮我|请|麻烦).{0,10}(上线|下线|开启|启用|禁用)",
    r"(帮我|请|麻烦).{0,10}(创建|新建|添加|删除|移除)",
    r"(帮我|请|麻烦).{0,10}(在 MI|在平台|在后台).{0,10}(操作|执行|设置)",
    r"把.{2,20}(改[成到为]|调[成到为]|设[成为])",
]

WRITE_REJECTION_RESPONSE = """
我是只读分析助手，无法执行投放操作。

我可以帮你做的是：
- **预警**：告诉你哪些 campaign 低于红线、需要关注
- **分析**：分析调整前后的数据变化
- **证据**：提供支持决策的数据和 SQL

执行操作请前往：
- **停投/调预算/放量** → MI 平台或广告平台后台
- **修改红线/阈值** → 与 UA 确认后由管理员操作
- **定时任务** → DataWorks 平台

需要我帮你看相关数据来支持决策吗？
"""
```

### 7.3 例外处理

有些"改"不是写操作，而是分析请求：

```
"如果把红线改成 0.7 会怎样" → what-if 模拟，不是真的改
"之前改了预算之后效果怎么样" → 查操作历史，不是执行操作
```

判断规则：
- 含"如果""假设""会怎样" → 走 what-if 逻辑（第五节）
- 含"之前""之后""改了…效果" → 走正常路由（查操作历史）
- 只有"帮我改/停/调" + 无假设词 → 拦截

```python
def is_write_action(question: str) -> bool:
    if any(re.search(p, question) for p in WHAT_IF_PATTERNS):
        return False  # what-if 不是写操作
    if re.search(r"(之前|之后|改了|操作后|调了).{0,10}(效果|怎么样|数据)", question):
        return False  # 查操作历史不是写操作
    return any(re.search(p, question) for p in WRITE_ACTION_PATTERNS)
```

## 八、统一 Layer 3 预处理流程

```python
# runtime/backend/app/services/input_preprocessor.py（新增）

@dataclass
class PreprocessResult:
    action: str  # "route" | "clarify" | "meta_response" | "reject_write" | "what_if_reject"
    core_question: str           # 用于路由的问题（可能经过提取/展开）
    context_prefix: str          # 用户提供的背景信息
    meta_subtype: str | None     # 如果是元问题，具体子类型
    what_if_subtype: str | None  # 如果是 what-if，具体子类型
    direct_response: str | None  # 如果不需要 Runtime，直接返回的内容
    simulation_flag: bool        # 是否为阈值模拟（通知 Runtime 标记输出）


def preprocess_input(question: str, state: ConversationState | None) -> PreprocessResult:
    """
    Layer 3: 对用户输入做分类和预处理。
    在 TurnResolver（Layer 2）之后、KnowledgeRouter（Layer 4）之前执行。
    """
    # 1. 写操作拦截（最高优先级）
    if is_write_action(question):
        return PreprocessResult(
            action="reject_write",
            core_question=question,
            context_prefix="",
            direct_response=WRITE_REJECTION_RESPONSE,
            ...
        )

    # 2. 元问题检测
    meta_sub = detect_meta_question(question)
    if meta_sub:
        return PreprocessResult(
            action="meta_response",
            meta_subtype=meta_sub,
            direct_response=generate_meta_response(meta_sub),
            ...
        )

    # 3. What-if 假设性检测
    what_if_sub = detect_what_if(question)
    if what_if_sub == "causal_prediction":
        return PreprocessResult(
            action="what_if_reject",
            direct_response=CAUSAL_PREDICTION_RESPONSE,
            ...
        )
    elif what_if_sub == "threshold_simulation":
        # 继续路由，但标记为模拟
        pass  # simulation_flag = True

    # 4. 模糊检测（无 state 时才反问）
    if is_vague_question(question) and not has_sufficient_state(state):
        return PreprocessResult(
            action="clarify",
            direct_response=CLARIFICATION_RESPONSE,
            ...
        )

    # 5. 大段前缀提取
    core_q, prefix = extract_question_from_long_input(question) if len(question) > 100 else (question, "")

    # 6. 正常路由
    return PreprocessResult(
        action="route",
        core_question=core_q,
        context_prefix=prefix,
        simulation_flag=(what_if_sub == "threshold_simulation"),
        ...
    )
```

## 九、完整流水线（Layer 0-4 总览）

```
用户输入
  │
  v
Layer 0: 写操作拦截（正则，<1ms）
  │  → 命中：直接返回拒绝话术，不消耗 Runtime/LLM
  │
  v
Layer 1: 启发式拆分（正则，<1ms）
  │  → 命中分隔词：拆为 [Q1, Q2, ...] → 各走 Layer 2-4
  │
  v
Layer 2: TurnResolver（多轮状态，参见 多轮对话建设.md）
  │  → standalone: 直接下传
  │  → follow_up/correction: 展开为 resolved_question，继承 slots
  │  → topic_switch: 清 state，标 standalone
  │  → 低置信度: 进入 clarification
  │
  v
Layer 3: 输入预处理（本文档）
  │  → 元问题: 直接返回动态 meta_response
  │  → what-if causal: 直接返回诚实拒绝
  │  → what-if threshold: 标记 simulation_flag，继续
  │  → 模糊 + 无 state: 返回澄清反问
  │  → 长输入: 提取 core_question + context_prefix
  │  → 正常: 下传 core_question
  │
  v
Layer 4: KnowledgeRouter.route(core_question)
  │
  ├── confidence >= 0.6, 无双峰 → 主干
  ├── confidence >= 0.6, 有双峰 → 拆分/组合判断
  └── confidence < 0.6 → Fallback 通道
```

## 十一、验收标准

| 验收项 | 标准 |
|---|---|
| 写操作拦截 | 10 个写操作 case 全部拦截；10 个"查操作历史"case 不误拦 |
| 模糊检测 | 不误判含产品名的短句（"BB ROI" 不是模糊） |
| 元问题 | 动态生成的回答包含当前 catalog 中的实际表/产品/freshness |
| What-if | "如果红线改成 X" → 路由成功 + simulation 标记；"预算翻倍 ROI 会怎样" → 诚实拒绝 |
| 大段前缀 | 提取出的 core_question 能正常路由到正确 route |
| 主干不变 | 正常单问题走原流程，regression 17/17 全绿 |
