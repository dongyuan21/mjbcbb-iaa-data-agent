## 总体关系

三套能力分工如下：

| 能力 | 核心对象 | 时间锚点 | 主要回答 |
|---|---|---|---|
| MI ROI360 | 包体 / 渠道 / campaign / 国家 | `active_date` 投放日 | 花了多少钱、回收到哪里、长周期 ROI / LTV 怎么预估 |
| 素材效能看板 | 素材生产 cohort | `upload_at` 生产日 | 素材是否被测试、是否有效测试、是否出坡、是否成为爆款 |
| Campaign Overview | 单个 Campaign | `active_date` + campaign scope | 这个 Campaign 是否健康、为什么、国家/素材/操作/红线哪里拉动或拖累 |

关键呼应关系：

- MI ROI360 是 Campaign Overview 的底层经营事实来源之一，提供 `roi_359=ROI360`、`total_cost_zhe`、注册、收入、留存和预测蓝底段。
- 素材效能看板补的是 MI ROI360 不天然覆盖的前置漏斗：从素材产出到测试、有效测试、ROI0 出坡、S/A 爆款。
- Campaign Overview 的 Top 素材模块使用 MI `asset_report`，和素材效能看板都在解释素材效果，但前者站在 Campaign 消耗视角，后者站在素材生产 cohort 视角。
- 素材效能的出坡是早期 `ROI0` 阈值判断；Campaign Overview / MI ROI360 的健康度主要围绕 `ROI360`、红线和目标线，二者不能混为一个指标。
- 蓝底预测口径必须保留：MI / PGP 中 `#E0FFFF` 代表预测或预测派生段，不应在文档或导出里抹掉。

### 核心漏斗口径

| 阶段 | 公式 / 来源 | 优化师为什么关心 |
|---|---|---|
| 生产数 | `mg_material_library` 按 `upload_at` 和 `material` 去重，取最新 `updated_at` | 衡量素材团队供给，不受投放消耗影响 |
| 测试数 | 生产后 T/T+1/T+2 三个自然日内，在 FB / TT 主渠道有 spend 的素材数 | 判断素材是否进入投放测试，不让生产素材沉没 |
| 未测试数 | `生产数 - 测试数` | 直接暴露排期、素材交接或命名映射问题 |
| 有效测试数 | 从最早消耗日起 3 个自然日累计折后消耗 `>= 20 USD` | 排除没有足够预算的小样本测试 |
| 出坡数 | 有效测试窗口内 `ROI0 = date_diff=0 revenue / cost_zhe` 达到包体×渠道阈值 | 衡量素材首日回收质量，是素材是否值得继续放入策略池的早期信号 |
| 爆款数 | 最新 SABCD 标签中 `sabcd_level in ('S','A')` 的素材数 | 识别可复用模板和高潜素材 |

出坡率在 v3 口径下是 `出坡数 / 测试数`，不是旧口径的 `出坡数 / 有效测试数`。

ROI0 阈值写在 `queries.py` 常量中，核心包体如下：

| 产品 / 包体 | TikTok | Facebook |
|---|---:|---:|
| kcolb tsalb GP / iOS | 4% | 6% |
| Mahjong Blast GP | 6% | 5% |
| Mahjong Blast iOS | 7% | 6% |
| kcolb Crush GP | 8% | 8% |
| kcolb Crush iOS | 7% | 8% |

### 模块速查

| 模块 | 计算内容 | 业务含义 | 与 MI 的关系 |
|---|---|---|---|
| 指标趋势图 | 日级 `D_NEW / D_TEST / D_UNTESTED / D_MEET / D_OUTSLOPE / D_BOOM` | 看生产、测试、有效测试、出坡、爆款是否同步增长 | MI 主要从投放日看 ROI，这里从生产日看素材供给漏斗 |
| 出坡素材趋势 | 出坡数柱状 + 出坡率折线，出坡率 `D_OUTSLOPE / D_TEST` | 判断测试素材里有多少具备早期回收能力 | 不等同 MI ROI360，只是 ROI0 早期筛选 |
| 转化监控 | 测试率、有效测试率、出坡率、爆款率 | 定位漏斗瓶颈在排期、预算、小样本还是素材质量 | 可作为 Campaign/MI 异常后的素材侧归因入口 |
| 生产漏斗 | 生产、测试、有效测试、出坡、爆款五阶段总量 | 给管理层和优化师看整体衰减 | 和 MI 的 campaign 漏斗互补，不是同一粒度 |
| 未出坡原因趋势 | `未测试=生产-测试`，`预算不足=测试-有效测试`，`ROI未达标=有效测试-出坡` | 把失败原因拆成人、预算、素材质量三类 | MI 只能看到投后结果，本模块解释前置失败 |
| 产品维度 | 产品下测试、出坡、爆款和出坡率 | 比较 BB / MB / BC 的素材策略质量 | 产品来自素材名前缀，MI 多用 bundle_id，需注意对齐 |
| 渠道维度 | FB / TT 下测试、出坡和出坡率 | 判断渠道匹配和测试效率差异 | 渠道应和 MI `media_source` 归一规则保持一致 |
| 生产人效 | 设计师×日期生产矩阵 | 管理素材供给能力和产出波动 | 不直接对应 MI 指标，是组织效率指标 |
| 未测试明细 | 生产但 T+2 内未主渠道消耗的素材 | 用于催排期、查映射、查素材未投原因 | 可回查后续是否进入 MI asset_report |
| 漏斗明细 | 日期、产品、渠道、包体、素材类型、设计师与各阶段数 | 多维复盘哪类素材在哪个渠道更容易出坡 | 可作为 Campaign 异常后素材策略拆解 |
| 通晒明细 | 生产 cohort 下素材级消耗、CTR、CVR、IPM、ROI0、SABCD、状态 | 优化师复盘具体素材好坏 | 和 MI `asset_report` 需要做素材名 / material key 归一 |
| 爆款追踪 | S/A 素材趋势、产品趋势、爆款明细 | 提炼可复制爆款模板 | SABCD 标签可和 MI 投放表现互证，但标签取最新快照 |

### 需要特别保留的边界

- 本看板的日期筛选是生产日期 cohort，不是投放日期 cohort。
- 未出坡原因趋势目前可由 SQL-01 到 SQL-03 前端派生；如果写 SQL 复核，必须按同一生产 cohort 算，不要用投放日期重算。
- `bundle='—'`、`channel='Other'` 是无测试 / 未落入主渠道的 bucket，不能误删，否则未测试素材会丢。
- 素材产品识别来自素材名前缀，包体来自 spend / SABCD 维度；这两套口径必须区分。
- SABCD 爆款取最新 `dt` 快照，适合当前复盘，但不代表历史当日的素材等级。
- 通晒明细和爆款明细有 Top / limit 行数限制，不能当作完整素材全集导出。

### 页面定位

Campaign Overview 是优化师的 Campaign 工作台。它不是 MI ROI360 的复制页面，而是把 MI ROI360 rows、MI campaign-govern、MI asset_report、MI 操作历史、CK campaign meta、CK 国家预测和红线算法合成到一个页面，解决“这个 Campaign 该关注什么、风险在哪里、哪些国家/素材/操作在影响结果”。

默认收入源是 `sdk`；BB 默认 forecast version 是 `v6_sdk`，非 BB 默认 `xy_v5`。代码里接受 `v6` alias，但写文档时应落到实际有效版本。

### 关键公式与聚合

| 指标 | 公式 / 规则 |
|---|---|
| ROI360 | MI 字段 `roi_359`；聚合时按 cost 加权，若有 `revenue_359` 则优先 `sum(revenue_359) / sum(cost) * 100` |
| ROI30 / ROI60 / ROI90 | 成熟真实段或预测段按 cost / revenue 规则聚合，预测单元保留蓝底 |
| CPI | `Cost / Registers` |
| ARPU | `Revenue / Registers` |
| Retention | 按 registers 加权 |
| Campaign 预估利润 | `Cost * (ROI360 / 100 - 0.9)` |
| 国家预估收入 | `Cost * ROI360 / 100` |
| 国家预估利润 | `Cost * (ROI360 / 100 - 0.9)` |
| 国家消耗贡献 | `country_cost / positive_cost_total` |
| 国家收入贡献 | `country_estimated_revenue / total_estimated_revenue` |
| 国家利润贡献 | `country_estimated_profit / total_estimated_profit`，总利润为 0 时不计算 |
| 国家 ROI 拉动 | `country_ROI360 - campaign_total_ROI360` |

国家贡献的派生收入 / 利润 / 拉动只在预测完整可展示时输出；若国家有 partial forecast failure，后端会压掉派生值，避免半截预测误导。

## 两个看板的联合分析路径

### 从 Campaign 异常追到素材

1. 在 Campaign Overview 看 ROI360、CPI、红线、国家贡献，确认问题是回收、成本、国家结构还是冷启动样本不足。
2. 看 Top 素材效果，定位 Campaign 内高消耗素材的 CPI / IPM / ROI0 / ROI7 / 留存。
3. 回素材效能看板查这些素材或同类素材的生产 cohort：是否及时测试、是否有效测试、是否 ROI0 出坡、是否 SABCD S/A。
4. 输出时把结论拆为：Campaign 经营风险、素材前置漏斗问题、需要 UA/DA 拍板的问题。

### 从素材团队复盘追到 Campaign

1. 在素材效能看板看生产、测试、有效测试、出坡、爆款漏斗，定位瓶颈。
2. 对出坡或爆款素材，回查 Campaign Overview 的 Top 素材和 Campaign ROI360，确认是否真的带来长周期回收。
3. 对未出坡素材，区分未测试、预算不足、ROI0 未达标，不要直接写成长周期 ROI 不好。
4. 最后用 MI ROI360 作为经营事实锚，补充 campaign / bundle / media 层长周期表现。

## 回答规范

回答这类问题时必须：

- 先说明证据状态：`reviewed_code`、`candidate_sql`、`verified_sql`、`live_sql` 或 `snapshot_only`。
- 讲清楚时间锚点：素材效能是生产日 cohort，MI / Campaign 主要是投放日 cohort。
- 区分 ROI0 和 ROI360：ROI0 是素材早期出坡信号，ROI360 是经营回收目标和预警锚点。
- 标出预测段和真实段：蓝底 / forecast 字段不得被当成真实回收。
- 对投放治理只输出预警、候选、`needs_decision`，不得替业务给最终投放动作。
- 缺 freshness 时，只能给分析框架、历史口径或待验证问题，不能输出当前经营结论。
