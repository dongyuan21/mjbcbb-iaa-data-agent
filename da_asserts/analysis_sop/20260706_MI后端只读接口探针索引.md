## 鉴权与安全边界

MI 只读探针默认复用本机登录态，不在仓库保存凭证：

- `tools/scripts/mi_auth.py`：Python 脚本统一读取 `MI_AUTH_BEARER` / `MI_BEARER_TOKEN` / `MI_TOKEN`，若为空则读取 `mi-curl` 本机 token 文件。
- `/Users/<dev>/.codex/skills/mi-curl/scripts/mi_curl.sh`：用于轻量 GET / 手工接口确认，读取本机 token 与 `sso_session`。
- 禁止打印、不归档、不提交 Bearer、cookie、SSO、用户身份、raw API 明细。
- 查询只能覆盖 configuration、columns、options、rows / summary 的小窗口样本；不得调用 MI 写接口或广告平台写接口。
- `tools/scripts/probe_mi_backend_modules.py`：统一跑 ROI360、素材 configuration、campaign-govern rows / detail / radar / history / changelog 和 forecast options；默认只输出字段形态、cell 形态、行数和分页形态。

## 最小复验链路

### 一键 safe-summary 脚本

```bash
python3 tools/scripts/probe_mi_backend_modules.py \
  --bundle-id com.kcolb.juggle \
  --start-date 2026-07-05 --end-date 2026-07-05 \
  --forecast-version v6 \
  --asset-forecast-version v6_sdk \
  --revenue-source sdk \
  --limit 2 \
  --history-limit 3
```

脚本输出只保留 `http`、业务 `status_code`、configuration 字段、columns 字段、rows / summary 的首行字段名和 cell 形态、forecast option 值、detail/radar 集合形态、history/changelog 行数与分页形态。脚本内部会用高消耗 campaign 做 follow-up selector，但输出不暴露 campaign 值或用户身份。

### A. ROI360 页面能力

| 检查点 | 接口 / 脚本 | 验收 |
|---|---|---|
| configuration | `GET /api/boards/reports/roi360/configuration?v=roi360`，可用 `mi-curl` 或 `probe_mi_backend_modules.py` | HTTP 200，能看到 filters / dimensions / metrics |
| columns | `POST /api/boards/reports/roi360/query/columns`，可用 `probe_mi_backend_modules.py` | 返回本次查询列定义，不保存 raw |
| forecast options | `GET /api/boards/reports/ua_roi/filters/forecast_version/options?bundle_id={bundle_id}`，回归锚点 `forecast_version/options?bundle_id={bundle_id}`，或 `query_mi_roi360.py --forecast-version auto` / `probe_mi_backend_modules.py` | 以 options 为准判断 forecast family/version；不要把某个包体的默认值硬套给所有包 |
| media options | `GET /api/boards/reports/ua_roi/filters/media_source/options`，回归锚点 `media_source/options` | 支持 all / paid_nonorganic / organic / infoflow / preinstall 口径 |
| summary | `POST /api/boards/reports/roi360/query/summary` 或 `python3 tools/scripts/query_mi_roi360.py --endpoint summary ...` | 固定 `active_date + bundle_id`，输出聚合摘要 |
| rows | `POST /api/boards/reports/roi360/query/rows?v=roi360&offset=&limit=` 或 `python3 tools/scripts/query_mi_roi360.py --endpoint rows ...` | 固定 `active_date + bundle_id`，小 limit，输出 CSV/JSON 摘要 |

示例：

```bash
python3 tools/scripts/query_mi_roi360.py \
  --bundle-id com.kcolb.juggle \
  --start-date 2026-07-04 --end-date 2026-07-05 \
  --forecast-version auto \
  --revenue-source sdk \
  --dimensions active_date,bundle_id \
  --metrics total_cost_zhe,total_registers,roi_0,roi_6,roi_29,roi_359 \
  --endpoint rows \
  --limit 10
```

## 线上 Agent 使用规则

1. 先识别是否属于 MI ROI360、素材报表、campaign governance / history 或 PGP 页面接口问题。
2. 只读查询：优先 configuration / options，再 rows / summary 小窗口，不做写操作。
3. 结果只输出聚合事实、字段存在性、行数、状态码、业务 `code` 和必要样例指标。
4. 对 ROI360 预测时序、DNU 迟到分区、ARPU 分母、change log 因果边界，继续套用 `20260706_投放问题线上答题模板.md`。
5. 遇到 forecast、蓝底、D360=0、`v6_sdk`、`xy_` 分流或小包问题，先读 `20260706_MI预测算法链路蒸馏v3.md`；遇到 `ltv_pred` / `roi-forecast/run` / 离线预测落表问题，再读 `20260706_MI预测服务工程侧蒸馏v4.md`；不用旧 snapshot 直接下结论，必须说明当前验证时间、数据源和缺口。
