# SOP: DNU install_time 与 dt 迟到分区护栏

## 元信息

| 项 | 内容 |
|---|---|
| ID | `sop_20260618_dnu_install_time_dt_lag_guardrail` |
| 状态 | verified |
| 来源 | `data_agent_plan/POC01_BB美国UA_DNU拆解路线.md` |
| 适用问题 | DNU / activation 下滑、UA media_source / campaign / adset / ad 拆解 |
| 适用范围 | MaxCompute 激活明细表，尤其是 `dwd_market_appsflyer_activation_push_data_di` |
| 最后验证 | 2026-06-18 |

## 分析目标

防止按 `install_time` 看某天 DNU 时，只扫描同一天 `dt` 分区，漏掉 T+1 或更晚到达的激活明细，从而把数据延迟误判为投放下滑。

## 触发条件

满足任一条件时必须使用本 SOP：

- 查询使用 `SUBSTR(CAST(install_time AS STRING), 1, 10)` 或同类安装/激活业务日期。
- 查询目标是 DNU、activation、install、UA media_source、campaign、adset、ad 级拆解。
- 表是 `_di` 日增量表，且 `dt` 是数据入仓/分区日期，不一定等于业务安装日期。

## 核心规则

| 项 | 规则 |
|---|---|
| 业务日期过滤 | 用 `install_time` 或业务日期字段限定 cohort / anomaly / baseline。 |
| 分区过滤 | `dt` 必须覆盖业务日期窗口，并向后扩到 `latest_partition` 或至少 T+1。 |
| 当前窗口判断 | 先 probe 目标表 `max(dt)`，确认昨天业务日是否已有后续分区可扫。 |
| 输出边界 | 如果 `dt` 未覆盖 T+1，结果只能标为 `partial_partition_scan`，不能给强下滑结论。 |

## 推荐 SQL 结构

```sql
-- 示例：看 2026-06-17 install cohort，baseline 为 2026-06-10 ~ 2026-06-16
-- dt 扫到 2026-06-18，以纳入 T+1 迟到数据。
WHERE dt BETWEEN '2026-06-10' AND '2026-06-18'
  AND SUBSTR(CAST(install_time AS STRING), 1, 10) BETWEEN '2026-06-10' AND '2026-06-17'
```

不要写成：

```sql
-- 错误风险：只扫到业务日当天，可能漏掉 T+1 迟到数据。
WHERE dt BETWEEN '2026-06-10' AND '2026-06-17'
  AND SUBSTR(CAST(install_time AS STRING), 1, 10) BETWEEN '2026-06-10' AND '2026-06-17'
```

## 分析步骤

1. 验证 MaxCompute 连通性：`SELECT 1 AS ok`。
2. 对目标表执行轻量分区 probe：`SELECT max(dt) AS latest FROM <table>`。
3. 确定业务日期窗口：
   - `baseline_window`
   - `anomaly_day` 或 `anomaly_window`
4. 设定 `dt_scan_window`：
   - start = baseline/anomaly 中最早业务日期。
   - end = `latest_partition`，或至少 anomaly 结束日 + 1 天。
5. 跑 media_source / campaign / adset / ad 拆解。
6. 如果初版查询只扫到业务日当天，必须重跑修正版，并把初版结论标为 superseded。

## 输出格式

输出必须写明：

```text
业务日期窗口：
dt 扫描窗口：
目标表 latest dt：
是否纳入 T+1：
结果是否可作为当前窗口结论：
```

## 判断规则

- `dt_scan_end < anomaly_end + 1 day`：标 `partial_partition_scan`。
- `dt_scan_end >= latest_partition` 且 latest 覆盖 anomaly T+1：可给当前窗口结论。
- 初版和修正版差异较大时，以修正版为准，并把差异写入 POC / SOP / case。

## 示例

POC-01 初版查询把 `install_time=2026-06-17` 的 DNU 拆解只扫到 `dt=2026-06-17`，得到约 `-12169.57` 的 DNU 缺口。目标表当时 `latest dt=2026-06-18`，修正后 `dt` 扫到 `2026-06-18`，缺口修正为约 `-2378.57`。

该差异说明：当前窗口 DNU 分析如果不纳入迟到分区，容易把数据未到误判为投放下滑。
