# 报告图片处理策略

> 目标：定义哪些报告图片可以结构化，哪些只归档，避免 Data Agent 从截图中编造或过度推断数值。

## 图片类型分级

| 类型 | 例子 | 处理方式 | 可进入判断吗 |
|---|---|---|---|
| `table_screenshot` | 包体目标、GAP、DA 测算表 | OCR / 视觉模型初提取，人工校验后转 CSV / Markdown 表 | 校验后可以 |
| `simple_chart` | 单指标柱状图、简单折线图 | 只抽标题、指标、维度、趋势；精确数值需原始数据表 | 不直接作为精确数值 |
| `multi_metric_chart` | ROI P10/P25/P50/P75/P90、消耗占比多线图 | 要求补图表背后数据；只记录图表说明和待补字段 | 不直接作为精确数值 |
| `dense_heatmap` | ROI360 不同观察时间变化矩阵 | 不 OCR，不反推格子数值；记录需要原始矩阵数据 | 不进入数值判断 |
| `unclear_image` | 分辨率低、遮挡、压缩严重截图 | 只归档并标 `needs_better_source` | 不进入判断 |

## 状态枚举

`image_status` 建议使用以下值：

| 状态 | 含义 |
|---|---|
| `no_image` | 来源没有图片依赖。 |
| `image_links_seen_but_not_ocr_verified` | MCP 只看到图片链接或图片 block，未读取图片内容。 |
| `images_archived` | 图片已单独归档，但未抽取。 |
| `reviewed_image_extracts` | 图片已逐张复核，可读表格 / 图表已抽成摘要或 CSV，复杂图已标待补原始数据。 |
| `table_images_ocr_pending` | 表格截图已识别为可 OCR，尚未校验。 |
| `table_images_ocr_verified` | 表格截图已转结构化表，并人工或二次校验。 |
| `charts_need_source_data` | 图表需要补原始数据，截图不作数值源。 |
| `dense_images_archive_only` | 高密度热力图 / 矩阵只归档，不解析。 |
| `needs_better_source` | 图片质量不足，需要重新导出或补源数据。 |

## 抽取规则

### 表格截图

表格截图允许结构化，但必须保留来源字段：

```text
source_image, extraction_method, extracted_at, reviewer, review_status
```

`review_status` 为 `verified` 前，只能作为草稿，不应进入 `verified_sql`、正式阈值表或决策 case。

### 简单图表

简单图表可以抽：

- 图标题。
- 指标名。
- 维度和分桶。
- 方向性结论，如上升、下滑、分化、拐点。

精确百分比、绝对值、P 分位线数值必须来自原始数据表、SQL 或报告正文可复制表格。

### 多指标图和热力图

多指标图、热力图、高密度矩阵默认不 OCR。应记录缺失数据请求：

```text
need_source_data: true
required_fields: [metric, bucket, value, count, date_window]
reason: dense_heatmap_or_multi_metric_chart
```

如果业务只需要方向性结论，可以写入 `analysis_sop/`，但必须标注 `chart_direction_only`。

## 钉钉 MCP 特别规则

- 钉钉 MCP 返回 Markdown 正文和表格时，可读取文本表格。
- 文档中的图片链接、`unknown` kcolb 或签名 URL 只能证明有图片，不能证明图片内容已被 agent 读取。
- 不保存带 `Signature`、`OSSAccessKeyId`、`Expires` 的长期图片 URL。
- 需要使用图片时，先下载为本地附件或由用户上传截图，再按本策略处理。

## Agent 禁止行为

- 不从热力图格子颜色反推精确 ROI。
- 不从折线图坐标轴估算业务阈值。
- 不把未校验 OCR 表格写入长期阈值配置。
- 不把截图中的“数据量小”扩展成通用样本阈值，除非另有结构化定义。
