## 分析目标

把“倍率下降”拆成可验证的分子分母问题，先定位变化属于入水口抬升、长期塌方还是两者叠加，再用渠道、国家、桶、漏斗、版本证据收敛到主因。

## 输入

| 输入 | 说明 |
|---|---|
| 时间范围 | 至少覆盖异常前 28 天、异常后 7-30 天；按 cohort date 看成熟度。 |
| 对象范围 | 游戏、端、国家、渠道、自然量、campaign 或投放组。 |
| 指标 | `LTV_0`、`LTV_7`、`LTV_30`、`LTV_N / LTV_0`、留存、ARPDAU、impressions_per_dau、fill_rate、eCPM、ANR / Crash。 |
| 数据表 | 分析平台 / CK 投放报表、AF 归因、产品桶埋点、版本/崩溃数据；具体表名需由 verified SQL 补齐。 |
| 外部输入 | 市场侧配置变更日志、发版日志、广告策略变更日志。 |

## 分析步骤

1. 画 `LTV_0`、`LTV_7`、`LTV_30` 三线趋势，确认倍率下降属于哪一象限：D0 抬升、长期下降、两者叠加或整体缩水。
2. 用 7 天同 weekday WoW 做断点检测，绝对值超过 20% 的日期作为归因锚点。
3. 将 `LTV_N` 拆成留存和 ARPDAU：判断是留存先跌、广告 ARPDAU 先跌，还是两者共同下行。
4. 如果 ARPDAU 是主因，继续拆 `impressions_per_dau * fill_rate * eCPM / 1000`，判断是曝光密度、填充率还是单价问题。
5. 按端、国家、渠道、自然量、cohort date 做红绿矩阵，判断是单市场/单渠道问题还是全局同步问题。
6. 拆新回 7D、老用户 7D+、自然量，判断入水口质量和长期存量是否同时变化。
7. 同时跑产品纯净桶、商业化纯净桶、双纯净桶、实验桶。纯净桶也同步下跌时，降低实验归因优先级。
8. 做产品五层漏斗：启动、时长、广告曝光、广告收入、留存。重点验证“插屏上涨 -> 留存下跌 -> LTV 下降”链路。
9. 按版本、机型、ANR / Crash 与留存做时间相关性，判断是否发版或低端机问题。
10. 把所有证据填入归因决策表，每个候选主因必须有支持/不支持/待补证据。

## 输出格式

- 一句话结论：倍率下降属于哪一象限，主因候选是什么。
- 断点日：列出断点日期、指标、WoW 幅度。
- 分解证据：留存、ARPDAU、曝光密度、填充率、eCPM 的贡献。
- 维度证据：端、国家、渠道、自然量、新回/老用户、桶、版本。
- 归因决策表：每个候选主因给出支持/不支持/待补证据。
- 动作建议：观察、补数、降插屏、检查 SDK/中台、调整买量、暂停归因。

## 判断规则

- `LTV_0` 上升但 `LTV_N` 不变或下降，优先检查 D0 广告密度和首日吸金是否透支长期留存。
- 留存或 ARPDAU 跌幅超过 15% 时，分别优先进入留存侧或变现侧归因。
- 自然量也跌，不能把买量作为唯一主因。
- 双纯净桶也同步下跌，优先排查口径、SDK、中台、数据管道或埋点。
- 版本切换日接近断点日，必须补版本和机型证据；断点跨版本时降低发版归因优先级。

## 示例

当 `impressions_per_dau` 上升、D1 留存下降、`LTV_0` 上升但 `LTV_30` 下降时，倾向判定为首日广告密度抬升导致分母虚高，同时留存被打穿，后续需要验证插屏频控和广告策略变更。
