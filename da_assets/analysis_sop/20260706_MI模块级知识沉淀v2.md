## MI 报表通用协议

MI 报表的共同形态：

| 阶段 | 典型接口 | 作用 | Agent 用法 |
|---|---|---|---|
| configuration | `GET /api/boards/reports/{report_type}/configuration?v={report_type}` | 拿 filters、dimensions、metrics、默认值和 options API | 先验 schema，不直接回答数值 |
| options | `GET /api/boards/reports/{report}/filters/{field}/options?...` | 联动筛选项，如媒体、国家、forecast version | 验证参数候选，尤其 forecast family |
| columns | `POST /api/boards/reports/{report_type}/query/columns` | 当前维度 / 指标对应的列定义 | 验字段是否可用，不含行数据 |
| rows | `POST /api/boards/reports/{report_type}/query/rows?v={report_type}&offset=&limit=N` | 明细行 | 小 limit，只读查询；避免落 raw 明细 |
| summary | `POST /api/boards/reports/{report_type}/query/summary?v={report_type}` | 汇总行 | 先看整体，再 rows 下钻 |
| details | `POST /api/boards/reports/{report_type}/details/{detail}` | 报表详情块，如 campaign / radar | 分析平台 governance 主要使用 |
| history GET | `GET /api/boards/reports/campaign-govern/ua-operates` / `ua-remarks` / `GET /api/boards/roi/campaign-govern/changelog` | 操作历史、备注、change log | 只输出 count、窗口和候选证据，不输出人名 / raw 文本 |

返回体通用外壳：

```json
{
  "status": {"code": 0, "message": ""},
  "data": {}
}
```

rows / summary 单元格常见形态：

```json
{
  "value": 12.34,
  "type": "percent",
  "background_color": "#E0FFFF"
}
```

Agent 取值时只读 `value`；`background_color="#E0FFFF"` 是 分析平台 预测段的重要信号。保存知识时只能保存字段名、行数、状态、聚合值和验证结论，不保存完整 raw response。

## 模块 A：分析平台

### 能回答什么

- ROI1 / ROI7 / ROI30 / 分析平台 当前表现。
- SDK vs AF 回收差异。
- D360 / 分析平台 是否是预测段。
- LTV0 / LTV360 / ARPU 分母。
- 渠道、国家、campaign、adset、ad 下钻。
- forecast version 是否选错。

### 核心 filters

`分析平台` 当前 16 个 filters：

```text
active_date, week_day, bundle_id, media_source, country, user,
convert_type, advertiser_id, campaign_name, adset_name, ad_name,
revenue_type, forecast_version, reduce_spend, retarget_camp,
revenue_source
```

必须显式指定：

- `active_date`：投放日期窗口。
- `bundle_id`：包体。
- `forecast_version`：不要靠默认猜，先查 options。
- `revenue_source`：默认 `sdk`，对照可切 `af`。

### 当前维度

safe-summary 返回 11 个维度：

```text
active_date, bundle_id, country, media_source, user, forecast_version,
advertiser_id, campaign_id, campaign_name, adset_name, ad_name
```

Agent 默认粒度：

```text
active_date + bundle_id
```

需要预测段时必须保留 `active_date` 和 `bundle_id`，否则 forecast 链路可能不触发。

### 核心指标

高频指标：

```text
total_cost_zhe, total_registers, total_revenue, af_arpu,
roi_0, roi_6, roi_29, roi_359,

retention_1, retention_2, retention_6, retention_29,

```

字段映射：

| ROI7 | `roi_6` |
| ROI30 | `roi_29` |

### forecast version

不要硬编码 “MI 默认都是 v6”。必须查：

```text
GET /api/boards/reports/ua_roi/filters/forecast_version/options?bundle_id=<已脱敏>}
```

回归锚点：`forecast_version/options?bundle_id=<已脱敏>}`。

2026-07-06 safe-summary：

| bundle_id | options |
|---|---|
| `com.example.demo.game01` | `origin`, `v6`, `xy_v6`, `v6_sdk`, `v6_纠偏` |
| `com.example.demo.game04` | `xy_v5`, `xy_v4test1` |
| `com.example.demo.game03.ios` | `origin`, `v6`, `xy_v6`, `v6_sdk`, `v6_纠偏` |

业务口径：

- 示例产品 系列优先 V6 / V6_SDK 族。
- 非 示例产品 小包优先 XY 族。
- 以 options API 为当前源头；文档只记录规则，不替代当前查询。

### rows / summary 选择

| 问题类型 | 优先接口 | 原因 |
|---|---|---|
| 大盘 / 单包趋势 | summary -> rows | summary 更稳，rows 验证预测色和日期 |
| 渠道 / 国家拆解 | rows | 必须保留拆解维度 |
| campaign 复盘 | rows | `campaign_name` 是主要过滤和下钻字段 |
| D360=0 排查 | MI rows + CK 宽表 | 需要区分 runtime forecast 与 CK 落表 |
| LTV / ARPU 分母 | rows / summary + 字段语义 | 需要明确 `total_registers` vs `total_media_installs` |

### 常见失败模式

| 现象 | 原因 | 正确处理 |
|---|---|---|
| CK `sdk_revenue_day360=0` | 宽表落表/覆盖时序，不等于 MI runtime 没 forecast | 查 MI rows 蓝底与 CK `update_at` / `actual_roi_days` |
| summary ROI 为空 | 大结果集或汇总规则导致 ROI 被清空 | 用 rows 或更窄粒度复验 |
| forecast 版本不对 | 旧默认假设通用 V6 | 先查 options |
| campaign 匹配不到 | 名称空格、ID/name 混用 | 保留原始 `campaign_name`，必要时用 `campaign_id` fallback |
| 跨 media 聚合偏大 | CK 复现没按页面维度聚合 | 按页面 dimensions 重建 SQL |

## 模块 D：分析平台 Campaign Overview 如何包 MI

分析平台 不是 MI 的复制页，而是把 MI 作为来源能力再组装成工作台。

| 分析平台 模块 | MI / CK 来源 | 作用 |
|---|---|---|
| core query | 分析平台 rows / summary | 分析平台、消耗、注册、曲线主事实 |
| top15country | CK + forecast pipeline / 分析平台 补充 | 国家贡献与 forecast |
| materials | MI `asset_report` | Top 素材效果 |
| governance | MI `campaign-govern` detail / radar / rows | 目标、gap、生命周期、近期计划 |
| history | MI `ua-operates` / `ua-remarks` / changelog，CK snapshot fallback | 操作历史与备注 |
| plan configuration | CK meta + MI configuration + MI governance + asset_report | debug / 配置快照 |
| AI summary | core + governance + history + materials + curves | 只读摘要，不能自动投放 |

这里的产品边界非常关键：分析平台 可以把 MI 数据组织成“风险、候选、needs_decision”，但不能代替 UA 执行停投、放量或改预算。

## 问题分类到接口

| 用户问题 | 首选模块 | 必查 |
|---|---|---|
| 分析平台 为什么为 0 / 蓝底是什么 | 分析平台 + CK 宽表 | `roi_359` 颜色、`forecast_version`、`actual_roi_days`、`update_at` |
| 某包某渠道 分析平台 和消耗占比 | 分析平台 rows / summary | `active_date,bundle_id,media_source`，必要时 CK 验数 |
| LTV360 / LTV0 怎么算 | 分析平台 | `revenue_359 / total_registers`、`revenue_0 / total_registers` |
| Day0 ARPU 分母 | 分析平台 | `af_arpu` vs `media_arpu` |
| Top 素材为什么差 | asset_report | `campaign`、`ad_name`、`roi0/roi6`、`ret1/ret2/ret6` |
| 要看原始素材 URL | media_asset_report | 只适合 Google / AppLovin |
| Campaign 红黄线 / gap | campaign-govern + 分析平台 | `target_roi_360`、`gap`、`roi_359` |

## 回答守则

1. 先判断问题属于 分析平台、素材、campaign-govern/history、分析平台 工作台还是 CK 验数。
2. 先查 configuration / options，再查 rows / summary。
3. 所有数值回答必须带日期、包体、维度、forecast version、revenue source。
4. forecast 段必须说明是否蓝底或是否来自预测补齐。
5. history / changelog 只能作为候选操作证据，不输出确定因果。
6. 投放治理只输出预警、候选和 `needs_decision`，不输出最终投放动作。
