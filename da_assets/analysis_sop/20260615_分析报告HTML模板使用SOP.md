## 分析目标

把 raw HTML 模板中的结构沉淀为“报告生成约束”，避免把模板里的示例数值、示例结论和处置建议误读为事实。

## 输入

| 输入 | 说明 |
|---|---|
| 报告目标 | 给老板决策、给 PM 调策略、渠道质检、口径同步等 |
| 数据来源 | verified SQL、已确认数据资产目录、语义层或明确标为 draft 的 SQL |
| 数据周期 | active_date/示例产品/cohort/revenue_date 的口径必须写清 |
| 图片/图表 | 图表必须由源数据生成；不从截图反推精确数值 |
| 动作建议 | 用户 2026-06-15 确认：停投、扩量、收缩、扣款等目前只能输出 `needs_decision` |

## 使用步骤

1. 先选模板，再列出模板变量和需要的 SQL 输出列。
2. 只从 verified SQL 或本轮执行结果填充数字；draft SQL 的结果必须显式标 `draft_pending_sql_validation`。
3. 所有图表保留来源表、日期窗口、过滤条件和生成时间。
4. 报告结论使用“事实 + 含义 + 风险/下一步”，避免从相关性直接写因果。
5. 动作建议统一分级：`observe`、`needs_decision`、`approved_action`。

## 输出格式

- 标题、周期、对象范围、生成时间。
- 一句话结论，说明置信度。
- 数据口径：表、维度、指标、分母、过滤、成熟窗口。
- 关键图表和表格。
- 风险与人工确认项。
- 附录：SQL 链接、数据资产目录链接、语义层链接。

## 判断规则

| 规则 | 说明 |
|---|---|
| 示例不是事实 | 原 HTML 中填充的渠道、日期、数值、结论只作版式样例 |
| 口径先于图表 | 没有来源表和日期窗口的图表不能入报告 |
| 模板不拍板 | “停投/扩量/扣款/收缩”目前只能写为 `needs_decision` |
| 数字带来源 | 数字必须来自 SQL、数据资产目录、用户给定数据或明确的示例标签 |
| 图表可复现 | Chart.js 或 HTML 看板必须能追溯到结构化数据 |
