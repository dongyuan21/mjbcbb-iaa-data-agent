## 阈值分类规则

1. 产品名先规范化，例如 `Game Top(含越南包)` 映射为 `Game Top`。
2. `整包标准` 行使用 `data_scope=all`，与 `package_standard_pct` 比较，输出 `above_package_standard` / `below_package_standard`。
3. `投放红线 / 达标线` 行使用 `data_scope=paid_only`，与 `recovery_redline_pct` / `delivery_recovery_target_pct` 比较：
   - `分析平台 < recovery_redline_pct` -> `below_redline`
   - `recovery_redline_pct <= 分析平台 < delivery_recovery_target_pct` -> `between_redline_target`
   - `分析平台 >= delivery_recovery_target_pct` -> `above_target`
4. 同时保留周报原表阈值和白皮书阈值，若数值不同，输出 `threshold_conflict=yes`。
5. 周报截图 / Word 表抽取的 分析平台 来源标为 `roi_source=mixed`；只有 MI 行级颜色或导出蓝底能证明预测段时，才标 `forecast_blue`。
6. `sample_status=small_sample` 时，即使 `below_redline`，`decision_status` 也默认 `observe_only`。
7. 正常样本 `below_redline` 或 `between_redline_target` 可以输出 `actionable_candidate`，但 `action_boundary` 必须写为 `candidate_only_execution_requires_authorization`。

## MI 蓝底预测段验证路径

优先用 分析平台 只读查询，而不是 CK 实际 ROI7 替代 分析平台：

```json
{
  "report_type": "分析平台",
  "dimensions": ["active_date", "bundle_id", "media_source"],
  "metrics": [
    "total_cost_zhe",
    "total_registers",
    "af_cpi",
    "roi_0",
    "roi_6",
    "roi_29",
    "roi_59",
    "roi_119",
    "roi_179",
    "roi_359",
    "roi_360_range",
    "roi_trend_360"
  ],
  "filters": [
    {"field": "active_date", "operator": "between", "value": ["${start_date}", "${end_date}"]},
    {"field": "bundle_id", "operator": "in", "value": ["${bundle_id}"]},
    {"field": "forecast_version", "operator": "eq", "value": "${forecast_version}"},
    {"field": "revenue_source", "operator": "eq", "value": "sdk"}
  ],
  "metric_filters": [],
  "order_by": null,
  "only_display_warning": false
}
```

执行要求：

- 请求前先读 分析平台 configuration 与 `forecast_version` options；不要跨包硬套 `v6`。当前是两套预估族：**只有 示例产品 用 V6 系列**，其他包体使用 **XY 系列**。实测：示例产品 可用 `v6`，Game M 当前可用 `xy_v5_纠偏`，Game C / Sudoku / Demo Game 04 / Demo Game 10 / Demo Game 11 / Demo Game 01 等重点包可用 `xy_v5`。
- 本仓库提供只读辅助脚本：`python3 tools/scripts/query_mi_分析平台.py --bundle-id <bundle_id> --start-date <yyyy-mm-dd> --end-date <yyyy-mm-dd> --forecast-version auto --media-scope all`。脚本只读 `MI_AUTH_BEARER` 环境变量，不保存或输出 token。
- 优先请求 `query/summary` 看包体 / 媒体聚合，再用 `query/rows` 下钻到 campaign / country。
- `dimensions` 必须包含 `active_date` 和 `bundle_id`，否则 MI 后端不会走 ROI 预测补齐逻辑。
- 若响应或导出保留单元格颜色，`#E0FFFF` 对应 `roi_source=forecast_blue`；若颜色缺失但 分析平台 来自周报截图，标 `roi_source=mixed`。
- `roi_359` 是 分析平台；它可以是预测段，不能当真实回收。
- `revenue_source=sdk` 是 MI 默认口径；需要排查回收差异时再并列 `af`，不要混用。
- `all` 口径直接使用包体 summary；`paid_only` 可优先用 media_source quick actions 排除 `自然量` 的 `paid_nonorganic` 直查。若长 media 列表导致接口慢，只对红线重点对象直查，并标明未跑对象为 `not_run_non_key_risk_row`。
- 不保存 Authorization、cookie、token、SSO ticket、MI JWT；不点击保存、分享、导出等有副作用按钮，除非用户明确授权。

## 0615 验证摘要

本 SOP 已用于 `decision_cases/case_20260615_growth_weekly_roi_threshold_status.csv`：

- 按白皮书 trial 阈值，投放口径 16 行中 `above_target=10`、`between_redline_target=1`、`below_redline=5`。
- 正常样本中，`Demo Game 09 GP` 为 `below_redline`，`Demo Game 09 iOS` 为 `between_redline_target`，均可输出 `actionable_candidate`。
- `Demo Game 04 GP`、`Demo Game 08 iOS`、`Demo Game 11 iOS`、`Demo Game 01 GP` 为 `below_redline` 但 `sample_status=small_sample`，默认 `observe_only`。
- 周报原表与白皮书阈值存在 11 个差异，集中在 Game M、Demo Game 10、Demo Game 11、Demo Game 01；输出时必须保留 `threshold_conflict=yes`。

MI API 只读验证已沉淀到 `decision_cases/case_20260615_growth_weekly_mi_分析平台_api_validation.csv`：

- `all` 整包口径 16 行均由 MI `query/summary` 返回，`roi_359` 带蓝底 `#E0FFFF`。
- 多数整包值与周报接近，例如 Game Top GP `146.3%` vs 周报 `145.1%`、Demo Game 10 GP `87.7%` vs 周报 `87.9%`。
- `paid_nonorganic` 已对 6 个红线重点对象直查；Demo Game 09 GP、Demo Game 04 GP、Demo Game 11 iOS、Demo Game 01 GP 在 MI 当前窗口仍低于红线。
- Demo Game 09 iOS 和 Demo Game 08 iOS 在 MI 当前窗口高于红线，说明周报窗口 / 模板差异会影响动作判断；未确认精确模板前，不覆盖周报原值。

## 风险与边界

- 白皮书阈值是 `trial_active`，可用于试运行判断，但不是永久 confirmed。
- 白皮书覆盖 18 行包体 × 平台；未覆盖对象输出 `missing_threshold`。
- 阈值判断和候选动作生成可由 AI 自动完成；真实改预算、停投、放量、核减仍需业务授权。
- MI 蓝底预测是预测来源，不是真实回收；需要真实回收时只用非蓝底实际段。
