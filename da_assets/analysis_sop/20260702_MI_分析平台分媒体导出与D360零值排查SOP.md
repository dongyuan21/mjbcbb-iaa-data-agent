## 适用边界

本 SOP 用于回答 分析平台 相关导出和排查问题，尤其是分产品、分媒体导出 分析平台 / LTV0 / LTV360，计算消耗分布占比和 LTV 分布占比，排查 `sdk_revenue_day360 = 0`，以及说明如何将自然量分摊给 UA 渠道。

不适用边界：

- 不把自然量分摊解释为 AF / MMP 真实归因。
- 不把 D360=0 直接解释为停投、没有预测、或真实 D360 LTV 为 0；标准话术是“不能解释为停投、不能解释为真实 D360=0”。
- 不输出最终投放动作，只输出风险预警、候选判断和 `needs_decision`。
- 不把 candidate SQL 当 verified SQL；执行前必须做 schema / 小窗口验证。

指标口径：

| 指标 | CK 宽表公式 | 说明 |
|---|---|---|
| 折后消耗 | `SUM(cost_zhe)` | 分析平台 默认成本口径 |
| 分析平台 | `SUM(sdk_revenue_day360) / NULLIF(SUM(cost_zhe), 0) * 100` | D360 是长周期预估补全口径 |
| LTV0 / 首日 LTV | `SUM(sdk_revenue_day1) / NULLIF(SUM(registers), 0)` | MI 页面 `revenue_0` / ROI1 对应首日累计回收；CK 宽表以 `sdk_revenue_day1` 对齐 |
| LTV360 | `SUM(sdk_revenue_day360) / NULLIF(SUM(registers), 0)` | 360 日累计回收 / AF 注册设备 |
| 消耗分布占比 | `media_cost_zhe / total_cost_zhe` | 必须两阶段聚合 |
| LTV0 分布占比 | `media_sdk_revenue_day1 / total_sdk_revenue_day1` | 分布占比用收入金额占比，不用单行 LTV 直接相加 |
| LTV360 分布占比 | `media_sdk_revenue_day360 / total_sdk_revenue_day360` | 分布占比用 D360 收入金额占比 |

必须两阶段聚合：

1. 内层 CTE 先按业务粒度聚合出 `total_cost_zhe`、`total_registers`、`sdk_revenue_d1`、`sdk_revenue_d360`。
2. 外层用 totals CTE 或窗口总量计算占比。
3. 禁止 `sum(x) / sum(sum(x))`、`SUM(sum(...))` 或 aggregate inside aggregate。

## D360=0 排查 checklist

1. `示例表` 是否正确过滤了单一层级。
2. `country_group` 是否为 `other`；`other` 可能无预估覆盖。
3. 是否为 Top 国家且 `cost_zhe > 100`；这只是请求预估接口的必要线索，不是充分条件。
4. `update_at` 是否早于非 示例产品 小包夜间预估产出后的宽表刷新。
5. 非 示例产品 小包预估任务通常约 20:00-05:00 运行；宽表若先刷新，可能临时匹配不到 D360。
6. 同一日期窗口是否在后续 `update_at` 刷新后补出 D360。
7. `forecast_family` / `forecast_version` 是否匹配产品族：示例产品 走 V6 族，非 示例产品 小包通常走 XY 族；宽表本身未必暴露全部 forecast 选择，需要回 MI options / 后端口径确认。
8. `actual_roi_days` 只说明真实段边界；D360 这类长周期是预估口径，不能因为真实天数不足就当作 0。

标准判断：

```text
D360=0 不能直接解释为停投，也不能解释为真实 D360=0 或真实 D360 LTV/ROI 为 0。
应先检查 示例表、country_group、cost_zhe>100、update_at、夜间预估任务、宽表刷新时序和 forecast family/version。
```

## 自然量分摊给 UA 渠道

自然量分摊是经营试算，不是 AF / MMP 真实归因。

默认输出三版：

| 版本 | 口径 |
|---|---|
| `all` | 保留所有渠道，包括 organic / 非 UA / UA，作为总体对照 |
| `paid_only` | 只看 UA 付费媒体，不分摊自然量 |
| `allocated_organic` | 将 organic 自然量按 UA 权重摊回各付费媒体 |

默认权重：

```text
allocated_organic_dnu = organic_dnu * media_paid_dnu / total_ua_paid_dnu
```

可选权重：

```text
allocated_organic_dnu = organic_dnu * media_cost_zhe / total_ua_cost_zhe
```

输出要求：

- 必须显式写 `非 AF/MMP 真实归因`。
- 必须说明默认按 `paid_dnu`，若业务要求按消耗分摊，可替换为 `cost_zhe` 权重。
- `other`、预装、厂商商店、信息流等是否纳入自然量池需要 `needs_decision`。
- 若要求真实增量贡献，需要实验 / holdout / MMM 证据，不能从 分析平台 明细表直接推断。
