# 默认召回边界与晋升规则

## 状态

| 项 | 内容 |
|---|---|
| knowledge_status | active |
| applies_to_current | true |
| default_recall | true |
| confirmed_date | 2026-06-20 |
| confirmed_via | 用户确认采用低风险治理规则验证 knowledge 默认召回正向晋升 |
| 适用范围 | Data Agent 知识库的默认召回、证据分层和晋升边界 |

## 规则目标

本文件定义 Agent 运行时默认召回的准入边界。它只约束知识资产如何进入默认召回，不新增业务口径、不指定业务阈值、不改变 Hive / CK 默认选表、不定义 join 或指标公式。

Agent 做知识库维护、SQL 资产晋升、表卡治理或报告入库时，必须先区分三类材料：

| 类型 | Agent 行为 |
|---|---|
| 默认召回知识 | 可作为运行时规则或路由依据，但仍要遵守文档内的适用范围 |
| 维护时读取材料 | 可用于审查、修复、刷新、对账，不自动变成回答事实 |
| 证据 / 归档材料 | 只能作为来源线索或审计证据，不直接回答为当前事实 |

## 允许进入默认召回的条件

知识文件进入 `knowledge/agent_knowledge/catalog.yaml` 的 `default_recall=true` 前，至少满足以下条件：

1. `status` 必须属于 manifest 允许的默认召回状态，例如 `active`、`active_backlog`、`confirmed_evidence` 或 `trial_active`。
2. `applies_to_current` 必须与正文边界一致；历史快照、一次性分析和 source manifest 不能标为当前事实。
3. `confidence`、`facts_level` 和来源说明必须足以让 Agent 判断它是当前规则、试运行规则、证据还是路由说明。
4. 会改变业务阈值、官方口径、默认选表、join、PII 输出边界或投放动作授权的内容，必须有人确认后才能进入默认召回。
5. 只属于表级事实的内容应维护在 `ai_hive/` 或 `ai_ck/` 表卡；只属于指标、实体、join 的内容应维护在 `knowledge/agent_knowledge/semantic_contract/`；只属于可复跑 SQL 的内容应维护在 `da_assets/verified_sql/`。

## 不得默认召回的材料

以下材料不能因为“存在于仓库中”就被 Agent 当成默认事实：

| 材料 | 处理方式 |
|---|---|
| `raw_exports/`、`da_assets/raw/` | 原始证据归档，只能作为来源标注或抽取输入 |
| `knowledge/audit_archive/draft_knowledge/` | 草稿线索，必须审核后再进入正式知识层 |
| `TODO/` | 待办、问题和拍板清单，不是事实库 |
| `da_assets/candidate_sql/` | SQL 候选资产，未通过晋升前不能默认召回 |
| `knowledge/audit_archive/mi_analysis/` snapshot | 带日期的一次性分析，不代表最新 MI 当前事实 |
| `ai_ck/audit_archive/table_profiles_raw_dump/` | profile 原始 dump，只作审计和调试 |
| 旧 freshness snapshot / 旧回归报告 | 只能说明生成时状态，评价当前数据必须重新 probe |

## Codex 本机记忆同步边界

Codex 本机记忆（如 `~/.codex/memories/`、会话 rollout、临时 ad-hoc note）只是开发侧辅助材料，不是线上 PI Agent 的事实来源，也不能被直接复制进默认召回。

从本机记忆同步到线上 PI 前，必须先做筛选：

| 记忆类型 | 是否可同步到线上 PI | 正确落点 |
|---|---|---|
| 业务口径、指标语义、表字段陷阱、已验证 SQL、可复用分析 SOP、经验证的问题案例 | 可以，同步前需补来源、适用范围、状态和验证记录 | `ai_hive/` 或 `ai_ck/` 表卡、`knowledge/agent_knowledge/policies/`、`knowledge/agent_knowledge/semantic_contract/`、`da_assets/verified_sql/`、`da_assets/analysis_sop/`、`da_assets/decision_cases/` |
| 山海部署、CI、worker、Redis、runtime smoke、工具修复、临时 worktree 和本机排障过程 | 不进入业务默认召回 | 开发 runbook、技能、工程日志或 Codex 私有记忆；只在排障任务中按需读取 |
| 一次性查询结果、日期窗口样本、截图抽取、未确认 owner 结论 | 不直接进入默认召回 | `TODO/`、`audit_archive/`、`candidate_sql/` 或带状态的 evidence，待验证后再晋升 |

同步时只沉淀可复用结论，不沉淀执行流水。若一条记忆同时包含业务口径和部署过程，应拆分：业务规则进入知识层，部署证据只保留为验证记录或工程侧审计。

## 晋升路径

| 来源 | 可晋升去向 | 必需动作 |
|---|---|---|
| 报告、截图、docx、raw SQL | `da_assets/analysis_sop/`、`da_assets/verified_sql/`、`da_assets/decision_cases/` | 保留来源、周期、提取方式、置信度和验证记录 |
| candidate SQL | `da_assets/verified_sql/` | 小窗口或 live query 验证，通过 SQL 晋升门禁 |
| 表 schema / freshness / PII 变化 | `ai_hive/agent_knowledge/tables/` 或 `ai_ck/agent_knowledge/tables/` | 刷新表卡、catalog、snapshot，并跑表卡质量门禁 |
| 跨表指标、实体、join | `knowledge/agent_knowledge/semantic_contract/` | 有 verified SQL 或表卡证据，并通过语义模型回归 |
| 经人确认的跨任务规则 | `knowledge/agent_knowledge/policies/` | 更新 manifest，必要时补回归用例，通过 knowledge consistency |
| Codex 本机记忆中的可复用业务结论 | 按内容类型归入表卡、policy、semantic_contract、verified_sql、SOP 或 case | 剥离部署/基建流水，补齐来源、适用范围和验证记录；不得把私有记忆路径作为线上依赖 |

## Agent、脚本和人分别负责什么

| 角色 | 可自动处理 | 不可自动决定 |
|---|---|---|
| Agent | 文件分层、manifest 登记、门禁修复、证据摘录、低风险治理规则沉淀 | 新业务阈值、官方指标口径、默认 join、PII 放宽、投放停放量动作 |
| 脚本 | YAML / CSV / JSON 解析、路径存在性、默认召回状态、表卡质量、SQL 晋升、检索路由和回归 | 判断业务是否认可、判断口径是否官方 |
| 人 | 确认业务边界、授权高风险晋升、处理 owner 冲突 | 机械维护索引、刷新报告、格式修复 |

## Harness 验证意义

本文件是一次低风险的 knowledge 默认召回正向验证样本。若 `check_knowledge_consistency.py`、`check_agent_retrieval_map.py` 和 Agent regression 通过，说明 harness 已能验证一条确认后的治理规则安全进入默认召回。

这不等于所有业务知识都可以自动晋升。后续遇到会改变默认选表、join、指标、PII 或投放动作的规则，仍必须按本文件要求进入人确认流程。
