## 产品定位（基本边界）

| 项 | 说明 |
|---|---|
| Agent 角色 | **只读分析与预警**；不是自动投放执行器 |
| 必须输出 | 风险预警、`threshold_status`、分层观察名单、证据链（消耗/ROI/口径/freshness） |
| 禁止输出 | 最终停投、放量、降预算、广告平台写操作指令 |
| 评审口径 | **缺少自动投放是有意设计，不是能力缺口**；不得在建设计划或进度评审中将其列为待补齐缺陷 |

> **团队口径确认（2026-06-24，业务负责人口头确认）**：Agent 只预警、不自动投放；`trial_active` 红绿线可用于预警。阈值表外在投包无阈值时只标 `missing_threshold`。

## Agent 快速入口

本文件是 **UA 投放治理规则草案 + 已确认局部规则**，不是完整自动决策引擎。

Agent 读取本文件后，应先判断任务类型：

| 用户问题 | Agent 应做 | Agent 禁止做 |
|---|---|---|
| “哪些包/渠道/campaign 有风险” | 产出风险预警清单，标注触发依据和缺失阈值 | 直接宣布必须停投 |
| “哪些 campaign 可以放量” | 先分层并输出预警/观察名单；标 `needs_decision` 供人决策 | 在阈值未覆盖或未授权最终动作前自动给最终放量动作 |
| “某计划是否该降预算” | 判断是否接近/跌破红线、是否数据量小、是否 ROI 下修 | 在风控黄线、buffer 未定时给确定降幅 |
| “生成 SQL / 看板字段” | 拉取消耗、ROI、CPI、LTV、留存、all/paid_only，并输出阶段标签 | 改写业务阈值 |

## Doc 目标

这份文档的目标不是解释单个 MI 指标，而是定义 UA 投放行为的治理边界：

1. 制约会影响公司经营利润和生存安全的投放行为。
2. 建设健康的广告计划发育标准，鼓励对人群、点位、素材的持续探索。
3. 避免冷启动阶段预算过度消耗，让测试有明确目标、观察周期和退出机制。
4. 建立按月 review 的标准，适配不同产品阶段、不同预算规模和不同回收周期。

一句话：

```text
用红线限制亏损扩张，用黄线提前预警风险，用扶持政策保护有效探索。
```

强管控对象：

- 包体维度。
- 包 × 渠道维度。
- 日均消耗 > 1w 美金的 campaign / 头部计划。
- 对公司经营利润有显著影响的渠道、包体、头部计划。

|---|---:|---|
| `game_app_code` | 20 | 来自历史点位 staging CSV |
| `game_app_code × store × os` | 42 | 同一游戏在不同商店 / 系统下拆分 |
| 2026-04 首见 / 2026-06-16 确认 / 2026-07-06 更新的试运行标准 | 21 行 | 已结构化到 `../report_knowledge/PACKAGE_ROI_TARGET_THRESHOLDS.csv`，覆盖试运行重点包/端，不是 PGP 历史包体全集 |

因此，这 21 行标准不是 PGP 历史包体全集；在 2026-07-06 用户更新后，可作为覆盖包体的当前红线 / 达标线判断依据，未覆盖包体仍标 `missing_threshold` / `needs_current_threshold`。

重点关注：

- 渠道本身发生蚕食或假量。
- 包体 / 渠道 ROI 持续被击穿。
- 包体 / 渠道 ROI 持续下行，存在击穿风险。
- 头部计划 ROI 被击穿。
- 头部计划 ROI 持续下行，存在击穿风险。

## 三条线

| 线 | 含义 | 触发后动作 |
|---|---|---|
| 风控黄线 | 蚕食、假量等风险分达到黄灯标准 | 禁止继续加量，转交风控 + DA 进一步设计策略 |
| 回收红线 | 公司无法接受的 ROI 下限 | 立即缩小预算，直到恢复到红线以上 |
| 投放回收达标线 | 计划优化目标线 | 作为 UA 优化和放量的目标标准 |

当前已知定义：

- 回收红线：公司无法接受对应 ROI，需要立即缩小预算。
- 投放回收达标线：使用包维度 ROI 扣除自然量后，逆向推算目标 ROI；理论上计划优化应以达标线为目标。
- 风控黄线：按 campaign / 渠道计算风控分；达到黄灯后禁止继续加量。

## 治理政策

### 风控治理

蚕食、假量约束：

- 分 campaign / 渠道计算风控分。
- 当风控分达到黄灯标准时，禁止继续加量。
- 后续转交风控 + DA 进一步设计策略。
- MI 相关功能预计 6.15 就绪；在此之前由分析师手动导出 Excel。

### ROI 治理

包 ROI：

- `../report_knowledge/PACKAGE_ROI_TARGET_THRESHOLDS.csv` 已由 2026-06-16《发行红绿线执行说明（试运行）》确认，并在 2026-07-06 由用户更新为 21 行当前试运行阈值，当前状态为 `trial_active`。
- 该表覆盖 21 个包体 × 平台，可用于试运行阶段红线 / 达标线判断；输出时必须标 `trial`，且不替业务下最终停投、放量、降预算动作。
- 未覆盖包体、风控黄线、ROI 下修 buffer、数据量小通用阈值仍保持待补。

包 × 渠道 ROI：

- 同时参考回收红线与投放回收达标线。
- 跌破红线时立即缩预算。
- 达标线用于长期优化目标和放量判断。
- 2026-06-16 试运行文档明确：包维度、包 × 渠道、日均消耗 >= 1w 美金 campaign 使用同一套阈值，不另加渠道修正系数。
- 未被 21 行试运行标准覆盖的包体 / 平台，仍需补阈值后再判断。

日均消耗 >= 1w 美金 campaign：

- 进入强管控。
- 需要按回收红线、达标线和 ROI 趋势判断是否继续加量、观察、降预算或停投。

### Google ROI 参考标准（用户输入，2026-07-05）

状态：`user_confirmed_reference`。这是业务侧提供的历史参考标准，用来帮助 Agent 做 Google 投放对象的风险分层和追问，不是自动执行规则；输出仍必须遵守“只预警、不自动投放”。

参考周期：

- `2026-01` 到 `2026-06`。

参考池：

| 参考池 | 用途 | 当前已知目标 |
|---|---|---|
| Google 整体 + 全国家 | 做整体历史均值和目标预估 360 ROI 参考 | 目标预估 360 ROI 约 `80%~85%+` |
| google-US | 做 US 单国家历史均值参考 | 目标值未在本轮输入中结构化；默认按历史均值比较，不擅自补数 |

判断标准：

| 状态 | 判断规则 | Agent 输出 |
|---|---|---|
| 优秀 | 首日 ROI / 各节点 ROI 高于历史均值 `10%~20%` | 标 `above_reference` / `excellent_candidate`，仍不输出最终放量动作 |
| 可观察 | 首日 ROI / 各节点 ROI 处于历史均值或上下浮动 `10%` 左右 | 标 `observe_only`；如持续 `4` 天无改善趋势，升级为 `needs_decision` / `needs_optimization_review` |
| 需立刻优化预警 | 首日 ROI / 各节点 ROI 低于历史均值 `20%`，且持续 `2` 天以上无变化 | 标 `needs_optimization_review` + `needs_decision`；不得直接输出停投、降预算或改广告平台动作 |

辅助指标：

- 优先结合各节点 ROI 判断，不只看单日 ROI。
- 当首日 ROI 或预估 360 ROI 达标时，继续对比 CPI、ARPU、留存、倍率。
- 若 CPI 高于历史均值 `10%~20%`，或 ARPU、留存、倍率低于历史均值 `10%~20%`，标 `needs_attention`。
- 单日周期性波动超过 `10%~20%` 时，标 `volatility_attention`，并拆看 `3~7` 天整体预估 360 ROI 和国家结构。
- 新手保护期按 `14` 天处理；保护期内避免用未成熟 ROI 给强结论。

回答边界：

- 必须说明所用参考池：Google 整体 + 全国家，或 google-US。
- 必须说明是“历史均值参考 / 业务参考标准”，不是实时验证结果。
- 若缺少历史均值、对象窗口、国家、campaign 粒度或 freshness，先输出待补证据，不强行分层。
- 与红线 / 达标线冲突时，先分别输出 `threshold_status` 与 `reference_status`，再标 `needs_decision`。

日均消耗 <= 10w 美金产品：

- 3w 美金以内：以探索为主。
- 3w 到 10w 美金：`360 ROI > 75%`。

## ROI 上下修趋势

UA 需要关注不同观测周期下 ROI 的上修与下修趋势。

DA 每周通晒不同观测周期的 ROI 修正方向：

- ROI 向下修复：观测周期越久，ROI 越低。UA 需要预留 ROI buffer，避免后续下修后击穿红线。
- ROI 向上修复：观测周期越久，ROI 越高。UA 可以适当调节 ROI 约束，并联系约束 owner 修改范围，提升放量空间。

使用建议：

- 不要只看短期预测 ROI 是否刚好超过红线。
- 对存在下修趋势的包 / 渠道 / campaign，需要更高 buffer。
- 对长期稳定上修的对象，可以讨论放宽约束，但必须有 DA 周期性证据。
- ROI 下修 buffer 的具体算法仍由算法同学调整中，当前不在文档里写死。

## 扶持政策

公司鼓励围绕点位、人群、素材进行持续的广告计划探索。

扶持方向：

- 有明确测试假设的点位探索。
- 有明确人群差异的人群探索。
- 有明确素材策略的素材探索。
- 能形成复盘闭环并证明价值收益的计划。

## 冷启动标准

业务经验与预估收敛规律：

- 7 天内 360 ROI 预估噪声大。
- 14 天后预估 ROI 开始收敛。
- 21 天后趋于平稳。
- 冷启动周期最长定为 14 天。

冷启动期定义：

```text
累计消耗 < 7K 美金
且
投放周期 <= 14 天
```

冷启动测试建议：

- 日均消耗 `< 300 USD` 时，只能观察，不输出放量 / 降预算动作候选。
- 观察时间至少达到 7 天。
- 时间过短时 ROI 模型无法收敛，结论不稳定。
- 7 天是基础观察窗口，不等于自动通过冷启动；进入爬坡仍需结合 ROI、累计消耗、留存 / 倍率 / CPI 和人类判断。

## 爬坡标准

符合以下任一条件，可认为通过冷启动并进入爬坡：

1. 累计消耗 >= 4K 美金，观察周期 >= 7 天，且 ROI 超过达标线。
2. 累计消耗 >= 4K 美金，观察周期 >= 14 天，ROI 超过红线，且留存 / 倍率 / CPI 有较强优势。

其中“留存 / 倍率 / CPI”的计算以 MI ROI360 口径为准：

- `af_cpi = total_cost_zhe / total_registers`。
- `ltv_7_2 = ROI7 / ROI2`，`ltv_30_2 = ROI30 / ROI2`，`ltv_360_2 = ROI360 / ROI2`。
- 留存汇总按 `sum(retention_N × installs) / sum(installs)`，且只统计成熟且 `retention_N > 0` 的行。

爬坡阶段增加预算前需要：

- 达到爬坡标准。
- 交给分析师分析并给出意见。
- 单次预算增加不应超过 100%。
- 单次增加预算后，需要静止保持 4 天以上，观察回收稳定性。

头部标准：

```text
日均消耗 >= 1w 美金
且
ROI 达到目标管控标准
```

头部 campaign 接近红线或存在击穿风险时，Agent 只输出 `needs_decision`，抛给人决策；不自动给降预算、停投或放量动作。

## Review 审视线

按 UA 负责人维度 review：

- 总冷启动阶段消耗。
- 冷启动阶段 ROI。
- 出坡效率。
- 是否存在过多饱和创建广告计划，影响广告模型优化。

创建测试前，需要有明确测试方向：

- 测什么点位。
- 测什么人群。
- 测什么素材。
- 成功标准是什么。
- 失败后如何止损。

建议在创建测试前，交给分析师与约束 owner 讨论，结合分析视角补充结论。

## Agent 使用规则

回答 campaign 放量 / 降预算 / 停投问题时，必须先判断对象阶段：

| 阶段 | 判断条件 | 主要策略 |
|---|---|---|
| 冷启动 | 累计消耗 < 7K 且周期 <= 14 天 | 控制日均预算，至少观察 7 天；日均消耗 `< 300 USD` 只能观察 |
| 爬坡候选 | 累计消耗 >= 4K 且周期达标 | 看 ROI 是否超过达标线或红线 + 质量优势 |
| 爬坡中 | 已通过冷启动，准备增预算 | 单次加预算 <= 100%，加后静止观察 >= 4 天 |
| 头部计划 | 日均消耗 >= 1w | 强管控 ROI 红线、达标线和上下修趋势；接近红线时交给人决策 |
| 包 / 渠道治理 | 包或包 × 渠道 ROI 被击穿或持续下行 | 触发红线 / 黄线治理 |
| 数据量小包 | 当前数据样本不足、日均消耗 `< 300 USD`，或试运行阈值表中标注 `sample_status=small_sample` | 当前样本不足时只观察；表内 small_sample 可用于对应阈值对象观察标记，不能泛化为通用阈值；`not_provided` 不等于小样本 |

### Agent 执行流程

1. 确定对象粒度：包、包 × 渠道、campaign。
2. 确定数据口径：固定输出 `all` 与 `paid_only`，不要只给单版。
3. 判断 ROI 来源：蓝底预估、真实值、还是混合；蓝底不得当作最终真实回收。
4. 判断生命周期：冷启动、爬坡候选、爬坡中、头部计划、数据量小。
5. 匹配当前 `trial_active` / `confirmed` 阈值；未覆盖包体标 `missing_threshold` / `needs_current_threshold`。
6. 生成状态：观察、候选动作、需要拍板、上会、算法待定。
7. 明确下一步 owner：业务、DA、风控、算法、UA。

### 输出边界

Agent 可以输出：

- 风险候选。
- 放量候选。
- 观察名单。
- 数据量小名单。
- 缺失阈值清单。
- 上会问题清单。

Agent 不应输出：

- “必须停投”这类最终指令，除非阈值已结构化且用户明确授权自动判断。
- 未定义的 ROI buffer。
- 未定义的风控分黄灯阈值。
- 单版 organic 结论。
- 将阈值表中的 21 行标准误认为全部包体标准。

Agent 不应自行拍板：

- 新增或修改具体包维度 ROI 红线数值。
- 新增或修改具体包 × 渠道达标线数值。
- 风控分黄灯阈值。
- “业务制定投放目标”与“DA 30 天数据反推目标”冲突时以谁为准。
- ROI 下修趋势需要预留多少 buffer。
- “留存 / 倍率 / CPI 有较强优势”的动作阈值。
- 素材 IPM 高但 ROI 差时是否继续测、收缩或换方向。

Agent 可以做：

- 从 MI / CK / MC 拉取消耗、ROI、CPI、LTV、registers、media_installs。
- 按包、渠道、campaign 聚合，识别接近试运行红线 / 当前阈值缺失 / 持续下行对象。
- 固定产出 `all` 与 `paid_only` 两版。
- 输出冷启动、爬坡、头部计划分层清单。
- 对“数据量小”包默认给观察结论，不直接触发红线强动作。
- 标注哪些判断依赖业务阈值，不能自动给出最终动作。
