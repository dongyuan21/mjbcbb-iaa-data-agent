# 花费同步与对账规则

> **来源**: `nexus/backend/boards/internal/service/report/handler/cost/spend_sync/` 模块源码蒸馏  
> **蒸馏日期**: 2026-06-20  
> **状态**: reviewed  
> **适用范围**: 投放花费按月同步 API、花费对账、Data Agent 花费类 SQL 写作

---

## 1. 模块概述

花费同步模块提供**按月维度聚合投放花费**的查询能力。前端 / 调用方传入月份列表（YYYY-MM），后端**并发**查询两个 ClickHouse 数据源，合并后统一返回 USD 计价的花费明细。

输出粒度：`month × bundle_id × media_source × agent_company`。

## 2. 双源聚合逻辑

| 来源 | CK 实例 | 库表 | 含 bundle_id | 用途 |
|---|---|---|---|---|
| **V2（来源 A）** | shucang（aliyunClickHouse） | `shucang_market.tj_ad_spend_active_v2` | 是 | 主花费明细，含完整的 bundle_id 维度 |
| **advertiser_bak（来源 B）** | reduce（clickhouseReduce） | `ad_revenue_bak.tj_advertiser_data_list` | 否（仅取 `bundle_id = ''` 的行） | 补充代理花费，V2 中缺失的部分 |

### 聚合规则

- 两个来源**并发查询**，结果直接拼接（`append`），不做去重。
- 来源 B 在 SQL 层面已通过 `WHERE bundle_id = ''` 过滤，与来源 A 的有 bundle_id 行互斥，因此拼接不会产生重复。
- 来源 B 的外层 SELECT 将 bundle_id 硬编码为 `'BlockBlast'`（当前业务仅此一个产品走 bak 补充）。

### 花费计算公式

| 来源 | 原始花费（美元） | 折扣花费（美元） |
|---|---|---|
| V2 | `ROUND(SUM(cost / currency), 2)` | `ROUND(SUM(cost_zhe / currency), 2)` |
| advertiser_bak | `ROUND(SUM(cost / f_exchange_rate), 2)` | `ROUND(SUM(cost_zhe / f_exchange_rate), 2)` |

- V2 的 `currency` 字段和 bak 的 `f_exchange_rate` 字段都是汇率转换因子，将本币转为 USD。
- 输出 `currency` 固定为 `"USD"`。
- 所有金额保留 2 位小数（`ROUND(..., 2)`）。

### 过滤条件

| 来源 | 过滤条件 | 说明 |
|---|---|---|
| V2 | `cost > 0` | 排除零花费行 |
| advertiser_bak | `(cost + cost_0) > 0` 且 `HAVING costs > 0` | cost_0 是附加费用字段，两者合计大于 0 才保留；聚合后再过滤一次 |

## 3. 月份格式转换规则

### API 输入

- 格式：`YYYY-MM`（如 `"2026-05"`）
- 校验正则：`^\d{4}-\d{2}$`
- 年份下限：≥ 2020
- 月份范围：01–12
- 不允许未来月份（以 UTC 当前月为上界）

### CK 查询参数

API 的 `YYYY-MM` 在代码中转为两种格式，分别喂给两个来源：

| 来源 | 参数类型 | 转换方式 | 示例 |
|---|---|---|---|
| V2 | `[]uint32` | 去掉连字符，转数字 | `"2026-05"` → `202605` |
| advertiser_bak | `[]string` | 去掉连字符，保留字符串 | `"2026-05"` → `"202605"` |

### CK 内月份提取

| 来源 | SQL 表达式 | 返回类型 |
|---|---|---|
| V2 | `toYYYYMM(toDate(active_date))` | UInt32 |
| advertiser_bak | `toUInt32(LEFT(toString(date), 6))` | UInt32（从字符串截取再转） |

### 返回值格式化

查询返回的 `uint32` 月份（如 `202605`）格式化回 `YYYY-MM`：
- 年 = `m / 100`
- 月 = `m % 100`
- 输出 = `fmt.Sprintf("%04d-%02d", year, month)`

## 4. 花费对账口径

对账时需注意：

1. **统一币种为 USD**：V2 用 `cost / currency` 换算，bak 用 `cost / f_exchange_rate` 换算；两个汇率字段命名不同但语义相同。
2. **V2 与 bak 互斥拼接**：bak 仅取 `bundle_id = ''` 的行，V2 包含有 bundle_id 的行，两者不重叠。
3. **bak 的 bundle_id 硬编码**：输出中 bak 行的 bundle_id 被强制设为 `'BlockBlast'`，不反映真实包名。
4. **排序**：V2 按 `costs DESC`，bak 按 `agent_company, costs DESC`；最终合并后无全局排序保证。
5. **输出维度一致**：两个来源的 GROUP BY 维度统一为 `month, bundle_id, media_source, agent_company`（bak 内层先按原始维度聚合，外层覆盖 bundle_id）。

## 5. 查询护栏

| 护栏 | 规则 | 说明 |
|---|---|---|
| 月份数量上限 | **最多 6 个月**（`maxMonths = 6`） | 超出返回错误 |
| 月份格式 | 必须 `YYYY-MM` | 不符合正则返回错误 |
| 未来月份 | 不允许 | 与 UTC 当前月比较 |
| 年份下限 | ≥ 2020 | 更早的年份返回错误 |
| 去重 | 自动去重 | 相同月份只查一次 |
| 空输入 | 返回错误 | months 为空或全空白均拒绝 |
