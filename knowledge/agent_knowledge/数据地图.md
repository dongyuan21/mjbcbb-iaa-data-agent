# knowledge 数据地图

`knowledge/agent_knowledge/` 是已审核业务知识、分析规则和跨表语义契约层，用来回答“哪些规则能默认引用、哪些只能作为线索、哪些需要当前确认”，以及“跨表指标、维度、join 应该按哪个机器契约执行”。

## 默认读法

1. 先读 `knowledge/agent_knowledge/catalog.yaml`，检查目标文件的 `status`、`default_recall`、`applies_to_current` 和 `confidence`。
2. 业务规则、SQL 协议、分析协议优先读 `knowledge/agent_knowledge/policies/`。
3. 报告抽取知识读 `knowledge/agent_knowledge/report_knowledge/`，必须看周期和当前适用边界。
4. 跨表指标、维度、join、治理状态和诊断先读 `knowledge/agent_knowledge/semantic_contract/model.json`；源 YAML 只在维护时读取。
5. 对账证据读 `knowledge/agent_knowledge/reconciliations/`，只作为对应口径的证据链。
6. 草稿和快照回到 `knowledge/audit_archive/`，不得当当前事实。

## 主要入口

| 主题 | 位置 | 使用边界 |
| --- | --- | --- |
| 召回注册表 | `knowledge/agent_knowledge/catalog.yaml` | 机器可读真理源 |
| 当前业务规则 / SQL 协议 | `knowledge/agent_knowledge/policies/` | active / confirmed 才可作为当前规则 |
| 跨表语义契约 | `knowledge/agent_knowledge/semantic_contract/model.json` | 机器可读 metric / dimension / join / governance 入口 |
| 报告知识 / 阈值表 | `knowledge/agent_knowledge/report_knowledge/` | 默认只对来源周期成立；trial_active 可作试运行候选判断 |
| 提示词 | `knowledge/agent_knowledge/prompts/` | 操作规范，不是业务事实 |
| 对账证据 | `knowledge/agent_knowledge/reconciliations/` | 支撑口径校准，不替代表卡或 verified SQL |

## 状态边界

- `active` / `confirmed_evidence`：可按 manifest 边界默认引用。
- `trial_active`：可用于当前候选判断，但最终动作仍需人确认。
- `snapshot` / `snapshot_data`：带日期的一次性输出，不代表最新事实。
- `draft_only`：只能作为治理线索。
- `semantic_contract` 源 YAML：属于机器契约构建输入，默认读 `model.json`，维护时才读 YAML。
