# semantic_contract 数据地图

`knowledge/agent_knowledge/semantic_contract/` 是跨表语义契约层，用来把自然语言里的业务实体、维度、指标、join、治理状态和异常诊断映射到已治理表卡。

## 边界

- `knowledge/agent_knowledge/semantic_contract/model.json` 是默认消费入口；源 YAML 是构建输入，不替代表卡。
- `ai_ck/agent_knowledge/tables/` 和 `ai_hive/agent_knowledge/tables/` 负责单表字段、分区、PII、freshness 和 pitfalls。
- `da_assets/verified_sql/` 负责已验证 SQL；语义层可以引用它，但不能把候选 SQL 自动晋升为 verified。
- `audit_archive/` 中的候选提案不进入默认召回。

## 主要链路

| 主题 | 入口 |
| --- | --- |
| Agent 默认语义契约 | `model.json` |
| 实体 | `entities.yaml` |
| 维度 | `dimensions.yaml` |
| 指标 | `metrics.yaml` |
| join | `joins.yaml` |
| 投放治理状态机 | `governance.yaml` |
| 异常诊断映射 | `diagnostics.yaml` |
| 构建与回归 | `knowledge/engineering_artifacts/semantic_contract/build_model.py`、`knowledge/engineering_artifacts/semantic_contract/eval/` |

## 使用原则

- 跨表 SQL 先从 `model.json` 找 metric 和 join，再回到表卡检查字段、过滤和 PII。
- `needs_decision` metric 或治理字段只能输出待决，不生成自动动作。
- CK 与 MaxCompute 不直接 SQL join；需要分别查询后在应用层或分析层对齐。
- 修改源 YAML 后必须重跑 `python3 knowledge/engineering_artifacts/semantic_contract/build_model.py` 和 `python3 knowledge/engineering_artifacts/semantic_contract/eval/compose_sql.py`。
