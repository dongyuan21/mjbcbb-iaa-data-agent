### P0：D7 累计收入被误解为第 7 天当天收入

证据：

- 原问题 replay session `6edc9e99-181c-418d-8d72-8976ddd88d44` 的 D7 SQL 只取行为表 `dt='2026-06-24'`。
- 变体 replay session `11a3c89c-36b4-4fec-9f51-edb2862b0fc1` 的 `d7_rev` 也是行为表 `dt='2026-06-24'`。
- 用户要的是“激活 D0/D7 收入均值 / d7总收入均值”里的 D7 累计口径，即 cohort 用户从 D0 到 D7 的累计收入均值；不是第 7 天当天收入。
- 非负收入口径下，D7 累计收入均值应大于等于 D0 累计收入均值。线上回答出现 D0 高于 D7，本身就是强信号。

正确 SQL 形态：

- D0 收入：`dt = cohort_date` 的收入。
- D7 累计收入：`dt >= cohort_date AND dt <= cohort_date + 7` 的收入累计。
- 人均值分母：同一个 activation cohort 的 `COUNT(DISTINCT distinct_id)`。

建议 runtime 修复：

- 将 `D7累计`、`D7总收入` 和常规 `D0/D7收入均值` 都解释为累计到第 N 天；只有用户明确说“D7 当天”才用单日收入。
- SQL 生成阶段为 D7 累计添加模板约束，不允许只写 `dt = cohort_date + 7`。
- 结果校验阶段增加单调性检查：非负收入下，D7 累计均值低于 D0 累计均值时，必须停止并自检口径。
