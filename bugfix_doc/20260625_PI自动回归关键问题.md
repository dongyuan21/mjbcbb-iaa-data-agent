# 20260625 PI 自动回归关键问题

> 记录日期：2026-06-25
> 范围：PI 自动回归暴露的 runtime 稳定性问题
> 状态：已闭环（fixed_and_regression_passed）

## 一、问题

按 Goal 模式建设并运行 PI 自动回归（脚本 `tools/scripts/pi_replay_regression.py`，用例 `eval/pi_replay_regression/cases.yaml`，同题 D0/D7 收入均值）。第一次回归暴露的不是 D7 语义退化，而是 5 类 runtime 稳定性问题：

| 编号 | 问题 | 根因 |
|---|---|---|
| 1 | 只读 SELECT 被误报"Only read-only SQL is allowed" | SQL 前带 `-- D0 single-day smoke` 注释，`ensure_read_only()` 未先剥离 leading SQL comment |
| 2 | MC 聚合 smoke 报 `column ... should appear in GROUP BY` | PI 生成 `SELECT dt, COUNT(1) ... LIMIT 1` 未写 `GROUP BY dt` |
| 3 | MC freshness probe 全分区扫描被拒 | PI 生成 `SELECT MAX(dt), MAX(SUBSTR(active_time_utc8,...))` 无 `dt` 分区谓词 |
| 4 | 回归脚本 `/api/chat` 长请求超时 | HTTP 空读超时，脚本无法稳定拿到 session_id |
| 5 | D7 cohort 日期漂移 | PI 在无显式日期时把 cohort 从 `2026-06-17` 漂到 `2026-06-16` |

## 二、解决方案

| 问题 | 修复 | 提交 |
|---|---|---|
| 1 | `runtime/tools/data_query.py` 在 `ensure_read_only()` 前剥离 SQL 注释（leading `--`、inline `--`、`/* */`） | `ca121d5` |
| 2 | `data_query.py` 对窄范围 partition count smoke 自动补 `GROUP BY`；prompt 要求维度列 + 聚合必须 group by | `6964c29` |
| 3 | `data_query.py` 对 freshness probe 降级为安全的 `SELECT MAX(dt) AS max_dt FROM <table>`；prompt 禁止无分区谓词读非分区字段 | `7bac38d` |
| 4 | `pi_replay_regression.py` 改用 `/api/chat/stream`，通过 SSE heartbeat 保持连接 | `e15d722` |
| 5 | prompt 固化：用户未指定 cohort 日期且要求 D7 时，用收入表最新成熟分区 `revenue_latest_dt - 7 天`；回归 case 增加 `assistant_must_include: "2026-06-17"` | `e15d722` |

## 三、验收

二次回归连续 3 次 PASS（session `cfdc4a21` / `16ac1515` / `e25430a2`）：query_records 5-7 条均成功、0 失败；MC 有实际 query_records 证据；核心 SQL D7 收入用累计窗口 `dt >= '2026-06-17' AND dt <= '2026-06-24'`；分母保护用 `LEFT JOIN + COALESCE` 保留 cohort 全量；最终回答 D7 累计均值高于 D0 均值。

最终报告：`eval/PI调用日志复核_20260625/20260625_PI自动回归测试报告.md`，状态 `pass`。

## 四、遗留观察项

无。该问题已关闭。后续同类 PI 回归必须继续保留 query_records 失败检查，不能只看最终文本答案。

## 五、方法论沉淀

1. **只读护栏要先剥离 SQL 注释**：SQL 前缀注释是合法语法，护栏不能因注释误判 SQL 类型。
2. **PI 生成的 smoke SQL 要在 runtime 层归一化**：聚合 smoke 自动补 GROUP BY、freshness probe 降级为安全形态，不能指望 PI 每次都写对。
3. **cohort 日期不能漂移**：用户未给日期时必须固化"最新成熟 cohort"规则并在回归用例里断言具体日期，防止 PI 自由选择导致口径不稳。
4. **长查询回归用 SSE 流式**：HTTP 空读超时会误判后台成功为失败，改用 SSE heartbeat 保持连接。
