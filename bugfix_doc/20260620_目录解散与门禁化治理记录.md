# 20260620 目录解散与门禁化治理记录

> 记录日期：2026-06-20
> 范围：解散 `case_studies/`、`examples/` 两个游离顶层目录；统一三库 manifest 命名；把"靠人盯"的边界改成脚本门禁
> 状态：已闭环
> 前序：`20260620_知识层收敛与语义契约归并记录.md`

## 一、问题

1. **游离顶层目录**：`case_studies/`、`examples/` 不应独立存在，但解散前被 25+ 张表卡当 `source_docs` / `evidence`，不能裸删。
2. **manifest 命名不一致**：ai_hive/ai_ck 用 `catalog.yaml`，knowledge 用 `manifest.yaml`，近似名并存易混淆。
3. **三层定义三处复制**：三层"用途分层规范"在三个库 README 各写一份，事实重复，易漂移。
4. **边界靠人盯**：顶层目录分类、表卡 source_docs 解析、跨表指标不进表卡、ai_ck/metrics 与 semantic_contract/metrics 边界，都靠人工记忆，无脚本强制。

## 二、解决方案

### 1. 目录解散（文件夹消失，内容并入工程）

| 旧路径 | 新位置 | 理由 |
|---|---|---|
| `case_studies/wide_hi/` | `ai_hive/audit_archive/evidence/wide_hi/` | MC 侧血缘审计证据 |
| `case_studies/mi_roi360_board_recon/` | `ai_ck/audit_archive/mi_roi360_board_recon/` | CK/MI 反推对账证据 |
| `examples/audience/` | `da_assets/candidate_sql/audience/` | 未验证 SQL 样例与 candidate_sql 概念重合，统一治理 |

用 `git mv` 保留历史 + 确定性迁移脚本重写引用。顺带修复 61 个历史遗留的 `source_docs_unresolved`，表卡 quality_gaps 从 66 降到 5。

### 2. manifest 命名统一

knowledge 的 `agent_knowledge/manifest.yaml` 改名为 `catalog.yaml`。统一后规则：**每库都是 `agent_manifest.yaml`（挂载）+ `agent_knowledge/catalog.yaml`（召回注册表）**。

### 3. 三层定义单源化

三层规范抽到唯一 canonical：`data_agent_plan/知识库三层结构规范.md`。三个 README 的通用三层表改为一行指向规范，只保留本库具体文件清单。

### 4. 边界门禁化（不靠人盯）

| 边界 | 门禁实现 |
|---|---|
| 顶层目录必须被路由图分类 | `check_agent_retrieval_map.py` 新增 `check_top_level_coverage` |
| `showoff/`、`bugfix_doc/`、`术语解释/` 等人读目录纳入分类 | `AGENT_RETRIEVAL_MAP.yaml` 新增 `reference_only_dirs` |
| 表卡 `source_docs` 仓内路径必须解析 | `check_table_card_quality.py`：未解析 → 硬错误（G1） |
| 表卡正文不得含跨表指标/语义 | `check_table_card_quality.py`：禁 `requires_join`、顶层 `metrics:`、`type: cross_table`（F1） |
| `ai_ck/metrics` 与 `semantic_contract/metrics` 边界 | 新增 `check_metric_layer_boundary.py`（E1） |
| 弃用顶层目录不得回潮 | 两个门禁的 `deprecated_route_paths` 新增 `case_studies/`、`examples/`、`agent_knowledge/manifest.yaml` |

`check_metric_layer_boundary.py` 已接入 `run_regression.py`。

## 四、遗留观察项

1. `da_assets/candidate_sql/audience/*.sql` 是未验证样例，未登记 index.yaml（gate 不扫 `.sql`）；如需晋升走 `SQL晋升治理.md`。
2. 三层规范是单源；后续新增知识库或新层必须先改 `data_agent_plan/知识库三层结构规范.md` 再落地，避免又回到三处复制。

## 五、方法论沉淀

1. **解散文件夹不是裸删**：被表卡当 source_docs/evidence 的目录，要"解散 + 内容并入对应审计层 + 重指向全部引用"，迁移脚本保留历史。
2. **边界必须门禁化**：靠人盯的边界迟早失守，每个边界都要有对应 check 脚本强制，并接入回归。
3. **规范单源化**：通用定义只在一个 canonical 文件写，各处指向它，避免三处复制漂移。
4. **弃用路径要防回潮**：门禁的 `deprecated_route_paths` 列表防止后续文档重新引用旧目录。
