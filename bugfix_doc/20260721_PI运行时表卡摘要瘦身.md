# 20260721 PI 运行时表卡摘要瘦身（read_table_card_excerpts）

> 记录日期：2026-07-21
> 范围：PI 运行时表卡摘要提取（上下文工程，四轮压缩之外的独立轨道）
> 级别：性能优化
> 证据：commit `f243c3f8`
> 状态：已实现、已测试、已 push 到 origin/main

## 一、问题

`ai_hive`/`ai_ck` 单张表卡 8-17KB（158 张里最大 15KB），但 PI 运行时回答业务问题实际只需要关键字段（表名、分区、必须过滤、join key、known_pitfalls），不需要完整 schema、审计证据、历史变更。`read_table_card_excerpts` 已只提取关键字段（单卡输出 500-1200 字符），但读代码后发现两处展示层 bug + 缺兜底截断：

1. **分区字段 bug**：158 张表卡里 31 张只声明 `freshness.partition_field`、没有独立 `partitions` 列表（如 `tj_ad_sdk_revenue.yaml` 只有 `freshness.partition_field: active_date`），旧代码只读 `card.get("partitions")`，导致这 31 张摘要误显示"分区: N/A"。
2. **known_pitfalls 展示 bug**：`known_pitfalls[i].get("issue", p)` 的兜底值是整个 pitfall dict `p`（而非 `p.get("id")`），若某条 pitfall 缺 `issue` 字段，会把 `detection`/`example` 等维护期证据字段的 Python dict repr 整段串进摘要。
3. **缺兜底截断**：`known_pitfalls.issue` 最长 360 字符，`query_rules.notes` 单条最长 207 字符，已有 `[:3]` 截断基本够用，但缺单字段和单卡硬上限兜底。

## 二、解决方案

改动文件：`runtime/backend/app/services/knowledge.py` 的 `read_table_card_excerpts`（不改动表卡 yaml 本身、`read_first_read_contents`、`build_knowledge_context_parts`）。

1. **分区字段 fallback**：`partitions` 列表为空/无 `name` 时，回退读 `freshness.partition_field`（+ `partition_grain`，如 `active_date (day)`）。
2. **known_pitfalls 兜底修复**：复用打分阶段已算好的 `pitfalls_full`（`issue → id → ""` 干净兜底链），展示时对每条做 `_truncate_field` 截断，不再走会泄漏整 dict 的旧逻辑。
3. **新增两级截断常量**：
   - `_TABLE_CARD_FIELD_MAX_CHARS = 220`：单字段展示层截断上限，超出补 `…`；只影响展示，不影响打分的原始 `haystack` 文本。
   - `_TABLE_CARD_EXCERPT_MAX_CHARS = 3000`：单张表卡摘要硬上限兜底。
4. **摘要提取范围明确化**：只提取 `fqn`/`one_line_summary`/分区/`must_filter`/`join_keys`（仅列名）/`known_pitfalls.issue`（不含 evidence/fix/detection/example）/命中关键 `columns`（仅 name）；显式跳过 `source_docs`/`source_notes`/`column_groups`/`semantic_groups`/`metric_fields`/`example_queries`/`related_tables`。

## 四、遗留观察项

1. **route yaml 的 `first_read` 里手工列出表卡路径未清理**：多个 `task_routes/*.yaml` 在 `first_read` 直接列出表卡 yaml，会被 `read_first_read_contents` 当普通协议文档"原样截断"再读一次（未经精简）。若要进一步收窄表卡占比，需评估是否移除这些路径（`read_table_card_excerpts` 已按需检索注入精简版），但涉及改动多个 route yaml，留作下一轮 plan。
2. **截断阈值为经验值**：基于当前 158 张表卡字段长度分布设定，若未来表卡内容显著变长需重新抽样评估。

## 五、方法论沉淀

1. **摘要提取要白名单不要黑名单**：按白名单字段提取（fqn/grain/must_filter/join_keys/known_pitfalls.issue），不按黑名单跳过，未来混入新维护期字段也不会泄漏。
2. **兜底值不能是整个 dict**：`get("issue", p)` 的兜底若用整个 dict `p`，缺字段时会串进 Python dict repr，必须用干净的兜底链（`issue → id → ""`）。
3. **分区字段要有 fallback**：表卡可能用 `freshness.partition_field` 而非独立 `partitions` 列表，摘要提取要兼容两种写法。
4. **截断只影响展示不影响打分**：展示层截断不能截断打分用的原始 `haystack` 文本，否则会截断掉打分关键词。
