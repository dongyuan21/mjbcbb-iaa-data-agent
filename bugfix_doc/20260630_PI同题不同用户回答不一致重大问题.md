## 一、问题

用户报告：同一问题「分析 block_blast_gp 每个渠道每个国家，top20% 累积 d30arpu，能占 d30 总 arpu 的比例」，user_a 能拿到完整分析，user_b 两次被阻断。初步怀疑用户歧视/权限差异。

落地 `da_assets/verified_sql/vsql_20260630_d30_top20_user_concentration_channel_country.md`，Runtime 通过 `verified_sql_bootstrap.py` 按问题哈希精确匹配 canonical SQL，不再每次自由探索。

### 2. 路由 guardrail

`task_routes/text2sql_or_sql_planning.yaml`：top20%/集中度问题强制解释 A + DA 表路由 + 禁止错表/PII 外显。

### 3. PI 自动回归

## 六、方法论沉淀

1. **同题跨用户不一致先排查非确定性**：同 runtime/模型/guardrail 下，差异多来自 LLM 探索路径分叉 + 确定性熔断规则，而非用户歧视或权限差异。
2. **消除"手气查数"靠 verified SQL**：Agent 默认召回 verified SQL 而非每次自由探索，是稳定性的根本解。
3. **熔断规则要在分叉路径上都能兜底**：`no_progress_tools` 和 `consecutive_tool_failures` 两个阈值要配合 route 画像调整，避免 text2sql 任务因先读文件就误熔断。
4. **machine-auth N=3 不等于跨用户 UI 一致**：运行链稳定和页面体验一致是两件事，后者需独立人工验收。
