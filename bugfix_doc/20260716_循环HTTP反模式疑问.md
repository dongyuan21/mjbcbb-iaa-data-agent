# 20260716 循环 HTTP 反模式疑问

> 记录日期：2026-07-16
> 范围：PI 工具调用链路架构
> 级别：P2 / 架构疑问（待评估）
> 状态：已识别，待排期评估

## 一、问题

PI 通过 bash + curl 调用 FastAPI 自身的 `/api/pi-tools/*` 端点获取数据，形成循环 HTTP 反模式。每次查询经历：

```
用户 → FastAPI → PI subprocess → curl FastAPI → MC subprocess → 结果回到 PI → 回到 FastAPI → 回到用户
```

至少 4 层进程 + 1 次 HTTP 自调用。正确做法是 PI 直接调用数据工具脚本（或通过 MCP，Model Context Protocol），不需要绕回 FastAPI。

## 二、风险

- 多余的 HTTP 自调用增加延迟和失败点。
- 进程层级过深，超时和错误传播难追踪。
- FastAPI 既服务用户又服务 PI，职责混淆。

## 三、解决方案（待评估）

PI 直接调用数据工具脚本（`runtime/tools/data_query.py` 等），或通过 MCP 协议接入数据工具，去掉绕回 FastAPI 的 HTTP 自调用。具体方案待排期评估。

## 四、遗留观察项

- 本问题为架构方向疑问，待与 PI 接入方式一起评估，未排期。

## 五、方法论沉淀

1. **工具调用不应绕回服务自身**：Agent 调用数据工具应直接走脚本或 MCP，不该通过 HTTP 绕回 Web 服务，否则进程层级过深、延迟和失败点放大。
