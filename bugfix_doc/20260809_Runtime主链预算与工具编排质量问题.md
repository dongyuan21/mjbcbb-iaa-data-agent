## 一、问题

Runtime 同时存在“单次 provider 最大输出”和“整条 turn 累计 token”两种预算，当前语义不一致：

| 层 | 当前约束 | 已观察到的后果 |
|---|---:|---|
| provider 每次调用 | `max_tokens=16,000` | 每轮仍可发起很大的输出请求 |
| default / live SQL 累计预算 | 8,000 / 12,000 | 2～3 个正常回合即可能耗尽 |
| ToolLoop 检查时点 | provider 返回后累计检查 | 已付费候选会因超限被丢弃 |

Test 三条单次受控采样分别在 10,547、12,178、18,691 个累计 provider token 后以
`token_budget_exceeded` 终止；其中已见成功的目录/合同读取，未形成 terminal answer。完整 E3
live 结果仍为 0/8。该证据不能证明是某个模型、授权阈值或同工具失败风暴造成的唯一根因，但能
证明当前预算不能承载这些最小链路。

## 二、建议的解决方向

1. **预算语义分层**：保留每个 turn 的累计可计费上限；每次调用前按剩余预算、输入估算和最小收尾
   额度计算动态输出上限，而不是先请求、后丢弃结果。
2. **阶段化工具可见面**：按发现、合同、执行、收尾阶段，仅向模型暴露服务器已授权工具的必要子集。
   这只能收窄模型可见 schema，不能替代或放宽服务端 L5/P2/P3 授权。
3. **安全分账**：记录固定 prompt、状态、历史、route 知识、工具 schema、每轮 input/output、剩余预算
   和终态的计数；不得记录 prompt 正文、回答、SQL、rows 或原始异常。
4. **预算不足前置终止**：下一轮无法支付输入与最小收尾额度时，调用 provider 前 fail-closed，并给出
   有限原因码；不伪造业务结论。

## 三、业界方案调研要求

设计前应分别查阅 Claude Code、Codex、Cursor、Pi Agent 等产品的官方文档、公开实现或可复现行为，
不以营销描述或二手文章为依据。调研只比较以下可验证维度：

| 维度 | 要回答的问题 |
|---|---|
| 成本预算 | 是否区分整次任务预算、单次输出上限和下一轮预留额度 |
| 上下文治理 | 如何压缩历史、工具结果和工具定义；何时保留原文指针 |
| 工具编排 | 工具是否按阶段或状态缩小可见面；服务端如何继续强制授权 |
| 终态策略 | 预算不足时如何中止、澄清或交接；是否避免事后丢弃已生成结果 |
| 可观测性 | 如何只记录计数、阶段与原因码而不泄漏任务正文 |

调研产物必须逐项附来源链接、版本/日期、可证伪的机制说明和“可借鉴 / 不适用”结论；不得把外部
产品的行为直接当作本 Runtime 的正确实现。

## 四、验收

后续设计与实现至少应证明：

- 不再出现“provider 已返回、才发现累计预算无余量而丢弃”的路径；
- 预算、阶段、工具面与终态均能以安全计数解释；
- L5 binding、P2 ContractView、P3 coverage、失败熔断和 E3 门禁均不放宽；
- 同题同配置的预算轨迹可复现；完成链质量与成本变化分开报告；
- 仅在 Test 受控发布后，以无重试 case 如实复验，不按题目硬编码。

## 五、遗留观察项

1. 通用 `table_question` 的 MC freshness contract 覆盖是独立合同设计，不应混入本问题。
2. `enforce` 模式的 QuestionContract draft 覆盖是独立 P3 问题，不应以提高预算掩盖。
3. 是否调整具体预算数值，必须以分账和同配置受控样本为依据；不能仅因模型名称或单次结果决定。
4. Freshness 的正常 `mc_governed` 发布与 D2 provider control plane 是独立责任：本次 Freshness 滚动失败而未重试，
   也没有被下线、删定时或作为 D2 阻塞。它仍需等待下一次正常 Cron 的受控 publication 记录；不得手工触发 Cron
   冒充定时任务证据。今后的全服务发布不能把本次 API/Worker 的 Test-only 例外泛化为发布完成。

## 六、方法论沉淀

1. 上下文窗口可容纳，不等于整条 agent 链路的成本预算足以完成。
2. 预算必须在请求前调度，不能只在模型返回后作为结果丢弃条件。
3. 工具面收窄是减少成本与提升规划稳定性的手段，授权仍必须由 Runtime 强制。
4. 面向业界学习应对照机制和边界，不复制产品表象或为评测题临时优化。
