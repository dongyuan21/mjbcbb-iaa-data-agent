# 20260623 PI 路由误判与空结果掩盖重大问题

> 记录日期：2026-06-23
> 范围：Data Agent Runtime / PI 调用链 / MaxCompute SQL 复核
> 级别：重大问题
> 状态：已闭环（corrected，线上 test replay 验证通过，2026-06-24）

## 一、问题

线上问题：`查询 app_name='block_blast_gp'、media='googleadwords_int' 分国家的激活 D0/D7 收入均值`。PI 回复不满足要求，复核发现不是"数据为空"，而是 Runtime/PI 调用链同时出现三个缺陷（P0）：

1. **路由误判**：业务取数问题被路由到 `table_question`，没进 `text2sql_or_sql_planning` 的 SQL 协议链。
2. **SQL 口径误套**：PI 把行为表侧 `app_name='block_blast_gp'` 套到激活表侧，导致激活表核心查询返回 0 行。
3. **空结果被掩盖**：核心 SQL 返回 0 行后，PI 没继续做 MaxCompute smoke 诊断，最终文本只展示分区 probe，答非所问。

实测证据：激活表用 `app_name='block_blast_gp'` + `media_source='googleadwords_int'` 返回 0 行；同一激活表用 `bundle_id='com.block.juggle'` + `media_source='googleadwords_int'` 有大量激活，激活侧真实 `app_name` 为 `Block Blast!`。产品口径必须分表处理，不能把行为表 app_name 直接套到激活表。

## 二、根因

| 层 | 根因 |
|---|---|
| 路由层 | `KnowledgeRouter.route()` 旧逻辑把 task objective 里的英文 token 做子串匹配，`table_question` 的 objective 含 `a`、`or` 等短词，命中用户问题里的 `app_name`、`googleadwords_int`，误打到表问答路由 |
| 执行层 | PI prompt 只要求最多 4 次工具调用，没把"核心业务 SQL 0 行必须 smoke 诊断"定义为硬约束 |
| 汇总层 | `synthesize_tool_answer()` 旧逻辑跳过 `rows=[]` 的成功查询，回头格式化前面的非空 probe，用户看到像"查询成功"，实际展示的是分区日期 |
| 落库层 | 线上 SQL 证据主要在 assistant message metadata 的 `pi_tool_results`，`data_agent_query_records` 为空，增加复核成本 |

## 三、解决方案

1. **路由修复**：移除 objective token 子串加分；增加业务取数信号（`app_name`/`bundle_id`/`media_source`/`country`/`激活`/`收入`/`D0/D7`/`均值`）；对业务取数问题强制抬高 `text2sql_or_sql_planning`。
2. **PI prompt 修复**：工具上限 4→6 次为 smoke 留预算；明确 `SELECT 1`/`MAX(dt)`/`freshness` 只能作上下文不作业务答案；核心 SQL 0 行时必须诊断日期/产品端/bundle_id/app_name/media/国家/join 前后行数。
3. **答案合成修复**：识别 `ok=true` 但 `row_count=0` 的核心业务 SQL，返回"核心查询返回 0 行，未形成业务答案"，不再把 probe 包装成最终答案。
4. **落库修复**：`tool_executions` 缺失时把 `pi_tool_results` 转换成 query records；trace 的 `tool_calls` 保留 `pi_tool_results` 方便审计。
5. **回归测试**：新增路由命中、0 行不输出成功、pi_tool_results 回填等用例。

## 六、方法论沉淀

1. **路由不能用 objective token 子串匹配**：英文短词（a/or）会误命中用户问题里的字段名，必须用业务取数信号驱动路由。
2. **核心 SQL 0 行必须 smoke 诊断**：不能把 probe 结果包装成业务答案，0 行是口径错误的强信号，必须诊断日期/产品端/字段口径。
3. **产品口径要分表处理**：行为表 `app_name` 和激活表 `app_name` 可能不同（`block_blast_gp` vs `Block Blast!`），不能直接套用，激活侧用 `bundle_id` 更稳。
4. **证据链必须落库**：trace、assistant metadata、query_records 三处同时形成证据链，避免后续复核只能手工拼接。
